## 1. 功能与设计目标

### 1.1 功能定位

IR 验证器接收一个 `Program`，检查其结构、值定义、类型和控制流是否合法，返回可定位的诊断信息。验证器只检查，不修改、不修复 IR，也不执行 IR。

启用验证后，在前端生成共享 Program 后、每个 IR 优化 pass 前后、代码生成前执行检查。出现 ERROR 时停止后续编译；只有 WARNING 时允许继续。

这里的“正确”是满足本设计规定的 IR 合法性约束，不等于模型计算结果正确，也不等于优化前后语义等价。

### 1.2 七条核心规则

| 编号 | 规则标识 | 目标 | 默认等级 |
|---|---|---|---|
| R1 | `def-before-use` | 每个操作数在使用位置都有可用定义 | ERROR |
| R2 | `label-existence` | 基本块标签合法，跳转目标存在于当前函数 | ERROR |
| R3 | `block-termination` | 每个基本块以终止指令结束 | ERROR |
| R4 | `type-consistency` | 指令参数、结果及引用类型符合签名 | ERROR |
| R5 | `control-flow-integrity` | 分支结构完整，识别不可达基本块 | 结构错误为 ERROR；不可达块为 WARNING |
| R6 | `ssa-validity` | 同一函数的值名称只定义一次 | ERROR |
| R7 | `entry-existence` | 每个函数至少包含一个基本块 | ERROR |

工程目标：诊断可定位、输出顺序稳定、支持重复检查、单个函数出错不影响收集其他函数的问题、避免同一根因引起大量衍生诊断。

### 1.3 范围与非目标

本次检查共享 IR 层的 `Program / Function / BasicBlock / Instruction / Value`，不直接检查 ONNX 文件、LLVM IR 或 RISC-V 汇编。未经过该共享 IR 的独立编译路径不属于本次接入范围。

CFG 模块负责完整控制流建图及原位置映射，复用上游 FOR/ENDFOR 支持；验证器调用其分析结果，不自行实现循环建图。前端、IR 类型和 Builder 直接复用，不要求先转换 FOR/ENDFOR，也不改变原 Program。具体实施参见[开发文档](21-IR验证器-开发文档.md)。

本次不实现：优化等价性证明、运行结果验证、完整张量形状推导、除零检查、数组越界检查、内存别名分析、内存初始化分析、完整 PHI 支持、机器码验证。类型检查不应宣称能保证内存安全。

## 2. 输入约定与诊断接口

### 2.1 IR 层级与名称约定

验证器直接读取 IR 对象，而不是解析 `dump()` 的文本：

```text
Program
  ├─ global_values
  └─ functions[]
       ├─ params / returns / locals
       └─ blocks[]
            ├─ name
            ├─ instructions[]
            │    └─ opcode / dest / operands / attrs / target
            └─ phi_nodes
```

约定如下：

1. `func.blocks[0]` 是入口块，不要求名为 `entry`。
2. 普通基本块的列表相邻关系不自动表示执行边。FOR/ENDFOR 按函数 blocks 列表及块内 instructions 顺序配对，该结构顺序与执行路径分开处理；跨块标记不能任意重排后仍假定配对不变。
3. 值以名称识别，而不是以 Python 对象身份识别；两个不同 `Value` 对象可以引用同一个名字。
4. 参数和合法全局值在函数入口可用；`locals` 只是声明列表，不自动成为已定义值。
5. 全局值名称应唯一；函数参数和指令结果不得遮蔽全局值，也不得在本函数内重名。不同函数可以使用相同的局部值名称。
6. 外部输入、权重等值的定义以参数、全局值或实际指令为依据；未登记的具名值按 R1 诊断。验证器不猜测输入、不自动补定义，本课题不改造前端登记方式。
7. 空 `Program` 允许通过；如果存在函数而函数没有基本块，则违反 R7。

### 2.2 控制流表示约定

本设计接受显式 BR/BR_IF 控制流和合法的结构化 FOR/ENDFOR。块名来自 BasicBlock.name；BR、BR_IF、RETURN 是显式终止指令。FOR/ENDFOR 提供隐式循环路径，不等于普通指令，也不按“出现后禁止后续指令”处理。普通块之间不能仅凭列表相邻关系隐式落入。

- `BR.target`：一个非空目标块名。
- `BR_IF.target`：两个用逗号分隔的非空块名，依次为真分支、假分支。拆分后可以去除首尾空白，但不能过滤空项。
- `BR_IF` 支持一个整数条件操作数，或两个同类型比较操作数加 `attrs['cmp_op']`。
- 比较运算符统一为 `==`、`!=`、`<`、`<=`、`>`、`>=`；其他写法不在该签名范围内，验证器不自动转换，也不增加前端改造任务。
- `RETURN` 没有控制流后继。

FOR/ENDFOR 的配对、嵌套和路径由 CFG 模块分析，验证器根据结构问题报告 R5。合法循环不要求前端降低为跳转，更不需要复制循环体进行循环展开。

LABEL 或非空 `phi_nodes` 报告明确的“不支持表示”R5 ERROR，表示当前验证入口的能力边界，不称其为天然非法 IR。未来支持 PHI 时，需要增加沿前驱边使用值的专门规则，不能套用普通指令的支配检查。

复用前端不表示所有历史输入都会通过严格验证。对真实的定义、类型和结构问题应如实诊断；不通过自动修复输入或忽略错误放行。

### 2.3 常量与定义的边界

常量操作数需要满足 `is_constant=True`，且 `const_value` 与 `dtype` 相容。

名称解析优先级：先查参数、全局值和指令结果；只有不存在同名显式定义时，合法常量操作数才作为内联字面量处理。

因此，把一个指令结果标记成常量，不能绕过先定义后使用检查。例如先使用 `$x`，再用 `LOAD_CONST` 定义 `$x`，即使 `$x.is_constant=True`，仍违反 R1。

无显式定义的常量元数据无效时报告 R4，不再附带衍生的“未定义”诊断。具名引用仍按定义位置检查，元数据错误不能掩盖独立的先使用后定义错误。

### 2.4 错误等级

| 等级 | 定义 | 编译行为 |
|---|---|---|
| ERROR | 已确定违反输入契约或七条规则中的强制约束 | 收集当前检查结果后，停止后续 pass 和代码生成 |
| WARNING | 不违反强制结构约束，但存在值得关注的情况；本次为不可达块 | 展示诊断，继续编译 |

本设计明确把不允许的类型混用设为 ERROR，不做隐式类型转换。课题说明中的类型不匹配 WARNING 示例不作为本设计的最终等级约定。不可达块不会因此免除其他合法性检查。

### 2.5 公共接口

```python
class ErrorLevel(enum.Enum):
    ERROR = "error"
    WARNING = "warning"

@dataclass(frozen=True)
class VerificationError:
    level: ErrorLevel
    rule: str
    message: str
    function_name: str | None = None
    block_name: str | None = None
    instruction_index: int | None = None
    value_name: str | None = None
    stage: str | None = None
    context: tuple[IRContextLine, ...] = ()
    fix_hint: str | None = None

class IRVerifier:
    def __init__(self, program: Program): ...
    def verify(self, *, stage: str | None = None) -> list[VerificationError]: ...

def verify_ir(
    program: Program, *, stage: str | None = None
) -> tuple[bool, list[VerificationError]]: ...
```

展示扩展：`context` 保存诊断发生时的不可变 IR 上下文（前后各两条指令），`fix_hint` 保存修复建议，均有默认值。`format_ir_error` / `render_ir_error` 负责箭头、标记和终端颜色；`str(issue)` 保留紧凑格式。具体输出和 HTML 示例见[使用说明](21-IR验证器-使用说明.md#带上下文的诊断输出)。

`passed` 的定义是不存在 ERROR，而不是诊断列表为空。只有 WARNING 时应返回 `(True, warnings)`。

输出示例：

```text
[ERROR][def-before-use] stage=after:constant-folding function=main block=entry instruction=0 value=x: 值 x 在本块定义之前被使用
```

指令索引从 0 开始，表示 IR 块内位置，不冒充源代码行号。函数级或空块级诊断可以没有指令索引。重复定义定位到后一次定义，消息中说明第一次定义的位置。

同一次检查按“函数顺序、基本块顺序、指令索引、规则编号、值名、消息”排序；没有指令索引的块级诊断排在块内指令之前。按规则、内部精确位置、值名及固定原因键去重。内部位置包含函数序号、块序号、指令索引，以及参数/全局值的位置种类和列表序号，不仅使用公开名称。不同重名块中的相同错误各自保留；同位置同原因的重复报告才合并。全局诊断先于函数，函数级先于块级；原位置由 CFG 节点映射还原，不显示合成节点名。`stage` 由调用者传入，供定位哪个优化阶段引入错误。

## 3. 七条规则的检查设计

### 3.1 R1：先定义后使用

#### 规则说明

操作数必须是参数、全局值、合法内联常量，或在当前位置可用的指令结果。普通指令的结果在执行该指令后才可用，不能用自己的结果定义自己。

同一直线分析片段内，定义索引必须严格小于使用索引；跨片段时，定义节点必须支配使用节点，即入口到使用位置的每条路径都经过定义。含 FOR/ENDFOR 的原 BasicBlock 可对应多个 CFG 节点，即使定义和使用在同一原块，也不能只比较索引。

#### 检查方式

1. 预先收集整函数的定义表，记录名字、定义种类、块、指令索引和类型。
2. 对每个操作数按第 2.3 节解析名称与常量。
3. 找不到定义且不是合法字面量，报告 R1。
4. 参数、全局值直接满足可用性要求；指令结果经 CFG 位置映射按片段内顺序或跨片段支配判断。FOR 循环变量关联初始化节点，回边不制造新定义；循环体定义不自动在循环后可用。
5. R6 已发现重名时，将该名字标记为歧义，跳过依赖唯一来源的后续检查，避免重复误报。

CFG 无法可靠建立时，仍检查名称存在及可以确定的直线片段内顺序，跳过跨片段支配分析。不可达片段保留独立局部检查，不进行入口支配判断；可达使用仅由不可达位置定义的值必须报错。初版保守保留循环零次路径，不依靠常量迭代次数证明循环体必执行。

#### 示例与预期

```text
fun main(a: f32):
  entry:
    x: f32 = add a, 1.0
    y: f32 = mul x, 2.0
    return y
```

预期通过。交换前两条指令后，`entry` 第 0 条使用尚未定义的 `x`，产生一个 R1 ERROR。

```text
fun main(cond: i32, a: f32):
  entry: br_if cond -> left, right
  left:
    x: f32 = add a, 1.0
    br merge
  right: br merge
  merge:
    y: f32 = mul x, 2.0
    return y
```

预期在 `merge` 第 0 条报告 R1 ERROR：从 `right` 到达时没有经过 `x` 的定义。把 `left` 排在 `merge` 前面不能解决问题；将 `x` 的定义移到 `entry` 的分支之前才能使此例通过。

### 3.2 R2：标签与跳转目标存在

#### 规则说明

块名是当前函数内部的标签，必须非空且唯一。跳转不能引用其他函数的同名块，也不能指向不存在的块。

#### 检查方式

1. 遍历块列表构建名称索引，先检查空名称和重复名称，不能用字典覆盖来隐藏重复块。
2. 检查 `BR` 的单一非空目标。
3. `BR_IF` 由 R5 确认有两个合法目标字段后，再分别检查目标存在性。
4. 同一目标出现两次允许通过；“真、假两个出口”不要求落到两个不同块。

重复块名导致目标歧义时，不再报告“目标不存在”；该函数跳过依赖完整 CFG 的分析。

#### 示例与预期

```text
entry: br exit
exit:  return
```

预期通过。将目标改为 `missing`，在 `entry` 第 0 条报告 R2 ERROR；不再根据这个残缺 CFG 推导不可达警告。`BR.target=None` 或空字符串同样报告 R2 ERROR。

### 3.3 R3：基本块必须正确终止

#### 规则说明

基本块不能为空。无结构化循环时，块尾必须为 BR、BR_IF 或 RETURN；含 FOR/ENDFOR 时依据 CFG 提供的片段边界检查出口，FOR 提供进入/退出路径，ENDFOR 提供回边，不额外要求插入 BR。循环之后的普通片段仍须有合法结束方式，不允许任意块隐式落入。显式终止后还有普通指令由 R5 检查。

#### 检查方式

空块报告块级 R3 ERROR；普通块检查最后一条。结构化循环块结合 CFG 结构扫描结果检查各片段出口与循环后续，缺少合法结束方式时定位原指令或块；验证器不补 RETURN、不修改块列表。

#### 示例与预期

```text
fun main(a: f32):
  entry:
    x: f32 = add a, 1.0
```

预期在 `entry` 第 0 条报告 R3 ERROR。补上 `return x` 后通过。函数存在一个空的 `entry` 块时违反 R3，而不是 R7。

### 3.4 R4：类型与指令签名一致

#### 规则说明

检查操作数数量、是否允许结果、操作数与结果类型、同名引用与定义的类型，以及必要的常量元数据。不实施隐式数值转换。

#### 检查方式与签名表

通过集中维护的 opcode 签名表分发检查，先检查结构，再检查类型；参数缺失时输出诊断，不因直接访问列表下标而崩溃。

下表中 `T` 是任一种受支持的相同数值类型；`F` 是相同的 `f32` 或 `f64`。表中列出验证器采用的签名；本课题不自动改写构造端产物。

| 指令 | 操作数 / 结果 | 检查要求 |
|---|---|---|
| ADD、SUB、MUL、DIV | 2 / 必须有 | 两个操作数及结果均为 T |
| NEG、RELU | 1 / 必须有 | 输入和结果均为 T |
| EXP、GELU、SIGMOID、SOFTMAX | 1 / 必须有 | 输入和结果均为 F |
| MATMUL、DOT | 2 / 必须有 | 输入和结果均为 T；不检查完整形状语义 |
| CONV、GEMM | 3 / 必须有 | 含显式偏置，输入和结果均为 T；验证器不自动补偏置，也不新增前端规范化任务 |
| MAXPOOL、RESHAPE、TRANSPOSE | 1 / 必须有 | 输入和结果均为 T |
| CONCAT | 至少 1 / 必须有 | 所有输入和结果均为 T |
| LOAD_CONST | 0 / 必须有 | `attrs['value']` 与结果类型相容；若结果带常量元数据，应一致 |
| ALLOCA | 0 / 必须有 | 结果的 dtype 表示所分配存储的元素类型 |
| LOAD | 1 / 必须有 | 已知存储来源时，结果类型与其元素类型一致 |
| STORE | 2 / 无 | 顺序为地址、值；已知存储来源时，值类型与元素类型一致 |
| BR | 0 / 无 | 目标交给 R2 检查 |
| BR_IF（条件值） | 1 / 无 | 条件为 i32 或 i64，不允许同时携带 cmp_op |
| BR_IF（比较） | 2 / 无 | 操作数同类型，cmp_op 属于第 2.2 节规定集合 |
| RETURN | 0 或 1 / 无 | 显式声明返回类型时，应匹配返回数量与类型 |
| FOR | 0 / 必须有 | 结果为 i32 循环变量，start/end/step 按现有整数属性表示检查；配对交给 R5 |
| ENDFOR | 0 / 无 | 与 FOR 配对，不能附带普通操作数或 dest |

补充边界：

- 先检查 dtype 必须是 DataType.FLOAT32、INT32、FLOAT64、INT64 成员，字符串 "f32" 不合法、不自动转换。非法类型报 R4 后不再基于它做兼容比较；未使用参数、全局值和结果也检查。
- LOAD_CONST 的 attrs['value'] 与结果常量元数据：普通数值精确比较，不用误差容限；两个 NaN 视为一致，Inf 和零要求符号一致，+0.0/-0.0 不一致。不比较 NaN payload，不声称已按 f32 舍入。不一致报 R4，不自动选一份覆盖另一份。
- FOR 属性缺失、类型错误或无效步长归 R4；边界和步长方向按现有指令语义，不擅自扩展为 Python range 的全部能力。
- 对每个已唯一解析的具名操作数，检查其 dtype 与定义中的 dtype 一致；定义有歧义时跳过该项依赖检查。
- `Function.returns` 非空时作为显式返回签名检查；当前 RETURN 约定最多返回一个值，多返回声明报 R4 ERROR。`returns` 为空暂表示未声明签名，而不是必然 void。
- `ALLOCA` 定义的存储可以追踪元素类型；外部地址缺少独立指针类型描述时，不声称可以完整验证其地址性质。
- i32/i64 常量必须是非布尔整数，且落在对应有符号范围。f32/f64 常量允许非布尔整数或浮点数；允许 NaN/Inf，本次不验证舍入精度。
- 没有签名的未知 opcode 报 R4 ERROR，不能静默通过；第 2.2 节列出的不支持表示统一归入 R5，避免重复报告。

#### 示例与预期

```text
fun main(a: i32, b: f32):
  entry:
    x: f32 = add a, b
    return x
```

预期在 `entry` 第 0 条报告 R4 ERROR，消息列出实际输入类型 `i32, f32`。即使操作数都是 i32，如果结果声明为 f32，也应报 R4 ERROR。全部统一成同一种类型后通过。

### 3.5 R5：控制流完整性与不可达检测

#### 规则说明

终止指令之后不能继续放指令；条件跳转必须明确给出真、假两个出口；从入口无法到达的基本块应报告 WARNING。

#### 检查方式

1. 检查第一条显式 BR/BR_IF/RETURN 后的多余普通指令，定位首条多余指令，每块报告一次。FOR 后有循环体、ENDFOR 后有后续代码不属于此错误。
2. 检查 BR_IF 目标字段。`left`、`left,`、`left,right,other` 都不合法；不能删除空项后继续解释。
3. 调用 CFG 结构扫描匹配 FOR/ENDFOR，检查孤立、未闭合和嵌套；位置和原因映射为 R5 ERROR。函数间不共享配对栈。结构合法后，由 CFG 模块统一建立普通分支与循环路径：RETURN 无后继、BR 一个出口、BR_IF 两个出口，循环包含进入、退出和回边。
4. 显式分支回跳原入口块报告 R5 ERROR。结构化循环回到 CFG 内部条件节点不等于跳回函数入口，不能误报。
5. 读取 CFG 可达结果，原块所有可执行片段均不可达时报告一个块级 WARNING；某片段可达时不把整个原块误判不可达。不删除块或指令。
6. 存在重复块名、缺失目标、循环配对错误、缺失合法结束方式或不支持控制流表示等结构错误时，跳过本函数可达性和支配分析，以免产生衍生误报。

#### 示例与预期

```text
fun main(a: f32):
  entry:
    return a
    x: f32 = add a, 1.0
```

预期第 1 条同时满足两项独立违规：R5 ERROR“终止指令后仍有指令”，R3 ERROR“最后一条不是终止指令”。

```text
entry: br exit
dead:  return
exit:  return
```

预期仅对 `dead` 报一个 R5 WARNING，`passed=True`，块列表保持不变。如果 `dead` 内部还存在未定义值，则额外报告 R1 ERROR，最终 `passed=False`。

### 3.6 R6：SSA 单一定义

#### 规则说明

SSA 的约束对象是值名称的静态定义位置，不是指令执行次数。FOR 的循环变量在初始化位置定义一次，循环迭代不算重复定义；同名的另一条指令定义仍违反 R6。SSA 也不限制内存写入次数。一个名字不能由两条指令产生；向同一个地址多次 STORE 不构成重复定义。

#### 检查方式

先检查全局名称唯一性，再为每个函数建立包含全局名称和参数的定义表。遍历所有块中的 `dest`，包括不可达块；名字已经存在则报告 R6 ERROR，记录首次和再次定义位置。重复参数、参数与全局冲突也按本规则报告。

出现重复后将名称标为歧义，不以“最后一个定义覆盖第一个”的方式继续分析。`locals` 中的声明不重复计为定义。

#### 示例与预期

```text
fun main(a: f32):
  entry:
    x: f32 = add a, 1.0
    x: f32 = mul a, 2.0
    return x
```

预期仅在第 1 条报告一个 R6 ERROR；不针对歧义的 `return x` 再推导其他依赖唯一来源的错误。

```text
entry:
  slot: f32 = alloca
  store slot, 1.0
  store slot, 2.0
  x: f32 = load slot
  return x
```

预期通过：`slot` 和 `x` 各自定义一次，STORE 没有结果定义。

### 3.7 R7：入口存在

#### 规则说明与检查方式

对每个函数检查 `blocks` 是否非空。为空则报告一个函数级 R7 ERROR，并跳过该函数的块分析，继续检查其他函数。

有基本块时，第一块就是入口；入口内容和终止是否合法分别交给其他规则。

#### 示例与预期

```python
program = Program()
program.add_function(Function(name="main"))
```

预期一个 R7 ERROR，`function_name='main'`，块名和指令索引均为 None。给函数增加名为 `start` 且只含 RETURN 的块后通过，不要求改名为 `entry`。

## 4. 内部架构与编译流程接入

### 4.1 每次验证的分析上下文

每次 `verify()` 新建上下文，至少包含块名索引、定义表、歧义名称集合、前驱/后继表、可达集合、支配集合和诊断列表。不得跨优化 pass 使用失效缓存，也不能把临时分析标记写回 IR。

建议处理顺序：

1. 检查全局定义；逐函数检查 R7。
2. 收集块标签和定义，执行 R2 标签检查与 R6。
3. 调用 CFG 的结构扫描获得循环配对和片段信息，执行 R3/R5、R2 目标检查及 R4。
4. 结构有效时调用 CFG 模块建立完整图及位置映射，再调用可达性与支配分析。验证器不自行补边；CFG 结构问题由验证器转换为规则诊断。
5. 执行 R1；最后去重、稳定排序并计算 passed。

“由于结构错误跳过依赖分析”不等于该分析通过；此前已经存在 ERROR，整个验证必然失败。常见非法 IR 应返回诊断而非 KeyError/IndexError；任意非 IR 的 Python 对象不属于本接口保证范围，可抛 TypeError。

CFG 返回的分析结果包含完整图、原指令到节点映射、节点到来源映射、块入口和循环配对信息。每个定义记录原始位置，名称索引保留重复块的全部序号，歧义定义不覆盖。参数和全局值用各自列表序号定位，所有分析状态均不写回 IR。

### 4.2 支配关系算法

仅对入口可达集合 R 计算：

```text
Dom(entry) = {entry}
其他可达块 B 的初值：Dom(B) = R
反复更新直到不变：
Dom(B) = {B} ∪ 交集(Dom(P)，P 为 B 的可达前驱)
```

上述 B、P 表示 CFG 分析节点，不一定与原 BasicBlock 一一对应。定义节点 D 在 Dom(U) 中表示 D 支配使用节点 U；同一直线节点内仍检查原指令索引。算法由 CFG 模块提供，验证器只使用结果及原位置映射。

设 B 为 CFG 分析节点数（含循环拆分节点）、E 为边数、I 为指令及操作数总量：基础扫描 O(I+B)，可达分析 O(B+E)。集合迭代支配算法与迭代次数 K 有关，朴素实现可达 O(K·(B+E)·B)，支配集合空间 O(B²)，不能把整个验证器宣称为线性复杂度。先保证正确性，再通过规模测试判断是否需要替换算法。

### 4.3 验证开关与阶段

使用 `verify_ir: bool = False` 配置，由 `--verify-ir` 显式开启；不依赖日志等级。CI 中涉及 IR 的集成测试主动开启。默认关闭，必须显式启用，不由 DEBUG 日志间接开启。

| 检查阶段 | stage 示例 | 执行条件 |
|---|---|---|
| 前端生成共享 Program 后 | `after-parse` | 启用验证时执行 |
| 每个 pass 前 | `before:constant-folding` | 每个实际执行的 pass |
| 每个 pass 后 | `after:constant-folding` | pass 成功返回后 |
| 后端生成前 | `before-codegen` | 即使未开启优化也执行 |

阶段名 after-parse 指现有前端返回共享 Program 后；合法 FOR/ENDFOR 直接参与验证，不增加前端 lowering 前提。独立模型表示的路径不冒充已接入。初版不通过缓存省略相邻检查；可以在展示层合并重复 WARNING，但应保留其阶段来源。

控制逻辑示意：调用 `verify_ir` → 输出诊断 → 有 ERROR 则返回编译失败，否则继续。不能使用 `assert not issues`，因为 WARNING 不应中断编译。

失败时不调用后续 pass，不生成新的后端输出，也不覆盖已经存在的目标文件；CLI 返回非零退出码。关闭验证后不调用验证器，但不改变已有优化和代码生成逻辑。


### 4.4 CFG 建图职责与接口契约

统一使用 `build_cfg(IRCFGAdapter(func))`、`verify_cfg` 和 `compute_dominators`。不修改上游 CFG 模块，不新增节点/边算法。

验证器先检查原始结构（包括终结位置、跳转目标和循环配对），避免适配器正规化后丢失错误信息。普通指令沿对象身份关联原始位置；生成的循环初始化 LOAD_CONST 和更新 ADD 分别关联 FOR 和 ENDFOR。类型与 SSA 检查只遍历原始指令，不对生成指令重复检查。

支配计算使用图的可达视图；结构错误或适配器失败时停止跨块推断，保留局部诊断。适配器能力缺口交由上游 CFG 维护者处理。验证器不修改图和原 Program。

## 5. 测试设计

### 5.1 测试原则

单元测试直接构造 IR 对象，避免把解析错误当作验证器错误。每个用例除刻意破坏项外，其余结构应合法。不能只断言“有错误”，应检查 passed、规则、等级、函数、块、索引和关键值名；对明确要求单一诊断的场景还应检查数量。

下表 `E(Rn)` 表示对应规则 ERROR，`W(Rn)` 表示 WARNING；没有 ERROR 时 passed=True。具体中文消息只断言必要信息，稳定字段应精确断言。

### 5.3 完整分支正例

以下例子同时覆盖多个块、比较分支、内存读写和单一定义：

```text
fun absdiff(a: f32, b: f32) -> f32:
  entry:
    slot: f32 = alloca
    br_if a, b [cmp_op=>=] -> left, right
  left:
    x: f32 = sub a, b
    store slot, x
    br merge
  right:
    y: f32 = sub b, a
    store slot, y
    br merge
  merge:
    result: f32 = load slot
    return result
```

测试意图：正确程序不误报；`slot` 的定义支配两条路径和合流块；合流处通过内存加载结果，不直接引用只在一侧定义的值。

正确输出：`passed=True`，`issues=[]`。这里两条分支都写入 slot 是例子本身的性质，不代表验证器已经实现内存初始化证明。

### 5.4 完整循环正例

```text
fun repeat(limit: f32) -> f32:
  entry:
    slot: f32 = alloca
    store slot, 0.0
    br header
  header:
    current: f32 = load slot
    br_if current, limit [cmp_op=<] -> body, exit
  body:
    next: f32 = add current, 1.0
    store slot, next
    br header
  exit:
    result: f32 = load slot
    return result
```

测试意图：CFG 的环不导致无限遍历；header 支配 body；静态指令只有一个定义位置，即使运行时循环执行多次，也不违反 SSA。

正确输出：`passed=True`，`issues=[]`。不检查循环是否在所有输入下终止。


#### 结构化 FOR/ENDFOR 正例与反例

```text
fun loop_demo():
  entry:
    i: i32 = for [start=0] [end=3] [step=1]
    x: i32 = add i, 1:i32
    endfor
    return
```

正例应返回 passed=True、issues=[]，循环变量只占一个静态定义位置。把 return 改为 return x 时，应在原使用位置报告 R1：保守 CFG 保留零次执行路径，因此循环体中的 x 定义不支配循环后使用。即使二者在同一个原 BasicBlock，也需要跨分析片段判断。这里不执行循环，不用常量迭代次数证明必执行。

### 5.6 稳定性与健壮性测试

- 只读性：验证前后比较所有相关对象字段，包括 phi_nodes、attrs、常量元数据、列表顺序等；不能只比较可能遗漏字段的 dump 文本。
- 可重复性：同一验证器对象多次 verify，结果一致且诊断不累计；IR 被 pass 修改后再次验证能看到新状态。
- 多函数隔离：一个函数缺入口或 CFG 损坏，其他函数的问题仍被检出。
- 错误组合：重复块、缺失分支、参数数量错误同时出现时不崩溃，不产生缺乏依据的支配诊断。
- 名称语义：不同 Value 对象但同名引用能够解析到同一个定义；对象身份不影响结果。
- 稳定输出：同样输入多次运行的诊断顺序一致。
- 规模测试：生成长直线块、块链、菱形分支和带环 CFG，记录块数、边数、指令量、时间和内存；先建立基线，不设置依赖机器速度的极短耗时断言。

## 6. 涉及模块与实施步骤

### 6.1 模块改动规划

本次改动包含验证器、统一 CFG 接口适配、编译流程接入与测试。IR 类型、Builder、前端及各优化算法直接复用；不把 CFG 能力缺口转移为验证器内部建图。

| 文件 | 改动目的 | 具体规划 |
|---|---|---|
| `scratchv/analysis/ir_verifier.py` | 实现七条规则与统一诊断 | 实现错误等级、诊断结构、定义表、局部结构检查、现有 CFG 分析调用、类型检查、去重排序和公共接口 |
| `scratchv/analysis/__init__.py` | 对外提供完整验证接口 | 保留 IRVerifier、VerificationError 导出，补充 ErrorLevel、verify_ir 导出 |
| `scratchv/compiler.py` | 将验证接入共享 IR 编译流程 | 增加独立验证配置；在解析后、每个 IR 优化 pass 前后、代码生成前调用；遇 ERROR 中止，WARNING 继续；保护已有输出文件 |
| `scratchv/main.py` | 将命令行选项连接到编译配置 | 复用已有 `--verify-ir` 参数，接入独立配置，展示诊断并返回正确退出码；与数值结果验证的 `--verify` 区分 |
| `tests/test_ir_verifier.py` | 验证七条规则自身的正确性 | 实现正反例、边界、组合错误、诊断位置、重复调用及只读性测试 |
| `tests/test_ir_verifier_integration.py`（拟新增） | 验证编译流程接入行为 | 实现开关、阶段顺序、pass 故障注入、错误中止、警告放行和输出保护测试 |
| 本设计文档、开发文档及 `docs/topics/21-IR验证器/21-IR验证器-使用说明.md` | 保持交付说明一致 | 记录最终接口、支持范围、实际实现步骤和测试结果，不提前宣称完成 |

优化阶段的验证钩子由 `compiler.py` 中的优化管线配置，仅作用于共享 Program 的 IR pass，不扩展到汇编等其他表示。

`scratchv/__main__.py` 已负责调用命令行入口，无需改动；各优化算法模块也不因接入验证器而修改。

### 6.2 实现顺序

1. **建立测试构造器。** 复用现有类型与 Builder，建立直线、分支、循环和非法 IR 测试数据。
2. **实现诊断和上下文。** 完成 ErrorLevel、VerificationError、公共接口、稳定排序、去重、passed 计算及每次调用的状态初始化。
3. **实现局部规则。** 完成入口、标签、显式终止指令、分支格式、重复定义和可确定的直线片段内定义使用检查，并通过对应单元测试；循环结构检查接入下一步提供的 CFG 扫描结果。
4. **接入上游 CFG。** 复用统一建图与分析接口，在验证器内关联原始位置，运行上游测试与规则回归；不修改 CFG 或前端。
5. **实现类型规则。** 按 opcode 签名表检查操作数数量、结果、类型和常量元数据，完成参数化及边界测试。
6. **接入编译器和命令行。** 完成独立开关、检查阶段、失败中止、诊断展示和输出保护；使用假 pass 注入错误验证中止行为。
7. **回归与交付。** 执行单元、集成、规模及相关项目测试；在开发文档记录实际变更、测试命令、结果和支持边界。
