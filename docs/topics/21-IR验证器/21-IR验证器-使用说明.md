# 课题21：IR 验证器（7 条规则）

> 实现日期：2026-09-26。契约依据：[设计文档](21-IR验证器-设计文档.md)、[开发文档](21-IR验证器-开发文档.md)。

## 使用方式

默认不启用严格 IR 验证；CLI 使用 `--verify-ir`，库接口使用 `CompilerConfig(verify_ir=True)`。它与数值比对 `--verify`、日志等级相互独立。

```bash
python -m scratchv model.onnx --verify-ir --optimize basic -o output.s
```

```python
from scratchv.analysis import ErrorLevel, IRVerifier, verify_ir

passed, issues = verify_ir(program, stage="after-parse")
for issue in issues:
    print(issue)
if not passed:
    # 停止后续编译；不要使用 assert not issues，WARNING 可以继续。
    raise ValueError("IR verification failed")
```

公开诊断 `VerificationError` 为不可变 dataclass，保留 `level / message / function_name / block_name / instruction_index / value_name / rule`，提供可选 `stage`、不可变 `context` 快照及 `fix_hint`。指令索引从 0 开始，表示原 IR 块内位置，不表示源码行号。

```text
[ERROR][def-before-use] stage=after-parse function=main block=entry instruction=0 value=x: value used before its definition
```

## 七条规则

| 规则 | 检查内容 |
|---|---|
| R1 `def-before-use` | 参数、全局值、合法字面量或可用的指令定义；片段内顺序和跨片段支配 |
| R2 `label-existence` | 原基本块名称非空且唯一，分支目标属于当前函数 |
| R3 `block-termination` | 空块、缺失终止指令或合法循环续接 |
| R4 `type-consistency` | 所有 opcode 的参数数量、结果、dtype、返回签名、常量、已知存储元素类型 |
| R5 `control-flow-integrity` | 分支字段、终止后指令、循环配对、入口入边、不支持表示、不可达块 |
| R6 `ssa-validity` | 全局、参数和指令结果名称冲突；locals 声明和 STORE 不算定义 |
| R7 `entry-existence` | 非空函数必须有入口块；第一块无需命名为 entry |

不可达块为 WARNING，其余上述违规为 ERROR；不可达块内的独立错误仍检查。空 Program 允许通过。类型检查不隐式转换；dtype 必须是 DataType 成员。整数常量拒绝 bool、小数和越界值；浮点常量允许 NaN/Inf。LOAD_CONST 的两份元数据精确比较，两个 NaN 一致，异号零和异号 Inf 不一致。

## 结构化循环和 CFG

采用上游统一 CFG：`build_cfg(IRCFGAdapter(function))` 建图，`verify_cfg(cfg)` 检查图结构，`compute_dominators(cfg)` 计算支配关系。`cfg_builder.py` 保持上游兼容导入层，本课题不再维护独立 CFG 实现或新增 CFG 专属测试。

上游适配器把 FOR/ENDFOR 转换为分析用的初始化、条件、回边和出口，不修改原 Program。验证器仍在原始 IR 上检查类型和定义，避免把生成的循环更新指令视为 SSA 重定义。普通指令通过对象身份映射回分析节点；FOR 的定义对应使用原 dest 的 LOAD_CONST。值引用的定义匹配仍按名称，不依赖 Value 对象身份。

适配器会拆分终结指令并允许普通块 fallthrough，因此验证器在建图前检查原始块名称、跳转目标、终结位置、循环配对和不支持表示。这些检查不构造节点或边。严格 IR 不允许普通相邻块隐式续接，结构化循环边界除外。

原始结构错误或上游建图失败时，继续收集局部类型、名称和顺序诊断，但不推测跨块支配关系。建图异常转换为 R5。支配计算使用完整图的可达视图，不修改图或原 IR，防止不可达前驱干扰。循环体定义不能直接供循环后的路径使用。

上游生成节点命名等建图能力由 CFG 模块维护；适配失败会明确报告，不在验证器内另建一套图进行兜底。

## 与 DSL 纠错机制的衔接

沿用 [DSL 错误提示美化器](../09-DSL错误提示美化器/09-DSL错误提示美化器-设计文档.md) 的分层方式：先检查、收集独立错误、稳定排序与去重，有致命错误就停止后续处理。

DSL 语法验证仍先于 IR 构建。拼写建议、源码行列、错误上限、颜色策略和多错误恢复均由现有 DSL 组件处理；有语法错误时不运行 IR 验证。`CompileResult.diagnostics` 继续保存 DSL 诊断，`ir_diagnostics` 单独保存 IR 结构化诊断，`errors / warnings` 保存兼容文本，CLI 不重复渲染 DSL 诊断。

两者的语义范围不同：DSL 语法允许隐式输入；严格 IR 验证要求这些值登记为参数、全局值或实际定义。前端未登记的具名值在开启 `--verify-ir` 时会产生 R1。验证器不猜测输入，也不修改源码或 IR。关闭开关时保持原有编译行为。

## 编译检查点与失败行为

```text
after-parse
before:constant-folding → pass → after:constant-folding
before:dead-code-elim → pass → after:dead-code-elim
before-codegen → codegen → write
```

无优化也执行首尾两个检查点。PassManager 的可选 `before_pass(pass_, data)` / `after_pass(pass_, data)` 只在开启验证的 IR 管线绑定；`data_type=Program` 单独保证 IR pass 的输入输出契约。后置检查、下一 pass 和后端均使用实际返回的 Program。返回 None、非 PassResult 或非 Program 会停止管线。

任一检查失败后不执行后续 pass/后端，不创建输出，不覆盖原文件；CLI 返回 1。WARNING 按阶段保留并允许继续。

## 能力边界与扩展

本入口暂不支持 LABEL 指令和非空 phi_nodes，报告明确的 R5。标签来自 BasicBlock.name，不是 LABEL 指令。不检查完整形状、内存初始化/别名/越界、除零，也不证明优化等价性。

新增 opcode 时在 `OPCODE_SPECS` 登记参数范围、结果存在性和 T/F 类型族；特殊约束在 `_check_signature` 增加，并补充合法、数量、结果和类型反例。未知 opcode 会产生 R4，测试要求枚举中的每一项都有签名或明确的不支持分类。控制流新增能力应集中在 CFG 模块。

## 带上下文的诊断输出

CLI 在开启 `--verify-ir` 时自动展示附近最多前后各两条 IR 指令，以 `-->` 标出错误指令、以 `^~~~` 标出相关值（无具体值时标出整条指令），并给出 `note` 修复建议。块级、参数、全局值和无入口函数错误展示对应结构，不虚构指令位置。

诊断携带不可变的 `context` 快照和可选 `fix_hint`；快照在产生诊断时保存，不受后续 pass 修改影响。块和函数序号用于区分重名位置。终端按 TTY 自动着色，遵守 `NO_COLOR`，重定向输出不含颜色控制符。

`str(issue)` 与 `CompileResult.errors/warnings` 保留原有紧凑格式；CLI 根据 `ir_diagnostics` 渲染上下文并避免重复打印。库调用可以使用：

```python
from scratchv.analysis import verify_ir, format_ir_error

passed, issues = verify_ir(program, stage="after-parse")
for issue in issues:
    print(format_ir_error(issue))
```

美化只影响诊断呈现，不改变七条验证规则，也不会自动修改 IR。

## 逐测试查看 IR 和诊断（可选 review 工具）

在项目根目录执行：

```bash
.venv/bin/python -m scripts.review_ir_verifier
```

该命令实际运行上表四组测试，将每次送入验证器的完整 IR 和诊断写入 `benchmark_reports/ir_verifier_review.txt`。默认记录全部验证调用（含一个用例中多次变更 IR 后的检查），不只生成几个手写示例。实际用例数和调用数以报告末尾为准。

每个用例依次展示：

1. pytest 用例名（含参数化名称）及断言结果。
2. 每次调用的 stage、全局值、函数参数/返回签名/locals、块、phi 和带索引的指令。
3. IR 的 passed 状态、诊断数量、错误上下文和修复建议。

测试自身没有调用 IRVerifier.verify 时会明确标注（例如只检查格式化，或 DSL 语法错误提前停止），不伪造一份 IR。测试失败时还会附上 pytest 的断言失败信息。`Test result: passed` 与 `IR passed=False` 可以同时出现：这是非法输入被正确拒绝的正常反例。

```bash
# 把完整 review 也打印到终端；pytest 进度输出到 stderr
.venv/bin/python -m scripts.review_ir_verifier --stdout

# 先看分支和循环，减少阅读量
.venv/bin/python -m scripts.review_ir_verifier -k 'loop or branch' --output /tmp/ir-loops-review.txt

# 只看一个测试；--test 可以重复指定
.venv/bin/python -m scripts.review_ir_verifier \
  --test tests/test_ir_verifier.py::test_u05_u06_u07_u24_u38_diamond_memory_and_dominance \
  --stdout
```

命令退出码沿用 pytest：全部断言通过返回 0；报告中出现预期的 IR ERROR 不会因此返回 1。输出为无颜色文本，方便搜索和复制。

工具完全放在 `scripts/review_ir_verifier.py`，只在自身运行期间临时包装验证和 CFG 入口，结束后恢复。它不改编译器 CLI、不改测试用例、不注册持久 pytest 插件，也不属于编译必需组件。后续不需要时可直接删除脚本及本节说明；生成文件已被 `.gitignore` 忽略。
