# 课题 21：IR 验证器

> **难度**：高 | **类型**：项目实战<br>
> **实现**：`scratchv/analysis/ir_verifier.py`<br>
> **测试**：`tests/test_ir_verifier.py`

## 概述

IR 验证器在不修改输入的前提下检查 ScratchV IR 的结构、数据流、SSA
约束和控制流。诊断信息包含稳定的规则标识、函数、基本块、指令下标和
变量名，可用于定位前端或优化 Pass 产生的非法 IR。

验证器支持三种使用方式：

- 通过 `IRVerifier` 验证 Program、Function 或单个 BasicBlock；
- 通过 `verify_ir()` / `verify_or_raise()` 集成到编译流程；
- 通过 `python -m scratchv.analysis.ir_verifier --verify-ir` 验证 JSON IR。

## ScratchV IR 结构

```text
Program
└── Function
    ├── params
    └── BasicBlock（块名同时作为跳转标签）
        └── Instruction
            ├── opcode
            ├── dest
            ├── operands
            └── target
```

ScratchV 使用 `BR` 表示无条件分支，使用 `BR_IF` 表示包含两个目标的条件
分支，使用 `RETURN` 返回。条件分支的 `target` 写成逗号分隔的两个块名，
例如 `"then,else"`。

DSL 前端把在函数中从未赋值的名字表示为隐式输入，因此验证器允许这类
操作数。若某名字在函数内存在定义，则该定义必须在控制流图中支配每个
使用点；仅在某一条件分支中定义的值不能在分支汇合后直接使用。

## 验证规则

| 规则标识 | 验证内容 |
| --- | --- |
| `program-structure` | Program、Function、BasicBlock、Instruction、Value 的容器和必要字段合法 |
| `def-before-use` | 函数内定义的值必须在使用前定义，跨块定义必须支配使用点 |
| `label-existence` | `BR` / `BR_IF` 的目标块存在，基本块名称不重复 |
| `block-termination` | 每个基本块非空且以 `BR`、`BR_IF` 或 `RETURN` 结束 |
| `type-consistency` | 二元运算恰好有两个操作数；类型不一致时产生 WARNING |
| `control-flow-integrity` | `BR` 有一个目标、`BR_IF` 有两个目标，终结指令后无不可达指令 |
| `ssa-validity` | 同一函数中同名结果值只赋值一次 |
| `entry-existence` | 每个函数至少包含一个基本块 |

除类型不一致警告外，规则违规均产生 `ERROR`。`verify_ir()` 只在出现
`ERROR` 时返回失败；`verify_or_raise()` 和启用验证的 Pass 流程会抛出
`IRVerificationFailure`。

## Python API

### 验证 Program

```python
from scratchv.analysis.ir_verifier import IRVerifier, verify_ir

passed, issues = verify_ir(program)
if not passed:
    for issue in issues:
        print(issue)

# 等价的面向对象入口
issues = IRVerifier(program).verify_program()
```

### 分层验证

```python
verifier = IRVerifier(program)
function_issues = verifier.verify_function(function)
block_issues = verifier.verify_basic_block(
    block,
    function,
    defined={"input"},
    block_names={"entry", "exit"},
)
```

`verify_basic_block()` 的 `defined` 和 `block_names` 参数用于传入块外上下文；
省略时分别使用函数参数和函数的基本块名称。

### 在优化 Pass 前后验证

```python
from scratchv.analysis.ir_verifier import run_optimization_pipeline

optimized = run_optimization_pipeline(
    program,
    optimization_passes,
    verify_ir_enabled=True,
)
```

启用后，每个 Pass 的执行顺序为：

1. 验证 Pass 输入；
2. 输入非法时停止，且不执行当前 Pass；
3. 执行 Pass；
4. 验证 Pass 输出；
5. 输出非法时停止，且不执行后续 Pass。

Pass 可以是接收 `program` 的可调用对象、返回变更计数的零参数旧式 Pass，
或返回 `PassResult` 的现代 `CompilerPass`。它可以原地修改并返回 `None`，
也可以返回新的 `Program`。

## `--verify-ir` 命令行开关

JSON 输入示例：

```json
{
  "functions": [
    {
      "name": "main",
      "params": [],
      "blocks": [
        {
          "name": "entry",
          "instructions": [
            {"opcode": "RETURN", "operands": []}
          ]
        }
      ]
    }
  ]
}
```

执行验证：

```powershell
python -m scratchv.analysis.ir_verifier --verify-ir program.json
```

只加载、不验证：

```powershell
python -m scratchv.analysis.ir_verifier program.json
```

退出状态：

- `0`：加载成功，且启用验证时 IR 合法；
- `1`：IR 验证失败；
- `2`：文件读取、JSON 解析或字段结构校验失败。

## 错误报告

`VerificationError` 包含错误级别、规则标识、函数名、基本块名、指令下标、
变量名和文字说明。例如：

```text
ERROR [def-before-use] in function 'worker', block 'done',
instruction #0, value 'result': value 'result' is used before definition
```

优化流程异常还会注明失败发生在第几个 Pass 的执行前或执行后。

## 扩展验证规则

新增规则时：

1. 确定规则属于 Program、Function、BasicBlock 还是 Instruction 层级；
2. 只读取所需上下文，不修改被验证的 IR；
3. 通过 `_add_error()` 提供稳定且唯一的 `rule` 标识；
4. 消息中同时给出实际值、期望值和尽可能完整的位置；
5. 在 `tests/test_ir_verifier.py` 中添加合法、非法和边界用例；
6. 先确认新测试在旧实现上按预期失败，再实现规则并运行完整测试。

增加新的二元、三元运算或终结指令时，应同步更新 `BINARY_OPS`、
`TERNARY_OPS`、`CONDITIONAL_BRANCHES`、`UNCONDITIONAL_BRANCHES` 或
`RETURNS`，并补充相应测试。
