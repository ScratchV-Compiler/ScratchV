> 先读：[Topic 12 设计文档](12-指令计数统计器-设计文档.md)

## 1. 开发目标

将现有“汇编文本 -> 混合 dict -> 文本/HTML”实现分步改造为：

```text
共享汇编解析
  -> 指令分类
  -> InstructionStats
  -> ComparisonResult
  -> 多格式报告
  -> CLI / CompilerDriver / benchmark / CI
```

开发时遵守三个原则：

1. 先用测试锁定现有行为和已知问题，再改实现；
2. 先建新模型和 adapter，再迁移调用方，不直接删旧 API；
3. 每个阶段只解决一类问题，其测试通过后再进入下一阶段。

## 2. 修改范围

|---|---|

| compiler/CLI 集成测试 | 验证统计的是最终产物 |
| benchmark/CI 相关文件 | 保存带版本的统计和 baseline delta |

## 5. P0/P1：解析层

### 5.1 P0：先补失败测试

P0 只写测试和 fixture，不急于修实现。测试按语法类型组织：

| 测试类 | 输入示例 | 应有结果 |
|---|---|---|
| 空白和换行 | `""` 、空格、CRLF | 无 opcode，不增加任何计数 |
| 注释 | `# add a0, a1, a2`、`add ... # sum` | 只计前者指令，注释不参与解析 |
| 标签 | `loop:`、`.L1:`、`1:`、`name$part:` | 纯标签不计数，label 字段正确 |
| 同行指令 | `loop: addi t0, t0, -1` | opcode 为 `addi`，不丢失 |
| directive | `.text`、`.word 0x13`、`.option arch,...` | `is_directive=True`，不计数 |
| 带点 mnemonic | `fadd.s`、`amoadd.w.aq`、`c.addi` | 完整保留 opcode，不删点号 |
| 异常文本 | 非空但无 opcode 的行 | 记录 suspicious，不静默归类 |

完成条件：每种输入都有明确失败或通过期望，且旧测试基线已保存。

### 5.2 P1：统一汇编行解析

实现顺序：

1. 让计数器调用 `_asm_parser.parse_line()`；
2. `opcode is None` 时跳过空行、注释和纯标签；
3. `is_directive=True` 时跳过 directive；
4. 保留 label 后的 opcode，并将 opcode 统一为小写；
5. 删除 `inst_counter.py` 中未使用的 `_INST_RE` 和重复 directive 列表。

如果共享 parser 无法处理项目实际输入，先给 parser 加测试，再修 parser；不在计数器里打补丁。

对应测试：

| 测试模块 | 关键断言 |
|---|---|
| `test_asm_parser.py` | `label`、`opcode`、`operands`、`comment`、`is_directive` 与输入一致 |
| `test_inst_counter.py` 解析组 | 同行 label、数字 label、本地 label 都能得到指令 |
| 跨模块回归 | 计数器、美化器、调度器对同一行使用相同 parser 结果 |

完成条件：解析 fixture 全部通过，同一行在计数器和其他后端 pass 中得到同样的 opcode。

## 6. P2：指令分类

### 6.1 分类实现

1. 定义 `OpcodeInfo(category, extension, is_pseudo)`；
2. 完整录入项目实际生成的 RV32IM；
3. 补齐 FP、MEM、BRANCH、JUMP、ATOMIC、SYSTEM、PSEUDO 和 compressed；
4. 仅对 atomic `.aq/.rl/.aqrl` 后缀做受控归一化；
5. 未命中指令进入 MISC，同时保留 unknown 明细；
6. 分类口径变更时升级 `classification_version`。

### 6.2 按类别组织测试

| 测试分类 | 必测指令 | 断言 |
|---|---|---|
| ALU | `add`、`addi`、`sub`、`mul`、`srai`、`lui` | 类别均为 ALU，字典不漏记 |
| FP | `fadd.s`、`fmadd.d`、`fsqrt.s`、`fcvt.w.s` | 类别为 FP，`.s/.d` 不被截断 |
| MEM | `lw`、`ld`、`sw`、`flw`、`fsd` | 载入与存储都进入 MEM |
| BRANCH | `beq`、`bltu`、`bnez`、`c.beqz` | 条件分支都进入 BRANCH |
| JUMP | `jal`、`jalr`、`j`、`ret`、`call`、`c.j` | 控制流伪指令按语义进入 JUMP |
| ATOMIC | `lr.w`、`sc.w`、`amoadd.w.aq`、`amoswap.d.aqrl` | 后缀不影响 ATOMIC 分类 |
| SYSTEM | `fence`、`fence.i`、`csrrw`、`ecall`、`sfence.vma` | fence/CSR/exception 不落入 MISC |
| PSEUDO | `li`、`la`、`mv`、`nop`、`neg` | `is_pseudo=True`，默认文本模式计 1 |
| MISC/unknown | `zz_unknown_opcode` | MISC 计数不丢失，unknown 记录原名称 |

不使用过宽的 `startswith()`。例如 `fadd.s` 不应因为以 `fadd` 开头就被归类，而是依据完整 registry key。

### 6.3 完成条件

- 每个主类别至少有两个典型正例；
- 分类结果对大小写和 atomic 顺序后缀稳定；
- 项目已知 RISC-V 输出不被错误归入 MISC；
- 真正未知指令可见，分类版本可追溯。

## 7. P3：结构化数据模型

### 7.1 实现任务

1. 新增 `analyze_instructions(text, *, isa="unknown") -> InstructionStats`；
2. 新增 `analyze_file(path, *, isa="unknown") -> InstructionStats`；
3. 在 `InstructionStats.__post_init__()` 中防御性拷贝、验证不变式并转为只读映射；
4. 实现显式 `to_dict()`，不用 `dataclasses.asdict()` 当长期 schema；
5. 建立唯一 `_stats_to_legacy_dict()` adapter；
6. 保留旧 API 和现有 renderer 入口的旧签名。

`analyze_file()` 使用 UTF-8，保留 `FileNotFoundError`、`PermissionError`、`UnicodeDecodeError` 等标准异常，不静默替换非法字节。

### 7.2 测试分类

| 测试类 | 必须检查的内容 |
|---|---|
| 数据不变式 | `total == category sum == opcode sum`；9 类始终存在；unknown 是 opcode 子集 |
| 构造不可变 | 修改原始 dict 不影响 stats，修改 `stats.category_counts` 被拒绝 |
| 序列化 | `schema_version`/`classification_version` 存在，数值为 JSON number，空映射可输出 |
| I/O | 不存在、无权限、非 UTF-8 保留明确异常 |
| legacy adapter | `count_instructions()` 仍返回旧 dict，`_detailed` 仍是细节计数，旧 renderer 输出不变 |

完成条件：新代码只使用 `InstructionStats`，legacy dict 只出现在 adapter 边界。

## 8. P4：比较层

### 8.1 实现任务

1. 实现 `compare_stats(items, *, baseline_label=None)`；
2. 让 `compare_files()` 只负责读文件、生成唯一 label 和调用 `compare_stats()`；
3. 验证 schema、classification、count mode 和 ISA 可比；
4. 计算 total、全部 category 和全 opcode 并集的 delta；
5. baseline 行也生成全 0 delta；
6. 对外层和内层映射都实现不可变性；
7. 保留 `files/counts/diffs/to_dataframe()` 兼容面。

### 8.2 测试分类

| 测试类 | 输入 | 断言 |
|---|---|---|
| 正常 delta | baseline=10,current=8 | absolute=-2，percent=-20.0 |
| 正增 delta | baseline=8,current=10 | absolute=2，percent=25.0 |
| 零基线 | 0->0、0->3 | 分别为 0.0 和 `None`/`null`，不除零 |
| baseline 自身 | baseline label 对应的行 | total/category/opcode 全为 0 delta |
| 多文件 | 3 个以上 stats | 所有 label 都保留，按输入顺序输出 |
| 不可比 | 版本/count mode/ISA 不一致 | 返回 `not comparable`，不产生假 delta |
| label 冲突 | 同 basename 或重复 `--label` | 自动生成唯一标签或明确拒绝，不覆盖 |
| legacy 属性 | `files/counts/diffs/to_dataframe()` | 与现有输入/输出契约一致，`diffs` 排除 baseline |

完成条件：比较逻辑可以只用内存 stats 单测，不必为每个用例创建文件。

## 9. P5：报告渲染

### 9.1 实现任务

```python
render_text(stats_or_comparison, *, verbose=False) -> str
render_json(stats_or_comparison) -> str
render_markdown(stats_or_comparison, *, verbose=False) -> str
render_html(stats_or_comparison, *, title=...) -> str
render_chart(stats_or_comparison, output_path, *, title=...) -> None
```

- 所有 renderer 只读 `InstructionStats` 或 `ComparisonResult`，不重新解析汇编；
- JSON 严格实现设计文档第 5.2 节的 single/comparison schema；
- HTML 转义 title、label、source 和 opcode；
- Markdown 转义 label 中的 `|`；
- 空结果不调用空 pie，显示 `No instructions found`；
- matplotlib/pandas 继续 lazy import，无图和无 DataFrame 模式不依赖它们；
- 旧 renderer 函数在入口处适配 legacy dict。

### 9.2 测试分类

| 测试类 | 测试内容 |
|---|---|
| Text | 默认只有类别摘要；`verbose=True` 才显示 opcode/unknown；百分比保留一位小数 |
| JSON | `kind`/version/metadata 存在；所有 9 个 category 存在；数值为 number；`null` 规则正确 |
| Comparison JSON | `files` 为数组；baseline 含全 0 delta；opcode 使用全部输入并集 |
| Markdown | 表头、总数、delta、unknown 警告正确；label 含 `|` 时表格不被破坏 |
| HTML | title/path/opcode 中的 `<>&\"` 被 escape；多文件报告不丢文件 |
| Chart | 单文件和多文件都能生成；空输入显示提示而不调用空 pie |
| Optional dependency | 无 matplotlib 时文本/JSON 仍成功，只在请求 chart 时报错；无 pandas 时 `to_dataframe()` 报明确错误 |

完成条件：同一统计对象的所有报告总数、类别和 baseline 一致。

## 10. P6：CLI

### 10.1 执行流程

```text
parse args
  -> validate combinations
  -> assign unique labels
  -> resolve baseline
  -> analyze inputs
  -> build one result model
  -> render stdout
  -> render every requested file
  -> evaluate --fail-on-unknown
  -> return exit code
```

### 10.2 实现任务

- `main()` 返回整数，仅在模块边界 `raise SystemExit(main())`；
- 实现 `--label`、`--baseline`、`--compare`、`--verbose`、`--isa`、`--fail-on-unknown`；
- compare 模式不提前 `return`，所有请求的报告都被尝试生成；
- stdout 只放报告，stderr 放错误和文件写入状态；
- 严格模式在报告生成后返回 2。

### 10.3 测试分类

| 场景 | 预期 |
|---|---|
| 1 file | 默认摘要，`--verbose` 增加明细 |
| 1 file + `--compare` | 参数错误，退出码 1 |
| N files 无 compare | 只允许多份 stdout 摘要；请求文件报告时提示加 `--compare` |
| N files + compare | 所有 renderer 共用同一 baseline |
| labels 数量不对/重复 | 参数错误，不开始渲染 |
| baseline 无匹配/无 compare | 参数错误，退出码 1 |
| unknown + strict | 报告存在，退出码 2 |
| 缺文件/不可写路径 | stderr 明确失败，不输出伪成功 |

完成条件：CLI 组合测试验证输出文件、stdout/stderr 和退出码，不只验证“命令没崩溃”。

## 11. P7：CompilerDriver 集成

### 11.1 实现步骤

1. 在所有汇编后处理完成后取得 `final_asm`；
2. 仅当 `self.config.count_instr` 为真时调用 `analyze_instructions()`；
3. 将 `stats.to_dict()` 写入 `CompileResult.stats["instruction_count"]`；
4. 不再将正常统计写入 `warnings`；
5. LLVM IR backend + `--count-instr` 在编译前返回参数错误。

### 11.2 集成测试

| 测试类 | 断言 |
|---|---|
| 结果结构 | `result.stats` 中存在 `instruction_count` 且可序列化 |
| 最终产物 | `result.stats.total ==` 对最终 `.s` 文件单独分析的 total |
| pass 顺序 | 开启 peephole/const-merge/schedule/beautify 后等式仍成立 |
| 开关 | 关闭 `count_instr` 时不进行额外汇编解析，不写空结果 |
| backend 边界 | LLVM backend 在编译前拒绝 `--count-instr`，不静默跳过 |

完成条件：编译器报告与实际写出产物一致，正常统计不再占用 warning 通道。

## 12. P8：benchmark 和 CI

### 12.1 实现步骤

- 保存 commit/config/source/ISA、`schema_version`、`classification_version`、total/category/opcode/unknown 和 baseline delta；
- 比较前检查 schema、classification、count mode 和 ISA；
- unknown 在主干 CI 中默认要求为 0；
- total 回归阈值由每个 case 显式配置，没有配置时只报告；
- baseline 更新同时评审对应 commit、配置和理由。

### 12.2 测试分类

| 测试类 | 内容 |
|---|---|
| 数据记录 | JSON 字段完整，版本不缺失，unknown 可追溯 |
| 可比性 | 版本/count mode/ISA 不同时标记 `not comparable` |
| 阈值 | 没有配置时只报告；配置 `max_total_increase` 或百分比时按 case 判断 |
| 未知指令 | 主干默认为 0，新 ISA 扩展必须同步更新分类表和版本 |
| 性能 | 1k/10k/100k/1M 行输入；行数放大 10 倍时中位处理时间不超过 15 倍 |

超过性能阈值时先 profile，不直接更新基线；`1M` 行不建立百万项持久 AST 列表。
