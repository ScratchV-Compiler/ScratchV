# 课题12：RISC-V 后端指令计数统计器开发文档

> 文档类型：分层实施指南
> 读者：Topic 12 开发者、测试者和报告/CI 维护者
> 开发基线：仓库当前实现（2026-09-24）
> 先读：[Topic 12 设计文档](12-指令计数统计器-设计文档.md)

---

## 1. 开发目标

将现有“汇编文本 -> 混合字典 -> 文本/HTML”实现演进为一条可验证的分层管线：

```text
语法解析 -> 指令分类 -> 结构化统计 -> 比较
-> 多格式渲染 -> CompilerDriver -> benchmark/CI
```

开发期间必须保持现有公共 API 可用，先建新模型和适配层，再迁移调用方，避免在一次大改中同时修解析、改类别、换 API 和改报告。

## 2. 现有起点

### 2.1 主要文件

| 文件 | 职责 | 开发关注点 |
|---|---|---|
| `scratchv/backend/inst_counter.py` | 解析、分类、统计、比较、报告、CLI | 当前全部在一个模块，需先建逻辑边界 |
| `scratchv/backend/_asm_parser.py` | 共享汇编行解析 | 优先评估复用，避免新建第四套 parser |
| `scratchv/backend/__init__.py` | 后端公共导出 | 迁移期保留 `count_instructions` |
| `scratchv/compiler.py` | 最终汇编后统计 | 当前只向 warnings 写 total |
| `scratchv/main.py` | `--count-instr` 入口 | 需对 RISC-V/LLVM 边界和展示负责 |
| `tests/test_inst_counter.py` | 基础测试 | 需从“存在/不崩溃”升级为精确契约测试 |
| `benchmarks/bench_inst_counter.py` | 如存在，用于性能测量 | 锁定线性扫描与大文件表现 |

### 2.2 当前 API

```python
count_instructions(asm_text) -> dict
count_instructions_file(filepath) -> dict
format_table(counts) -> str
generate_chart(counts, output_path)
generate_multi_chart(multi_counts, output_path)
generate_html_report(counts, output_path)
compare_files(filepaths) -> ComparisonResult
print_comparison(result) -> None
ComparisonResult.to_dataframe()
```

现有 dict 表面类型为 `dict[str, int]`，但 `_detailed` 对应 `Counter`。所有新代码禁止继续扩展这个混合字典，应转向 `InstructionStats`。上述每个公共符号的兼容方案见设计文档第 20.1 节；完成新模型不代表可以立即删除旧签名、属性或 DataFrame 能力。

### 2.3 当前测试局限

- 没有覆盖 `label: instruction`；
- 没有覆盖 FP/atomic/system/compressed 指令；
- HTML 测试只检查存在 `<html`/`<table`，未验证转义和数据完整性；
- 比较测试没有断言 delta；
- 没有 CLI 退出码、`--verbose`、chart 空数据、同 basename 测试；
- 没有验证 CompilerDriver 统计的必然是后处理后产物。

## 5. P0：用测试锁定问题

### 5.1 先添加必然失败的用例

```python
def test_label_and_instruction_on_same_line():
    assert _extract_opcode("loop: addi t0, t0, -1") == "addi"

def test_local_label_and_branch_on_same_line():
    assert _extract_opcode(".L1: bnez t0, .L1") == "bnez"

def test_empty_chart_does_not_crash(tmp_path):
    stats = analyze_instructions("")
    generate_chart(stats, tmp_path / "empty.png")
```

空 chart 用例只在 matplotlib 可用时运行，不得让核心测试强制安装可选依赖。

### 5.2 确定旧行为是否兼容

将现有 ALU/MEM/BRANCH/JUMP/PSEUDO/MISC 样例的计数固定下来。对 `call/ret/j` 等分类口径改变，不应在 P1 解析修复中顺手改；它属于 P2 的版本化分类变更。

### 5.3 完成标准

- 每个已知缺口有对应用例；
- 失败原因只指向一个逻辑层；
- fixture 足够小，人工可计算期望值。

## 6. P1：统一汇编行解析

### 6.1 先评估共享 parser

运行并阅读 `scratchv/backend/_asm_parser.py`的单测。对下列行检查返回值：

```text
add a0, a1, a2
loop:
loop: addi t0, t0, -1
.L1: bnez t0, .L1
.text
.word 0x13
```

共享 parser 的 `ParsedAsmLine.is_directive`、`label` 和 `opcode` 是 Topic 12 的权威结果：只要 `is_directive=True` 就跳过；有 label 但 opcode 为空时跳过；有 opcode 时继续分类。它已覆盖 `.L1:`、数字标签和 `label: instruction`。如不能覆盖新口径，在共享 parser 中增加最小能力并运行后端全部相关测试，不在 Topic 12 内建新 directive 列表。

### 6.2 避免简单 `startswith()` 判定 directive

`.textfoo` 不应因 `.text` 而被无条件跳过。指令和 directive 应基于完整首 token 判断。

### 6.3 删除死逻辑

`_INST_RE` 如不再使用就删除；如决定使用，所有 opcode 提取必须只经过这一条路径。不保留两套看似相同但实际口径不同的解析器。

### 6.4 完成标准

- 标签+指令正确计数；
- 伪操作、纯标签、注释不计数；
- 带点 mnemonic 正确保留；
- 汇编美化器、窥孔优化器、调度器的相关测试无回归。

## 7. P2：建立分类注册表

### 7.1 定义元数据

```python
@dataclass(frozen=True)
class OpcodeInfo:
    category: InstructionCategory
    extension: str
    is_pseudo: bool = False
```

`InstructionCategory` 可使用 `str, Enum` 或受控字符串常量。如使用 Enum，JSON 输出必须显式转为稳定字符串。

### 7.2 按 ISA 扩展分组维护

```text
RV_I_INTEGER
RV_M_INTEGER
RV_F_FLOAT
RV_D_FLOAT
RV_A_ATOMIC
RV_SYSTEM
RV_PSEUDO
```

注册时检查 mnemonic 不重复。同一 opcode 在两组中出现应让测试立即失败，不要依赖字典后写覆盖前写。

### 7.3 分类变更流程

1. 添加失败用例；
2. 确认指令的 ISA 扩展和语义类别；
3. 更新注册表；
4. 判断是补遗漏还是改口径；
5. 如改口径，升级 classification version；
6. 更新报告基线和变更说明。

### 7.4 unknown 测试

使用与 RISC-V ISA 命名无关的 `zz_unknown_opcode`，验证它进入 MISC 且保留在 unknown 列表。不用 `custom-0..3` 命名空间或当前可能尚未支持、但将来会加入的标准 RISC-V 指令作 unknown fixture。

## 8. P3：引入 `InstructionStats`

### 8.1 先建新 API

```python
def analyze_instructions(
    asm_text: str,
    *,
    source: str | None = None,
    isa: str = "unknown",
) -> InstructionStats:
    ...
```

文件 API：

```python
def analyze_file(path: str | Path, *, isa: str = "unknown") -> InstructionStats:
    ...
```

使用 `pathlib.Path` 可以简化类型和 UTF-8 读取，但为兼容应接受 `str | Path` 而不是强制调用方立即修改。

`analyze_file()` 使用 `encoding="utf-8"` 并保留标准 I/O 异常语义：不存在抛 `FileNotFoundError`，无权限抛 `PermissionError`，非 UTF-8 抛 `UnicodeDecodeError`。它不自动忽略或替换非法字节。`count_instructions_file()` 作为 legacy wrapper 保留相同异常类型，不包装成模糊 `RuntimeError`。

### 8.2 集中 legacy adapter

```python
def _stats_to_legacy_dict(stats: InstructionStats) -> dict[str, object]:
    result = dict(stats.category_counts)
    result["_detailed"] = Counter(stats.opcode_counts)
    return result
```

`count_instructions()` 暂时调用 `analyze_instructions()` 并转换。不要让新 renderer 再消费 legacy dict；现有 `format_table/generate_*` 等公共函数在入口处通过同一 adapter 转换，不在 renderer 内穿插 `_detailed` 特判。

### 8.3 不变式

在 `InstructionStats.__post_init__()` 中先将三个输入映射防御性拷贝为新 `dict`，验证后用 `MappingProxyType` 或等价不可变映射通过 `object.__setattr__()` 存回字段。不可直接保存调用方传入的 dict。实现和专用测试验证：

- total 等于 category 之和；
- total 等于 opcode 之和；
- 标准 category 全部存在；
- 计数为非负整数；
- unknown 是 opcode 的子集，其和不超过 MISC。

额外测试必须尝试修改原始输入 dict 和 `stats.category_counts`，确认前者不影响 stats，后者被拒绝。

### 8.4 序列化

实现 `to_dict()`，明确输出 schema version 和所有字段。不使用 `dataclasses.asdict()` 作为长期公共 schema，因为内部字段调整会无意改变 JSON 契约。

## 9. P4：实现比较层

### 9.1 先比较 stats，再封装文件

```python
def compare_stats(
    items: Sequence[tuple[str, InstructionStats]],
    *,
    baseline: str | None = None,
) -> ComparisonResult:
    ...
```

`compare_files()` 只负责读文件、生成唯一 label 后调用 `compare_stats()`。这样单元测试不需为每个 delta 创建临时文件。

`ComparisonResult.stats/category_deltas/opcode_deltas` 都包含 baseline，baseline 的 delta 固定为全 0；三组映射顺序与 `items` 一致。外层和内层映射均防御性拷贝后转为只读映射，并测试两层修改都被拒绝。迁移期同时实现设计文档 20.1 节的 `files/counts/diffs/to_dataframe()` 只读兼容面；其中 legacy `diffs` 仍排除 baseline，`to_dataframe()` 仍保持现有列集和列顺序。

### 9.2 精确测试

对 baseline=10、current=8，断言 absolute=-2、percent=-20.0。同时覆盖 0->0 和 0->3，以及 baseline 自身的全 0 delta。JSON 中 percent 按设计契约 `round(value, 4)`，文本显示 1 位；不使用可能因浮点误差失败的完整 repr 快照。

### 9.3 同 basename

使用两个不同临时目录中的 `output.s` 测试，确保 `result.stats` 有两份不同数据，而不是后者覆盖前者。

## 10. P5：重构渲染层

### 10.1 统一函数约定

内容渲染器优先返回字符串：

```python
render_text(stats, *, verbose=False) -> str
render_markdown(stats_or_comparison, *, verbose=False) -> str
render_json(stats_or_comparison) -> str
render_html(stats_or_comparison, *, title=...) -> str
```

写文件为单独 helper 或 CLI 责任。这使内容测试不依赖文件系统，也便于 benchmark/CI 复用。为兼容，现有 `generate_html_report(counts, output_path)` 可作为写文件包装层。

### 10.2 文本报告

- 默认不显示 opcode 明细；
- verbose 按计数降序、mnemonic 升序；
- 零值 bar 为空，非零值才有至少一个字符；
- total=0 时所有比例为 `0.0%`；
- unknown 存在时即使非 verbose 也显示简短警告。

### 10.3 JSON

使用 `json.dumps(..., ensure_ascii=False, indent=2, sort_keys=True)` 或项目统一格式。数字保持数字类型，不预格式化为带 `%` 的字符串。单文件与多文件分别严格遵循设计文档 12.2 节的两种 schema；比较报告不自行发明第三种嵌套。

### 10.4 Markdown

比较表建议列：

```text
Category | Baseline | Current | Delta | Delta %
```

对 label、opcode 和 path 中的 `|`、换行和反引号做正确转义。

### 10.5 HTML

- 单文件和比较报告使用不同页面主体；
- title、label、source、opcode 全部 `html.escape()`；
- 不将 JSON 直接拼入 `<script>`，除非使用适合 script 上下文的安全序列化；
- 使用内联 CSS，网络断开时仍可读；
- 在小屏幕上允许表格水平滚动。

### 10.6 chart

先处理 total=0，不对空 values 调用 `max()` 或 `pie()`。图表函数保持 matplotlib lazy import，并在 headless 环境使用 `Agg`。生成后始终 `plt.close(fig)`，避免批量 benchmark 泄漏图对象。

## 11. P6：修整 CLI

### 11.1 重排执行流程

```text
parse args
  -> validate combinations
  -> assign/validate one unique label per input
  -> resolve one baseline (compare mode only)
  -> load/analyze all inputs
  -> create single or comparison model
  -> render stdout
  -> render requested files independently
  -> evaluate strict policies
  -> return exit code
```

不要在 compare 分支中提前 `return`，否则 HTML/chart/JSON 会被跳过。

CLI 参数规则固定为：

- `--label LABEL` 可重复，按顺序与位置文件一一对应；数量必须为 0 或等于文件数，值必须唯一；
- `--baseline LABEL|PATH` 只能与 `--compare` 一起使用，先精确匹配 label，再精确匹配原始 path，不做 basename 模糊匹配；
- compare 模式至少需要两个文件，未指定 baseline 时使用第一个输入；
- 多文件但无 `--compare` 时只输出逐文件文本摘要；如请求 JSON/Markdown/HTML/chart，按参数错误返回 1 并提示使用 `--compare`；
- 一次 compare 只构造一个 `ComparisonResult`，所有 renderer 共用它的 baseline。

### 11.2 `main()` 返回整数

将 CLI 内部 `sys.exit()` 改为 `return code`，只在：

```python
if __name__ == "__main__":
    raise SystemExit(main())
```

边界转换。这使单元测试可直接断言退出码。

### 11.3 实现 `--verbose`

当前 `--verbose` 只解析但未影响输出。修复后：

- 默认：只输出 category 摘要；
- `--verbose`：输出 opcode 明细、unknown 和元数据；
- JSON 默认仍应包含完整结构化数据，`--verbose` 只控制人类可读输出。

### 11.4 实现多产物

对每个请求的输出独立渲染和写入。一个渲染器失败时，CLI 必须返回非零并准确报告失败产物；已成功写入的其他文件不应被声称为失败或被自动删除。

### 11.5 参数组合测试

| 输入 | 参数 | 期望 |
|---|---|---|
| 1 file | none | 单文件文本摘要 |
| 1 file | verbose | 摘要 + opcode 明细 |
| 1 file | compare | 参数错误，退出码 1 |
| 2 files | none | stdout 按顺序输出两份独立摘要 |
| 2 files | none + 任一文件 renderer | 参数错误，提示增加 `--compare` |
| 2 files | compare | 相对第一份的 delta |
| 2 files | compare + json + html + chart | 三个文件都生成 |
| 2 files | compare + labels + baseline | 所有 renderer 共用精确匹配的 baseline |
| baseline | no compare / no match | 参数错误，退出码 1 |
| unknown | fail-on-unknown | 报告生成，退出码 2 |
| missing file | any | 明确 stderr，无伪成功消息 |

## 12. P7：接入 CompilerDriver

### 12.1 修改输出位置

统计位于 `_run_asm_passes()` 的所有变换之后、写文件之前，并且只在 `self.config.count_instr` 为真时执行。关闭 `--count-instr` 时不得隐式解析汇编或向 stats 添加空占位。不建议继续通过 `warnings` 反向带回结果。可以：

1. 让 `_run_asm_passes()` 返回 `(asm_text, pass_stats)`；或
2. 在 `compile()` 中的后处理之后、`if self.config.count_instr:` 守卫内单独调用 `analyze_instructions()`。

优先选择第 2 种，让统计作为明确的观测阶段，不和改写汇编的 pass 混在一起。

### 12.2 结果结构

```python
stats: dict[str, Any] = {
    "opt_message": opt_message,
    "cycle_report": cycle_report,
}
if instruction_stats is not None:
    stats["instruction_count"] = instruction_stats.to_dict()
```

CLI 展示只从 `result.stats["instruction_count"]` 读取，不再从 `warnings` 中解析字符串。

### 12.3 backend 校验

在 `args_to_config()` 之后或 compiler 输入校验阶段拒绝 `backend=llvm + count_instr=True`。直接拒绝比静默对 LLVM IR 统计更安全。

### 12.4 集成断言

```python
result = driver.compile(...)
stats = result.stats["instruction_count"]
on_disk = analyze_file(result.output_path)
assert stats["total"] == on_disk.total
assert stats["category_counts"] == on_disk.category_counts
```

对 peephole、const-merge、schedule、beautify 至少各选一个会改变文本的 fixture，验证统计对象是最终文件。

## 13. P8：接入 Benchmark 与 CI

### 13.1 先保存原始数据

不要只把一句“下降 5%”写进 Markdown。CI 先保存 JSON 原始统计和版本，Markdown/HTML 从 JSON 或同一数据对象生成。

### 13.2 基线校验

比较前验证：

```text
schema_version equal
classification_version equal
count_mode equal
isa compatible
benchmark input/config equal
```

不满足时将用例标记为不可比，而不是回退或改进。

### 13.3 阈值策略

- 正确性优先：编译/仿真错误时不评价指令数“改进”；
- total 阈值：按 case 配置，不使用全局一刀切；
- category 阈值：用于发现 spill 导致 MEM 增长等定向问题；
- unknown 阈值：默认 0，新扩展需同步更新分类；
- 所有基线更新必须有变更原因和评审，不在测试失败时自动接受新值。

### 14.6 性能验证

生成固定规模的 1k、10k、100k、1M 行汇编，记录中位耗时和峰值内存。判断扫描时间是否随行数近似线性增长。性能 fixture 应运行时生成，不提交巨大重复文本。

验收阈值：在同一机器、Python 版本和预热方式下，输入行数扩大 10 倍时，中位处理时间不应超过前一档的 15 倍；超过时需要 profile 说明，不得直接更新基线。峰值内存作为观测指标，v1 不设跨平台绝对门禁，但 1M 行分析不得构建百万项持久 AST 列表。

## 16. 调试指南

### 16.1 总数偏小

先查找标签与指令同行的输入，再检查 directive 判断是否使用过宽 `startswith()`。用 `objdump` 作对照时要注意，objdump 数的是机器指令，与带伪指令的 textual 口径可本来就不同。

### 16.2 MISC 突然升高

打印/查看 `unknown_opcodes`，不要只看 MISC 总数。判断是新 ISA 扩展、伪指令，还是 parser 把标签/伪操作误当成 opcode。

### 16.3 比较丢了一个文件

检查是否用 basename 作 dict key。为每个 source 生成唯一 label，并保留原路径字段。

### 16.4 compare 有文本但没有 HTML/chart

检查 CLI 在 `--compare` 分支中是否提前 return。计算 comparison model 后应继续经过统一 renderer 调度。

### 16.5 空文件图表崩溃

图表函数在计算 `max(values)` 或调用 `pie()` 前检查 total/categories。空数据生成带提示的空图，或返回领域错误；选定一种后用测试锁定。

### 16.6 `--verbose` 无效

确认参数真正传入 `render_text(..., verbose=args.verbose)`。不要在 `format_table()` 中无条件附加详细列表。

### 16.7 CompilerDriver 统计与文件不一致

检查统计执行点是否早于 peephole、const-merge、schedule 或 beautify。最终口径必须对写文件的同一 `asm_text` 进行分析。
