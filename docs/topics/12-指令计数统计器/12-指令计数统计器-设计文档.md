## 1. 这个功能要做什么

Topic 12 把 ScratchV 最终生成的 RISC-V 汇编转换为稳定的结构化统计，用于：

- 查看静态指令总数与 9 大主类别构成；
- 比较两个或多个汇编产物，量化编译器优化 Pass（窥孔优化、调度、常量合并等）前后的指令增减；
- 将结果输出为终端文本、结构化 JSON、GitHub Flavored Markdown、防 XSS 独立 HTML 或可视化图表；
- 将数据写入 `CompileResult.stats["instruction_count"]`，供 benchmark 和 CI 作为质量门禁；
- 发现未识别的指令（MISC / unknown_opcodes），防止分类注册表长期漏维护。

它测量的是“汇编文本中的静态 mnemonic 数”，不是运行时动态指令数、周期、Cache miss 或真实执行时间。因此可以说“静态指令减少 8%”，不能单凭本报告说“真实性能提升 8%”。

### 1.1 输入和输出

| 项 | 内容 |
|---|---|
| 输入 | API 传入的汇编文本、一个或多个 `.s` 文件、编译器后处理完成后的最终汇编、仿真器动态统计导入 |
| 核心输出 | `InstructionStats` 或 `ComparisonResult` |
| 人类可读输出 | stdout 终端文本表格、Markdown 报表、独立 HTML 报告、可选 Matplotlib 图表 |
| 机器可读输出 | 严格带版本的 JSON、`CompileResult.stats["instruction_count"]`、CI/benchmark 记录 |

### 1.2 实现边界与口径

核心实现采用 `textual` 模式：

- 每个出现在文本中的指令 mnemonic 计 1 条；
- 空行、注释、纯标签和 assembler directive（如 `.text`、`.word`、`.cfi_*`）不计数；
- 同行标签指令（如 `loop: addi t0, t0, -1`、`.L1: bnez t0, .L1`、`10: nop`、`name$part: add ...`）正确计入后置指令；
- 伪指令按文本中出现的行数计 1 条，不猜测 assembler 最终展开机器指令长度；
- `.word`、`.byte` 等数据 directive 即使内容可解码为机器码，也不计数；
- 未知 mnemonic 计入 `MISC`，同时完整记录其助记符名称和出现频次。

`expanded` 伪指令展开和 objdump 机器码直接计数属于后续扩展能力，不得与 `textual` 结果混淆。

### 1.3 与仿真器（Emulator / Simulator）的协作边界与接口设计

仿真器（如 `RV32Emulator`、`tinyfive`、Spike）与静态指令计数器（`inst_counter`）在编译器体系中处于不同阶段，必须明确其协作边界：

#### 1.3.1 职责划分与反模式阻断
- **严格禁止仿真器在执行热循环（Hot Loop）中调用文本解析器**：
  仿真器运行模型（如执行数千万或数十亿条动态指令）需要微秒/纳秒级效率。若每执行一条指令触发文本解析、正则表达式匹配或字典分配，会导致仿真性能发生 100~1000 倍的断崖式下跌。
- 仿真器内部必须使用紧凑的整数 Enum 或位掩码进行高频硬件计数（如 `CAT_ALU_R = 1, CAT_LOAD = 4`）。

#### 1.3.2 动态统计导入适配接口（`count_mode="dynamic"`）
仿真器在执行完成后，可将其内部聚合的执行计数通过工厂适配接口导入到结构化数据模型中：
```python
def from_emulator_counts(
    opcode_counts: Mapping[str, int],
    *,
    source: str = "emulator",
    isa: str = "rv32im",
) -> InstructionStats:
    """由仿真器收集的动态指令执行计数构造 InstructionStats 对象 (count_mode='dynamic')。"""
```
通过此接口，仿真器的动态执行数据能够直接复用本模块的 Markdown、HTML、JSON 报表渲染器。

#### 1.3.3 静态 vs 动态综合分析（Static-to-Dynamic Profiling）
编译器优化核心在于验证“静态代码削减”是否有效转化为“动态执行热点下降”。双方统一接口后，可联合输出对照报表：
```markdown
| 类别 (Category) | 静态指令数 (Static) | 动态执行数 (Dynamic) | 静态占比 | 动态占比 (热点) |
| :--- | ---: | ---: | ---: | ---: |
| ALU  | 604 | 1,200,000 | 68.1% | 85.0% |
| MEM  |  92 |   200,000 | 10.4% | 14.1% |
| JUMP |   3 |     1,200 |  0.3% |  0.1% |
| **TOTAL** | **887** | **1,413,200** | **100%** | **100%** |
```

## 2. 指令分类注册表规范

所有指令只进入一个主类别。ISA 扩展和“是否伪指令”是正交元数据。

标准 9 大主类别定义与典型指令：

| 类别 | 包含范围与边界 | 典型指令收录 |
|---|---|---|
| **ALU** | 整数算术、逻辑运算、移位、比较、乘除、上位立即数、位操作（Zbb） | `add, addi, sub, mul, mulh, mulhu, div, divu, rem, remu, sll, slli, srl, srli, sra, srai, xor, xori, or, ori, and, andi, slt, slti, sltu, sltiu, lui, auipc, addw, addiw, subw, sllw, srlw, sraw, mulw, divw, remw, c.addi, c.add, c.sub, c.slli, c.srli, c.srai, c.andi, c.and, c.or, c.xor, clz, ctz, cpop, sext.b, sext.h, zext.h, min, max, minu, maxu` |
| **FP** | 浮点算术、融合乘加、开方、比较、转换、符号注入、寄存器搬运 | `fadd.s, fsub.s, fmul.s, fdiv.s, fsqrt.s, fmadd.s, fmsub.s, fnmadd.s, fnmsub.s, fsgnj.s, fsgnjn.s, fsgnjx.s, fmin.s, fmax.s, feq.s, flt.s, fle.s, fclass.s, fcvt.w.s, fcvt.wu.s, fcvt.s.w, fcvt.s.wu, fcvt.l.s, fcvt.lu.s, fcvt.s.l, fcvt.s.lu, fmv.x.w, fmv.w.x, fadd.d, fsub.d, fmul.d, fdiv.d, fsqrt.d, fmadd.d, fmsub.d, fnmadd.d, fnmsub.d, fsgnj.d, fsgnjn.d, fsgnjx.d, fmin.d, fmax.d, feq.d, flt.d, fle.d, fclass.d, fcvt.w.d, fcvt.wu.d, fcvt.d.w, fcvt.d.wu, fcvt.l.d, fcvt.lu.d, fcvt.d.l, fcvt.d.lu, fcvt.s.d, fcvt.d.s, fmv.x.d, fmv.d.x, fmv.s, fabs.s, fneg.s, fmv.d, fabs.d, fneg.d` |
| **MEM** | 整数与浮点内存载入/存储（含压缩指令） | `lb, lbu, lh, lhu, lw, lwu, ld, sb, sh, sw, sd, flw, fsw, fld, fsd, c.lw, c.sw, c.ld, c.sd, c.lwsp, c.swsp, c.ldsp, c.sdsp, c.flw, c.fsw, c.fld, c.fsd, c.flwsp, c.fswsp, c.fldsp, c.fsdsp` |
| **BRANCH** | 条件分支指令及其汇编伪指令 | `beq, bne, blt, bge, bltu, bgeu, beqz, bnez, blez, bgtz, bltz, bgez, bgt, ble, bgtu, bleu, c.beqz, c.bnez` |
| **JUMP** | 无条件跳转、函数调用、返回等控制流伪指令 | `jal, jalr, j, jr, ret, call, tail, c.j, c.jal, c.jr, c.jalr` |
| **ATOMIC** | A 扩展的 load-reserved/store-conditional 和 AMO 原子内存操作 | `lr.w, sc.w, lr.d, sc.d, amoadd.w, amoswap.w, amoand.w, amoor.w, amoxor.w, amomin.w, amomax.w, amominu.w, amomaxu.w, amoadd.d, amoswap.d, amoand.d, amoor.d, amoxor.d, amomin.d, amomax.d, amominu.d, amomaxu.d` |
| **SYSTEM** | 内存屏障（Fence）、CSR 寄存器读写、系统调用与特权指令 | `fence, fence.i, csrrw, csrrs, csrrc, csrrwi, csrrsi, csrrci, csrr, csrw, csrs, csrc, csrwi, csrsi, csrci, ecall, ebreak, wfi, mret, sret, sfence.vma, rdcycle, rdtime, rdinstret` |
| **PSEUDO** | 非控制流的通用汇编语法糖/伪指令 | `li, la, mv, not, neg, negw, sext.w, seqz, snez, sltz, sgtz, nop, c.nop, c.mv` |
| **MISC** | 能够解析为有效指令，但分类注册表未收录的指令 | 自定义专用扩展指令（如专用矩阵/向量算子）或漏维护项 |

### 2.1 伪指令正交分类原则
- **控制流语义优先**：`call, tail, ret, j, jr` 虽然由汇编器展开，但语义是跳转与调用，统一归入 `JUMP`；`beqz, bnez` 等归入 `BRANCH`。
- **纯语法糖归入 PSEUDO**：仅 `li, la, mv, nop, not, neg` 等寄存器赋值与基础变换归入 `PSEUDO`。
- **元数据保留**：注册表中 `OpcodeInfo.is_pseudo = True` 标明其伪指令属性，分类与属性正交。

### 2.2 原子指令内存顺序后缀匹配
Atomic 指令支持在末尾附加 `.aq`、`.rl`、`.aqrl` 内存模型后缀。
匹配时序：
1. 完整助记符精确匹配注册表；
2. 若未命中，正则检查是否匹配 `^(amo\w+\.[wd]|(?:lr|sc)\.[wd])\.(?:aqrl|aq|rl)$`，剥离后缀后回查注册表（如 `amoadd.w.aq` 剥离后匹配 `amoadd.w`）；
3. **严禁无差别删除点号后缀**，因为 `fadd.s`、`c.addi`、`lr.w` 中的点号是指令语义的组成部分；
4. 未命中者一律归入 `MISC`，并记录进 `unknown_opcodes`。

## 3. 数据模型设计

### 3.1 单文件统计结果（`InstructionStats`）

```python
@dataclass(frozen=True)
class InstructionStats:
    category_counts: Mapping[str, int]
    opcode_counts: Mapping[str, int]
    unknown_opcodes: Mapping[str, int]
    total: int
    source: str | None = None
    count_mode: str = "textual"
    isa: str = "unknown"
    schema_version: int = 1
    classification_version: str = "1"
```

#### 不变式校验（Invariants）
`__post_init__` 构造时必须验证并满足：
1. `total == sum(category_counts.values())`
2. `total == sum(opcode_counts.values())`
3. `category_counts` 始终包含全部 9 个主类别，且数值均非负；
4. `unknown_opcodes` 是 `opcode_counts` 的子集，且对应的分类必为 `MISC`；
5. 所有内部映射必须防御性拷贝，并使用 `MappingProxyType` 冻结为深度只读。

### 3.2 多文件基准对比（`ComparisonResult`）

```python
@dataclass(frozen=True)
class CategoryDelta:
    baseline: int
    current: int
    absolute: int
    percent: float | None

@dataclass(frozen=True)
class ComparisonResult:
    baseline_label: str
    stats: Mapping[str, InstructionStats]
    category_deltas: Mapping[str, Mapping[str, CategoryDelta]]
    opcode_deltas: Mapping[str, Mapping[str, int]]
```

#### 比较计算与除零保护规则
```text
absolute = current - baseline
percent = round(absolute / baseline * 100, 4)   (baseline > 0)
percent = 0.0                                   (baseline == 0 且 current == 0)
percent = None                                  (baseline == 0 且 current > 0)
```
- `None` 在控制台文本与 Markdown 中展示为 `N/A`，在 JSON 中序列化为 `null`；
- 基线文件的 Delta 必须全为 0（`absolute=0, percent=0.0`）；
- `opcode_deltas` 覆盖所有参与比较文件的**指令全集并集**；
- 参与比较的文件若 `schema_version`、`classification_version`、`count_mode` 或 `isa` 不一致，直接抛出 `ValueError("not comparable: ...")`，拒绝虚假比对。

#### 标签自动消歧
当对比多个同名汇编文件（例如不同构建目录下的 `baseline/output.s` 与 `opt/output.s`）时，系统自动消歧（如 `output.s#1`、`output.s#2`），防止字典键覆盖。

## 4. 核心处理流程

### 4.1 汇编解析与统计流水线
```text
汇编输入 (文本/文件)
  -> 逐行扫描 (预处理去除 \r\n)
  -> scratchv.backend._asm_parser.parse_line()
  -> 过滤空行、纯注释、纯标签和 is_directive=True 指示符
  -> 提取小写标准 opcode
  -> 查询 OpcodeInfo 注册表 (含原子后缀规范化)
  -> 更新 category_counts, opcode_counts, total
  -> 若类别为 MISC 则追加记录 unknown_opcodes
  -> 守恒校验 invariants
  -> 构造只读 InstructionStats
  -> 渲染文本 / JSON / Markdown / HTML / 图表
```

### 4.2 编译器驱动集成时序
```text
RISC-V 代码生成 (Linear / DAG)
  -> 寄存器分配 (Greedy / LinearScan)
  -> 汇编发射 (AsmEmitter)
  -> 常量合并 Pass (merge_constants)
  -> 指令调度器 Pass (InstructionScheduler)
  -> 汇编美化器 Pass (beautify_asm)
  -> 取得最终纯净汇编 final_asm
  -> if config.count_instr:
       stats = analyze_instructions(final_asm)
       CompileResult.stats["instruction_count"] = stats.to_dict()
  -> 写出最终 .s 文件
```
- **关键约束 1**：统计必须位于所有汇编修改 Pass 之后，保证统计结果与写出磁盘的 `.s` 字节一致；
- **关键约束 2**：正常统计数据严禁追加至 `warnings`，必须写入结构化 `result.stats`；
- **关键约束 3**：LLVM IR backend 并非 RISC-V 汇编，若配置 `count_instr=True`，在编译前直接报错拒绝。

```bash
python -m scratchv.backend.inst_counter FILE [FILE ...]
```

#### 退出码规范：

- `3`：可选渲染依赖缺失（如请求 `--chart` 但未安装 Matplotlib）或报表写出失败。

## 6. 避坑指南（关键质量陷阱）

| 陷阱场景 | 错误表现 | 正确设计与防护 |
|---|---|---|
| **同行标签丢指令** | `loop: addi t0, t0, -1` 漏计 `addi` | 复用 `_asm_parser.py`，提取冒号后的合法助记符 |
| **点号后缀误剥离** | 将 `fadd.s` 剥离为 `fadd` 导致分类失败 | 严格保持点号，仅针对原子指令 `.aq/.rl/.aqrl` 受控归一 |
| **控制流伪指令错放** | 将 `call`/`ret` 归为 `PSEUDO` 导致 JUMP 占比虚低 | 控制流伪指令语义归入 `JUMP`，正交记录 `is_pseudo=True` |
| **基线为零除零异常** | 基线某类数量为 0 时计算增减百分比发生崩溃 | 0->0 返回 `0.0`，0->N 返回 `None`（呈现为 `N/A`） |
| **同名文件字典覆盖** | 比较 `a/out.s` 和 `b/out.s` 时后者覆盖前者 | 使用唯一标签生成器 `_make_unique_labels` 自动编号消歧 |
| **仿真器热循环反模式** | 仿真器执行指令时每步调用文本解析器，性能暴跌 | 仿真器使用紧凑整型计数，执行完毕后通过工厂适配器统一接入 |
| **统计时机过早** | 在窥孔优化前统计，报告指令数多于实际输出文件 | 统一在所有汇编后处理 Pass 之后对最终文本统计 |
| **HTML 报告注入** | 汇编路径或未知指令包含 `<script>` 时被执行 | 所有用户文本强制经过 `html.escape` 严格转义 |

## 7. 兼容性与版本演进

- 保留旧版 `count_instructions(asm_text) -> dict`、`count_instructions_file(path) -> dict`，字典附带 `_detailed` 计数器，保证现有 benchmark 与旧测试 100% 兼容；
- 保留 `ComparisonResult.files`、`.counts`、`.diffs`、`.to_dataframe()` 属性；
- 当 JSON 结构变动时升级 `schema_version`（整型）；当分类字典或口径扩充时升级 `classification_version`（字符串）。
