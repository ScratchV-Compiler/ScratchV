# Topic17 排期：寄存器分配支持伪指令 → 正确统计寄存器溢出

> 目标：在 benchmark（`benchmarks/test_regalloc/bench_cnn.py`）里编译 `models/graph/cnn.onnx`，
> 用**可信分配器（linear-scan）正确统计出寄存器溢出情况**，且产物能被 `RISCVAEncoder` 正确汇编成二进制。
>
> 本文回答两个问题：
> 1. **支持单条指令需要做哪些事**（第 4 节：7 步工作模板）
> 2. **需要支持哪几个指令**（第 3 节：清单 + 语义表）
>
> 全部数据为 2026-08-31 实测，复现命令见文末。

---

## 1. 现状实测（baseline）

### 1.1 cnn.onnx → 指令选择产物

`ONNXParser → ConstantFolder/DCE → InstructionSelector` 共产出 **58 条 MachineInstr**（含 11 条 `.label`）：

| op | 条数 | 类型 | 说明 |
|---|---|---|---|
| `.label` | 11 | 伪 | 块/分支目标标记 |
| `mv` | 12 | **伪** | conv/gemm/reshape/softmax 搬运 |
| `li` | 6 | **伪** | 常量加载 / maxpool·sigmoid 置 0/1 |
| `mul` | 5 | 真 | conv/gemm MAC |
| `add` | 5 | 真 | conv/gemm MAC 累加 |
| `max` | 4 | **伪** | ReLU(x)=max(x,0)，src2 为立即数 0 |
| `slt` | 5 | 真 | maxpool/sigmoid 比较 |
| `bnez` | 5 | **伪** | 分支（目标标签放在 comment 里） |
| `j` | 4 | **伪** | 无条件跳转（标签在 comment） |
| `jalr` | 1 | 真 | return |

→ 真·伪指令共 **31 条**（mv 12 / li 6 / bnez 5 / max 4 / j 4），与旧结论一致。

### 1.2 两个分配器的溢出统计（实测对比）

| 分配器 | 寄存器银行 | spill_slots | sw 指令 | lw 指令 | 产物能否汇编 |
|---|---|---|---|---|---|
| LinearScan v1_5（bench 用） | `_INT_REGS`=27 | **0** ✅ | 0 | 0 | ❌（见 2.2） |
| LinearScan v1_5 | `ALL_REGS`=19 | **0** ✅ | 0 | 0 | ❌ |
| LinearScan v1（compiler.py 用） | 默认 27 | 0 ✅ | 0 | 0 | ❌ |
| Greedy（register_alloc.py） | `ALL_REGS`=19 | **12 ❌（假）** | 12 | **0** | ✅ |

- 关键事实：CNN 峰值同时存活 vreg = **11**（`peak_active=11`）< 19 → 正确分配器应 **0 溢出**。
- **greedy 的 12 是假象**：`register_alloc.py:164 _assign_reg` 的 LRU 只插溢出 `sw`、从不插重载 `lw`，
  被挤出寄存器后读到的是被复用的旧值（语义也不完整）。**greedy 的溢出计数不可信**。

### 1.3 结论

- **linear-scan 的溢出数（0）已经是对的**——缺的不是"算对溢出"，而是：
  (a) 输出无法汇编（伪指令/标签发射格式错误）；
  (b) 两个分配器银行不一致，导致"统计口径"不可信；
  (c) 没有集中的伪指令语义表，`block_from_machine_instrs` 靠通用 operand-kind 推断，遇新伪指令即错。

## 2. 差距拆解（为什么现在"不能算正确"）

### 2.1 差 1 — linear-scan 输出汇编不了（阻断性）

`compiler.py:412` 的 linear 路径 `lsa.emit(ls_insts)` 走 `LsInstruction.to_asm(rename)`，产物：

```asm
  .label main_graph  # main_graph      ← 伪指令形式，不是 "main_graph:"
  bnez t6  # .Lmp_gt_1                  ← 分支目标只存在 comment 里
  j  # .Lmp_done_2                       ← 同上
```

`RISCVAEncoder` 汇编时：先剥 comment → `bnez t6` 只剩 1 个 operand → `riscv_encoder.py:448` 取
`operands[1]` 抛 **IndexError**。即 **linear 产物无法编译成二进制**，benchmark 里 `asm_valid=True`
是 `_validate_asm`（只查 opcode 白名单 + 未消解 vreg）的**假阳性**。

### 2.2 差 2 — 两个分配器银行不一致（口径不可信）

- greedy：`ALL_REGS` = t0–t6 + s0–s11 = **19**（`machine_types.py:172`）
- linear v1/v1_5：默认 `_INT_REGS` = a0–a7 + t0–t6 + s0–s11 = **27**（`regalloc_linear.py:26`）

同一序列 greedy 报 12、linear 报 0，一半原因是银行不同。评估溢出必须先定银行（**19**）。

### 2.3 差 3 — 无集中语义表（结构性缺口）

`block_from_machine_instrs`（`regalloc_linear.py:548`）按 operand.kind 通用推断 def/use：
- `max %v %rs 0`：src2=imm → 不进 uses ✅；`li %v 0`：def=1 ✅
- 但**对 terminator、clobber、分支目标位置、隐式临时寄存器一概无感知**。

伪指令要在分配器里"被支持"，需要一张**每条伪指令的寄存器语义表**（defs/uses/imm/terminator/target/clobber/n_phys），
分配、压力、发射、验证都查这张表——而不是靠 operand.kind 碰运气。

### 2.4 差 4 — 无基本块切分（正确性的天花板）

当前 linear 把**整个函数当一个基本块**（`.label` 只当普通指令），跨分支的值被保守延长存活 → 压力被高估 → 溢出可能被高估。
CNN 无环、前向分支，保守下仍是 0，所以**达标 cnn.onnx 不必先切块**；但要宣称"统计正确"必须补。

### 2.5 差 5 — 溢出指标定义不一致

- greedy 数 `sw` 指令数（12）
- linear 数 `_spill_slots`（0，唯一 vreg 数）
- LLVM 对比又数 `sp 4 字节访问/2`（`bench_cnn.py:_llvm_spill_stats`）

→ 需要统一定义：**溢出次数 = 分配器插入的 spill `sw` 站点数**（reload `lw` 数可作为第二指标）。

## 3. 需要支持的指令清单

### 3.1 伪指令（必须，5 个）— cnn 里出现 31 条

| op | defs | uses | imm 位 | terminator | target 位置 | clobber | 展开后 n_phys |
|---|---|---|---|---|---|---|---|
| `mv rd, rs` | rd | rs | – | 否 | – | – | 2（addi rd,rs,0） |
| `li rd, imm` | rd | – | src1 | 否 | – | – | 1（addi / lui+addi） |
| `max rd, rs1, rs2` | rd | rs1,rs2 | src2（可为 imm 0） | 否 | – | – | 3（bge/addi/j/…，压同 rd,rs1,rs2） |
| `bnez rs, label` | – | rs | – | **是** | comment→**应改为 operand** | – | 1（bne rs,x0,label） |
| `j label` | – | – | – | **是** | comment→**应改为 operand** | – | 0（jal x0,label） |
| `call label`（顺带） | rd=ra | – | – | **是** | operand | **击穿 caller-saved** | 1+ |

> `max` 展开为 `bge / addi rd,x0,0 / j / label: / addi rd,rs1,0 / label:` —— 展开**不新增 vreg、不升压**，
> 所以伪指令层面算的压力 == 展开后压力，可以做一致性校验（见 4.6）。

### 3.2 控制流真指令（terminator 语义，供 3.1/差 4 切块用，5 个）

| op | defs | uses | terminator |
|---|---|---|---|
| `jalr rd, rs`（ret） | rd（ret 时为 x0=无） | rs（ret 读 ra） | **是** |
| `jal` | rd | – | **是** |
| `beq / bne / blt / bge` | – | rs1, rs2 | **是** |
| `call` | ra | – | **是** |

### 3.3 已支持真指令（只需回归，不新增工作）

`add / addi / sub / mul / div / slt / srai / xor / and / rem`（ALU）、`lw / sw`（访存）。
这些在 cnn 里出现的是 `add / mul / slt`，通用 operand-kind 推断已正确，加回归测试即可。

### 3.4 标签/伪指令发射格式（1 个）

`MachineOp.LABEL`：现在 linear 输出 `.label name  # name`，必须改为汇编可解析的 `name:`，
且分支（`bnez`/`j`/`beq`/…）的 target 要作为**真 operand** 输出（`bnez rs, name`）。

### 3.5 汇总：本次要"做"的指令

| 优先级 | 指令 | 数量 |
|---|---|---|
| P0 必须 | `mv, li, max, bnez, j` + `jalr` + `MachineOp.LABEL` | 7 |
| P0 口径 | `ALL_REGS`(19) 统一（greedy/linear/bench 三处） | – |
| P1 鲁棒 | 真分支族 `beq/bne/blt/bge/jal/call` terminator + 基本块切分 | 6 |
| P1 修假 | greedy `_assign_reg` 补 reload / 或下线其 spill 计数 | 1 |

## 4. 支持单条指令的工作模板（7 步）

> 对 3.1/3.2 里每一条指令 O，都按下面 7 步做。一步 = 一个小 commit。

### 4.1 在语义表加一行
新建 `scratchv/backend/machine_semantics.py`：`OP_SEM[op] = (defs, uses, imm_pos, is_terminator, target_in_operand, clobber, n_phys)`。
按第 3 节表格逐条填。`block_from_machine_instrs` 改为查表（替代 548 行起的通用推断）。

### 4.2 分配器适配
- `compute_live_intervals` / `allocate` 用表的 defs/uses（**立即数位序绝不进 uses**）。
- `is_terminator` 交给块切分（P1）；P0 阶段至少保证不把 label 当 vreg。

### 4.3 发射层修复（针对 target 在 comment 的伪指令）
- `bnez`/`j`：`get_allocated_code` 里把 comment 里的标签提取为 operand → `bnez rs, name`。
- `MachineOp.LABEL`：输出 `name:`（无缩进注释）。复用 greedy 侧 `AsmEmitter` 的既有正确做法。

### 4.4 编码器回归
`riscv_encoder.py:_expand_pseudo` 已支持 li/max/bnez-带标签/j，但**确认**它能把新发射格式
（`bnez rs, name`、`name:`）正确解析；给 `_encode_line` 的 `bnez`/`j` 补 "标签必须存在" 的防御。

### 4.5 单指令单元测试（`tests/test_regalloc_pseudo.py`）
每条伪指令一个 case：构造 2–3 条含该伪指令的 LsInstruction → `compute_live_intervals` 的 defs/uses 正确 → 
`allocate` 后输出可被 `RISCVAEncoder.assemble()` 通过且分支目标解析到。

### 4.6 压力一致性校验（伪指令层 vs 展开层）
把伪指令序列先 `_expand_pseudo` 展开成真指令，再跑同一分配器，断言**两次 spill 数一致**。
这是"伪指令统计 == 真实指令统计"的机器可验证证明，直接回扣本课题的目标。

### 4.7 端到端回归（`bench_cnn.py`）
跑 `make bench` 对应用例：`asm_valid` 改为"真实汇编通过"（替换 `_validate_asm` 假阳性）；
`reg_spill_count` 断言 == 展开层分配结果。

> 单条伪指令 ≈ 0.5–1 天（4.1–4.5 为主，4.6/4.7 可批量）。

## 5. 排期

| 阶段 | 内容 | 涉及指令 | 工作量 | 交付物 |
|---|---|---|---|---|
| **P0-A** 基础设施 | 语义表 `machine_semantics.py` + `block_from_machine_instrs` 改查表 + 银行统一 19（compiler/greedy/bench 三处）+ 溢出指标统一定义 | 5 伪 + jalr + label | 1.5 天 | 表、指标、口径一致 |
| **P0-B** 发射修复 | label→`name:`、bnez/j→target 进 operand；`RISCVAEncoder` 回归 | bnez, j, label | 1 天 | linear 产物可汇编 |
| **P0-C** 单元测试 | `test_regalloc_pseudo.py` 每指令 1 case + `_expand_pseudo` 压力一致性校验 | 5 伪 + jalr | 1 天 | 测试绿 |
| **P0-D** 端到端 | `bench_cnn.py` `_validate_asm` 换真实汇编；spill 断言接 4.6 | 全部 | 0.5 天 | benchmark 达标 |
| **P1-A** 块切分 | 按 terminator+label 切基本块，live-in/live-out 携带 | beq/bne/blt/bge/jal/call/ret | 1.5 天 | 通用溢出正确性 |
| **P1-B** greedy 修复 | `_assign_reg` 补 reload 发射（或声明其计数不可用） | greedy | 1 天 | 两分配器对齐 |

**P0 合计 ≈ 4 天**（达到目标：benchmark 编译 cnn.onnx + 正确统计溢出 = 0）。
**P1 合计 ≈ 2.5 天**（鲁棒性/通用性，达标后按需做）。

## 6. 验证标准（验收清单）

1. `python benchmarks/test_regalloc/bench_cnn.py` 成功跑完，`reg_spill_count == 0`（peak 11 < 19）。
2. linear-scan 产物 `RISCVAEncoder.assemble()` 通过，分支目标全部解析（`asm_valid` 不再假阳性）。
3. 伪指令序列与展开后序列，spill 数一致（4.6 校验在 CI 里跑）。
4. greedy 与 linear 在**同一 19 寄存器银行**下结果可解释（greedy 修后 == 0，或明确标注不可信）。
5. `tests/test_regalloc_pseudo.py` 全绿；`make test` 无回归。

## 附录：复现命令

```bash
# 1) 伪指令序列 + 两个分配器对比
scratchv_env/bin/python -c "
from scratchv.frontend.onnx_parser import ONNXParser
from scratchv.backend.instruction_select import InstructionSelector
from scratchv.backend.regalloc_linear_v1_5 import block_from_machine_instrs, LinearScanAllocator
from scratchv.backend.machine_types import ALL_REGS
from scratchv.backend.register_alloc import RegisterAllocator
machine = InstructionSelector(ONNXParser().parse('models/graph/cnn.onnx')).run()
for name, bank in [('27', None), ('19', ALL_REGS)]:
    b = block_from_machine_instrs(machine)
    a = LinearScanAllocator(phys_regs=(list(bank) if bank else None))
    a.allocate(a.compute_live_intervals(b))
    print(name, 'spills=', len(a._spill_slots), 'peak=', a.peak_active)
for m in ['naive','greedy']:
    o = RegisterAllocator(machine, mode=m).run()
    print(m, 'sw=', sum(1 for x in o if x.op.value=='sw'), 'lw=', sum(1 for x in o if x.op.value=='lw'))
"

# 2) linear 产物汇编失败复现（IndexError: bnez 缺目标 operand）
scratchv_env/bin/python -c "
from scratchv.compiler import CompilerDriver, CompilerConfig
r = CompilerDriver(CompilerConfig(backend='riscv', reg_alloc='linear')).compile('models/graph/cnn.onnx', '/tmp/c.s')
from scratchv.backend.riscv_encoder import RISCVAEncoder
try: RISCVAEncoder().assemble(r.output_text)
except IndexError: print('linear asm 无法汇编（bnez 标签在 comment）')
"
```
