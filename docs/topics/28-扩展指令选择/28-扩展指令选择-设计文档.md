## 阶段 1：总体设计与整数闭环

### 一、功能介绍

#### 1.1 背景

ScratchV 共享后端将 DSL 或 ONNX 前端产生的 IR 翻译成 RISC-V 汇编：

```text
DSL / ONNX
    ↓
Program / Function / BasicBlock / Instruction
    ↓  指令选择
MachineInstr（仍使用虚拟寄存器）
    ↓  寄存器分配
使用 t0/s0/f0 等物理寄存器的 MachineInstr
    ↓  汇编发射
RISC-V 汇编
```

现有基础指令选择器支持 `add/sub/mul/div`、访存、分支以及若干神经网络操作，但对整数余数、常用数学操作和原生 f32/f64 浮点缺少完整的端到端支持。仓库已有 `inst_select_ext.py` 原型和部分 `MachineOp`，但前端、IR、寄存器分配、主编译管线和测试尚未贯通。

#### 1.2 设计目标

- 在共享 IR 中表示 `rem/mod`、`sqrt`、`min/max`、`abs` 等操作。
- 为 `i32` 实现合法的 RV32IM 指令选择。
- 让 `f32/f64` 从 IR 类型传播到 F/D 扩展指令、浮点寄存器、4/8 字节访存和 ABI 返回值。
- 明确浮点精度、舍入模式、NaN/零和异常标志语义。
- 为“硬件指令 / 伪指令序列 / 库调用”多候选降低预留目标特性和成本选择接口。
- 确保每条输出指令的操作数类型和寄存器类别合法，不只检查“出现了某个 opcode”。
- 通过 `--extended-isel` 显式启用新能力，开关默认关闭，保持旧路径兼容。
- 建立单元、集成、汇编合法性和语义测试。
- 补充操作和数据类型支持文档。

#### 1.3 非目标

- 不修改 `standalone/onnx_to_riscv_standalone.py` 的 CNN 直接机器码生成路径。
- 不在本课题实现完整的 IEEE 754 软浮点库。
- 不实现浮点向量化或 RISC-V V 扩展。
- 不对 LLVM 后端重复实现指令选择；LLVM 路径继续由 LLVM 完成目标降低。
- 不将 `transpose/concat` 未经数据布局证明地降低为“复制第一个指针”的 no-op。这两个算子不属于本课题交付范围。
- 不实现完整的 DAG 指令选择或全局调度成本模型；只引入轻量候选模式选择接口。

#### 1.4 当前实现与目标状态

以 2026-09-28 工作区为基线：

| 能力 | 当前状态 | 目标状态 |
|---|---|---|
| `DataType.FLOAT32/FLOAT64` | 已定义，ONNX `FLOAT/DOUBLE` 已映射 | 保留并补齐构造、传播和验证 |
| 基础 `div` | 已选择为 `DIV`，但常量操作数可能直接落到寄存器位置 | `i32` 源始终是 GPR，`f32/f64` 源始终是 FPR |
| 扩展 IR opcode | `OpCode` 中缺失 | 新增 `REM/SQRT/MIN/MAX/ABS` |
| 扩展选择器 | `inst_select_ext.py` 有原型 | 与真实 IR、寄存器类和主管线贯通 |
| F/D 扩展 MachineOp | 部分已列出 | 补齐 f32/f64 指令，删除非标准 `li.d`，增加舍入信息 |
| 浮点寄存器 | 未实现，所有 vreg 均分配到 GPR | `f32/f64` vreg 均分配到 FPR |
| `flw/fsw/fld/fsd` 输出 | FP 路径未完整贯通 | 输出标准 `offset(base)` 格式 |
| `--extended-isel` | CLI 已声明，但 `CompilerConfig` 未保存 | 完整贯通 CLI 到 `CompilerDriver` |
| 测试 | 13 个用例主要检查对象创建和旧操作 | 直接覆盖扩展 IR、汇编和语义 |

> 课题描述中的 `type_system.py` 在当前仓库中不存在，实际类型系统文件为 `scratchv/ir/types.py`。

### 二、语义与类型设计

#### 2.1 新增 IR 操作

| IR opcode | 操作数 | 结果 | 允许类型 | 语义 |
|---|---:|---:|---|---|
| `REM` | 2 | 1 | `i32` | RISC-V 有符号余数 |
| `SQRT` | 1 | 1 | `f32` 或 `f64` | IEEE 754 单/双精度平方根 |
| `MIN` | 2 | 1 | 相同的 `i32`、`f32` 或 `f64` | 返回较小值 |
| `MAX` | 2 | 1 | 相同的 `i32`、`f32` 或 `f64` | 返回较大值 |
| `ABS` | 1 | 1 | `i32`、`f32` 或 `f64` | 绝对值 |

DSL 同时接受 `rem(a, b)` 和 `mod(a, b)`，二者在第一版均降低为 `OpCode.REM`，遵循 RISC-V `rem` 语义，不声称与 Python `%` 在负数上一致。文档和测试必须显式说明这一点。

#### 2.2 整数除法和余数语义

`DIV`/`REM` 使用 RV32M 有符号语义：

- 商向 0 截断。
- 非零余数与被除数同号。
- 除数为 0 时不由选择器插入陷阱，保留 ISA 定义的结果。
- `INT32_MIN / -1` 的溢出行为按 ISA 定义测试，选择器不插入额外分支。

#### 2.3 类型传播

IRBuilder 不再为所有结果默认创建 `f32` 值。二元操作按以下规则生成结果：

```text
require lhs.dtype == rhs.dtype
require dtype is supported by opcode
dest.dtype = lhs.dtype
```

一元操作的结果类型继承输入。`LOAD` 的结果类型由指针所指元素类型决定；在当前 IR 没有独立指针类型的情况下，`builder.load(ptr, dtype=...)` 需允许显式指定。

不做隐式 `i32↔f32`、`i32↔f64` 或 `f32↔f64` 转换。异构操作数在 IR 验证阶段报错，不由指令选择器根据“任意一个操作数的 dtype”猜测转换或指令。

#### 2.4 DSL 类型入口

为了在不引入完整类型声明语法的情况下编写 `f32/f64` 用例，新增显式常量操作：

```text
a = const(1.5, dtype:f64)
b = const(2.0, dtype:f64)
c = add(a, b)
return c
```

`dtype` 只接受 `i32`、`f32`、`i64`、`f64`；缺省值与现有字面量一致，为 `f32`。当前简单 DSL 的未声明名称仍是 `f32`，不在本课题扩展函数参数声明语法。

#### 2.5 IR 验证签名

`analysis/ir_verifier.py` 的集中签名表增加：

| 指令 | 签名 |
|---|---|
| `REM` | `(i32, i32) -> i32` |
| `SQRT` | `(F) -> F`，`F ∈ {f32, f64}` |
| `MIN/MAX` | `(T, T) -> T`，`T ∈ {i32, f32, f64}` |
| `ABS` | `(T) -> T`，`T ∈ {i32, f32, f64}` |

验证器只报告错误，不修改 dtype，不插入 cast，不将混合类型或不支持的类型组合静默改为其他操作。

#### 2.6 `DIV/REM/MOD` 表示决策

保留现有单一 `OpCode.DIV`，由已验证的结果 dtype 决定 `i32 -> div`、`f32 -> fdiv.s`、`f64 -> fdiv.d`。不新增与它重叠的 `IDIV` OpCode。

IR 只新增 `REM`；DSL `mod(a,b)` 是其语法别名，不新增独立 `MOD` OpCode。这样保持旧 `DIV` IR 兼容，同时避免两个语义完全相同的操作码进入所有下游 pass。

### 三、指令选择设计

#### 3.1 总体结构

保留 `InstructionSelector` 作为 RV32IM 默认选择器，`ExtendedInstructionSelector` 继承它并覆写类型相关操作：

```text
InstructionSelector
    ├─ 现有 RV32IM 操作
    └─ 操作数合法化辅助方法
            ↑
ExtendedInstructionSelector
    ├─ i32 rem/min/max/abs
    ├─ f32/f64 load/store/arithmetic
    ├─ f32/f64 compare/min/max/abs/sqrt
    ├─ TargetFeatures + SelectionPattern 候选选择
    └─ 按 dtype 选择 GPR/FPR 操作数
```

不在 `supported_ops` 中声称一个 `OpCode` 中尚不存在、或者无法从前端构造的操作已受支持。

#### 3.2 目标特性与候选模式

同一 IR 操作可能有多个合法降低方案。例如 `sqrt(f64)` 可以选择 `fsqrt.d`、libm `sqrt` 或未来的软件展开。为避免将选择政策散落在多个 `_select_*` 分支中，引入轻量接口：

```python
@dataclass(frozen=True)
class TargetFeatures:
    isa: str = "rv32im"
    abi: str = "ilp32"
    rounding_mode: str = "rne"
    libm_available: bool = False
    optimize_for: str = "balanced"  # size / speed / balanced

@dataclass(frozen=True)
class SelectionPattern:
    name: str
    opcode: OpCode
    dtypes: tuple[DataType, ...]
    required_extensions: frozenset[str]
    estimated_cost: int
    predicate: PatternPredicate
    emit: PatternEmitter
    priority: int = 0
```

每个 `_select_*` 仍是现有 `getattr` dispatch 的稳定入口，但可从注册表中过滤“类型正确且目标特性满足”的 pattern，再按 `(estimated_cost, priority, name)` 确定性选择。初版不做全局 DAG 成本分析，也不让不合法候选参与比较。

#### 3.3 整数指令降低

| IR | RV32IM 输出 | 备注 |
|---|---|---|
| `DIV i32` | `div rd, rs1, rs2` | `rs1/rs2` 必须是 GPR |
| `REM i32` | `rem rd, rs1, rs2` | `mod` DSL 别名也到该路径 |
| `ABS i32` | `srai/xor/sub` | 保留 `INT32_MIN` 的二进制补码结果 |
| `MIN i32` | `slt` + 掩码选择 | 不依赖 Zbb `min` |
| `MAX i32` | `slt` + 掩码选择 | 不依赖非 RV32IM 指令 |

`min/max` 使用正确的全位掩码，不能将 `slt` 产生的 0/1 直接与差值做 `and`。一种无分支的 `min` 方案为：

```asm
slt  flag, a, b       # flag = a < b
sub  mask, x0, flag   # mask = 0x00000000 or 0xffffffff
xor  diff, a, b
and  diff, diff, mask
xor  dst, b, diff     # flag ? a : b
```

`max` 交换选择项即可。如临时 vreg 由选择器生成，必须使用统一的 fresh-name 机制，不得固定使用 `_min_tmp1` 而与多条操作或用户名称冲突。

#### 3.4 立即数合法化

RISC-V `add/sub/mul/div/rem` 都是寄存器-寄存器指令。选择器需区分：

- 允许立即数的机器操作，如 `ADDI`、`SRAI`、`LI`。
- 只允许寄存器的机器操作，如 `ADD`、`MUL`、`DIV`、`REM`、`FADD_S`、`FADD_D`。

对后一类操作，常量必须先由它自己的 `LOAD_CONST` 定义产生虚拟寄存器，或由选择器显式物化到 fresh vreg。不得输出：

```asm
div t1, t0, 2       # 非法：第三个操作数不是寄存器
```

#### 3.5 `f32/f64` 算术和访存

| IR | RV32F 输出 | RV32D 输出 | 寄存器类别 |
|---|---|---|---|
| `LOAD` | `flw fd, offset(rs1)` | `fld fd, offset(rs1)` | `fd:FPR`, `rs1:GPR` |
| `STORE` | `fsw fs2, offset(rs1)` | `fsd fs2, offset(rs1)` | `fs2:FPR`, `rs1:GPR` |
| `ADD` | `fadd.s fd, fs1, fs2` | `fadd.d fd, fs1, fs2` | FPR/FPR/FPR |
| `SUB` | `fsub.s fd, fs1, fs2` | `fsub.d fd, fs1, fs2` | FPR/FPR/FPR |
| `MUL` | `fmul.s fd, fs1, fs2` | `fmul.d fd, fs1, fs2` | FPR/FPR/FPR |
| `DIV` | `fdiv.s fd, fs1, fs2` | `fdiv.d fd, fs1, fs2` | FPR/FPR/FPR |
| `NEG` | `fneg.s fd, fs1` | `fneg.d fd, fs1` | FPR/FPR |
| `ABS` | `fabs.s fd, fs1` | `fabs.d fd, fs1` | FPR/FPR |
| `MIN/MAX` | `fmin.s/fmax.s` | `fmin.d/fmax.d` | FPR/FPR/FPR |
| `SQRT` | `fsqrt.s fd, fs1` | `fsqrt.d fd, fs1` | FPR/FPR |

`STORE` 的 IR 操作数顺序保持现有约定 `[address, value]`；降低到机器指令时显式映射为 `store value, offset(address)`，不得将 IR 的 operand 0 误当作待写入值。F/D 指令使用同一组 32 个 FPR；D 扩展使 FLEN=64，f32 值遵守 NaN-boxing 规则。

#### 3.6 `f32/f64` 比较与分支

IR 继续使用现有 `BR_IF` 比较形式，按 dtype 选择 `.s/.d` 后缀，再按 `cmp_op` 生成比较：

| `cmp_op` | 机器序列 |
|---|---|
| `==` | `feq.s gpr, fa, fb` / `feq.d gpr, fa, fb` |
| `!=` | `feq.s gpr, fa, fb` / `feq.d gpr, fa, fb`，再反转条件 |
| `<` | `flt.s gpr, fa, fb` / `flt.d gpr, fa, fb` |
| `>` | `flt.s gpr, fb, fa` / `flt.d gpr, fb, fa` |
| `<=` | `fle.s gpr, fa, fb` / `fle.d gpr, fa, fb` |
| `>=` | `fle.s gpr, fb, fa` / `fle.d gpr, fb, fa` |

浮点比较结果写入 GPR，然后使用 `bnez` 或 `beq` 分支。这是一条同时涉及 FPR 源和 GPR 目标的重要测试路径。

#### 3.7 `sqrt` 策略

具备 F/D 扩展时，f32 默认选择 `fsqrt.s`，f64 默认选择 `fsqrt.d`。不在第一版默认调用 `sqrtf/sqrt` 库函数，因为硬浮点 ABI 参数和返回值使用 `fa0`，而当前原型错误地使用 `a0` 和普通 `mv`。

如后续保留软件库回退，必须另设显式开关，并在调用前后遵守与精度匹配的硬浮点 ABI（`ilp32f/ilp32d`）、保存活跃 caller-saved FPR，不得与硬件路径共用 GPR `MV`。

#### 3.8 浮点舍入、精度和特殊值

- 算术和平方根默认使用 `RNE`（round to nearest, ties to even），不依赖调用环境中未知的动态 `frm`。
- `MachineInstr` 增加可选 `rounding_mode`，`AsmEmitter` 为需要舍入的 FP 指令输出静态 `rne`。`fmin/fmax`、比较和符号操作不附加 rm。
- f32/f64 分别使用 IEEE 754 binary32/binary64，不允许先转为 Python `int` 或经过低精度十进制文本往返。
- 浮点异常默认设置 `fcsr` 标志而不触发 trap。
- `fmin/fmax` 按 RISC-V F/D `minimumNumber/maximumNumber` 语义处理 NaN，并将 `-0.0` 视为小于 `+0.0`；测试不直接以 Python `min/max` 作为这些边界的参考。

#### 3.9 `f32/f64` 常量

RISC-V 没有标准 `li.s/li.d`。当前 `LI_D` 不能作为最终汇编输出，也不能先将 `1.5` 转成整数 `1`。

目标方案使用按宽度对齐的常量池：f32 使用 4 字节 `.word + flw`，f64 使用 8 字节 `.quad + fld`。例如：

```asm
.section .rodata
.p2align 3
.LC_f64_0:
  .quad 0x3ff8000000000000   # 1.5

.text
  la  t0, .LC_f64_0
  fld f0, 0(t0)
```

选择器按 dtype 和 IEEE 754 位模式联合去重，`+0.0/-0.0`、NaN 位模式和 Inf 不得经过十进制文本往返而改变。常量池标签只在当前编译单元内可见。

#### 3.10 常量折叠语义

`optimizer/constant_folding.py` 需同步识别 `REM` 及类型正确的 `DIV`。整数折叠不得直接使用 Python `//` 和 `%`，因为它们的负数语义与 RISC-V 不同。对非零除数：

```text
q = trunc_toward_zero(a / b)  # 用整数绝对值运算实现，不经过 float
r = a - q * b
```

除零折叠在初版保守跳过；`INT32_MIN / -1` 按 RV32 回绕结果处理。浮点常量折叠只有在能证明与目标 binary32/binary64 + RNE 相同时才启用，否则保留到目标指令。

### 四、寄存器类与溢出设计

#### 4.1 寄存器类

新增机器寄存器类：

```python
class RegisterClass(enum.Enum):
    GPR = "gpr"
    FPR = "fpr"
```

`MachineOperand` 对 `reg/vreg` 记录 `reg_class`，立即数和标签不需寄存器类。为保持旧代码兼容，未指定的现有整数操作数默认为 GPR。

`machine_semantics.py` 除 defs/uses 以外记录每个位置的类别约束，例如：

```text
FADD_S/FADD_D: dst=FPR, src1=FPR, src2=FPR
FLW/FLD:         dst=FPR, src1=GPR
FSW/FSD:         operand0=FPR(value), operand1=GPR(address)
FLT_S/FLT_D:     dst=GPR, src1=FPR, src2=FPR
```

同一 vreg 在不同指令中出现矛盾类别时立即报错，不将位模式在 GPR/FPR 间静默移动。

#### 4.2 物理寄存器池

| 类别 | 初版可分配池 | 保留 |
|---|---|---|
| GPR | 现有 `t0-t6, s0-s11` | `zero/sp/ra/gp/tp`、ABI 参数寄存器 |
| FPR | `ft0-ft11` | `fa0-fa7` 作为参数/返回，`fs0-fs11` 留待 ABI 保存支持 |

初版仅分配 caller-saved `ft*` 可避免错误使用未在 `abi_frame.py` 保存的 `fs*`。在无外部调用的默认硬件 `sqrt` 路径中可安全使用。

#### 4.3 分配器策略

`naive` 和 `greedy` 分配器将分别维护 GPR/FPR 映射与空闲池。`linear` 分配器在支持寄存器类之前，遇到 FPR vreg 必须给出明确错误，不能生成错误汇编；本课题交付前再将线性扫描按类别分配补齐。

分配时必须保证：

- GPR 和 FPR 名称空间分离。
- 一条混合类指令的源/目标分别从正确池中取寄存器。
- 活跃值穿越 `CALL` 时，caller-saved GPR/FPR 都需溢出或保存。
- 目标值和源值同名时依据 machine semantics 处理，不重复加载。

#### 4.4 溢出槽

| 值类型 | 槽大小 | 对齐 | 写回/加载 |
|---|---:|---:|---|
| GPR/i32 | 4 字节 | 4 | `sw/lw` |
| FPR/f32 | 4 字节 | 4 | `fsw/flw` |
| FPR/f64 | 8 字节 | 8 | `fsd/fld` |

分配器不再只返回“槽位数”，而是返回总溢出字节数或带 size/alignment 的 frame layout。`abi_frame.py` 根据真实字节数建立 16 字节对齐栈帧。

#### 4.5 ABI 返回值

- `i32` 返回值使用 `a0`。
- `f32/f64` 返回值都使用 `fa0`，并由类型决定值的宽度。
- FPR 间复制分别使用 `fmv.s/fmv.d`，不使用整数 `mv`。
- 本课题不实现多返回值。

### 五、汇编发射与目标配置

#### 5.1 访存格式

`AsmEmitter` 将 `FLW/FSW/FLD/FSD` 与 `LW/SW` 一样按内存操作数格式化：

```asm
flw ft0, 0(t0)
fsw ft0, 4(sp)
fld ft0, 0(t0)
fsd ft0, 8(sp)
```

不允许通用三操作数路径输出 `fld ft0, t0`。`LOAD/STORE` 的地址操作数始终是 GPR，数据操作数由宽度和类型决定。

#### 5.2 目标 ISA

`CompilerConfig` 增加：

```python
use_extended_isel: bool = False
target_isa: str = "rv32im"
target_abi: str = "ilp32"
fp_rounding_mode: str = "rne"
```

原生 `f32` 要求 F 扩展，原生 `f64` 要求 D 扩展；D 扩展依赖 F。推荐的完整配置为 `rv32imfd + ilp32d`，只用 f32 时可以使用 `rv32imf + ilp32f`。目标 ISA/ABI 与 IR 类型不匹配时，在代码生成前返回明确错误，不静默降级为整数指令。

#### 5.3 编译器集成

```text
--extended-isel
    ↓
args.extended_isel
    ↓
CompilerConfig.use_extended_isel
    ↓
CompilerDriver._generate_riscv_linear()
    ↓
ExtendedInstructionSelector(program)
```

当 `backend=llvm` 时，`--extended-isel` 报错或显式忽略二者只能选一。本设计选择报错，避免用户误以为开关改变了 LLVM 后端。`--dag-isel` 和 `--extended-isel` 互斥。CLI 同时提供 `--target-isa`、`--target-abi` 和 `--fp-rounding-mode`，并在构造 `CompilerConfig` 时保留其值。

#### 5.4 机器码编码器

当前 `riscv_encoder.py` 主要编码 RV32IM。本课题的必交付以“生成可被 GNU/LLVM RISC-V 汇编器接受的 `.s`”为边界；直接编码 F/D 扩展二进制属于后续扩展。

如用户对含 F/D 指令的汇编调用内置编码器，必须得到“当前编码器不支持 F/D 扩展”的明确错误，不得跳过未知指令产生不完整二进制。

### 七、测试设计

#### 7.1 IR 和 DSL 测试

- `rem/mod/sqrt/min/max/abs` 能从 DSL 构造对应 IR。
- `const(1.5, dtype:f32/f64)` 分别产生 `DataType.FLOAT32/FLOAT64`。
- `f32 + f32 -> f32`、`f64 + f64 -> f64`，`i32 rem i32 -> i32`。
- `f32 + f64`、`f64 + i32`、`i32 sqrt`、未知 dtype 被验证器拒绝。
- ONNX `FLOAT/DOUBLE` 输入保持精度并到达与 DSL 相同的指令选择路径。
- 新操作不影响现有 DSL 诊断位置和错误数上限。

#### 7.2 指令选择单元测试

| 用例 | 必须断言 |
|---|---|
| `i32 div` | 产生 `DIV`，两个源均为 GPR vreg |
| `i32 rem` | 产生 `REM` |
| `i32 abs` | 序列和临时 vreg 唯一 |
| `i32 min/max` | 序列对正、负、相等值结果正确 |
| `f32/f64 add/sub/mul/div` | 分别产生 F/D 扩展指令，所有数据 vreg 为 FPR |
| `f32/f64 load/store` | 分别产生 `flw/fsw` 或 `fld/fsd`；地址为 GPR，数据为 FPR，store 顺序正确 |
| `f32/f64 compare` | 比较输入为 FPR，布尔结果为 GPR |
| `f32/f64 sqrt` | 默认产生 `fsqrt.s/fsqrt.d`，不产生错误的 `a0` 调用序列 |
| `f32/f64 const` | 保留完整 binary32/binary64 位模式，不出现 `li.s/li.d` |
| 多候选操作 | 只选择 ISA/ABI/类型条件满足的 pattern，同成本时结果确定 |

仅断言 `supported_ops` 包含名称不算功能测试。

#### 7.3 寄存器分配测试

- 整数指令只获得 GPR，F/D 算术指令只获得 FPR。
- `flt.s/flt.d` 的目标是 GPR，两个源是 FPR。
- 分别构造超过 12 个同时活跃 f32/f64 值，验证 `fsw/flw` 的 4 字节槽位和 `fsd/fld` 的 8 字节槽位。
- 同时施加 GPR/FPR 压力，两类池不互相污染。
- `naive/greedy/linear` 对同一 f32/f64 用例都不泄漏 vreg。

#### 7.4 汇编合法性测试

使用可用的 RISC-V GNU 汇编器或 Clang 交叉目标检查：

```bash
clang --target=riscv32 -march=rv32imfd -mabi=ilp32d \
  -c output.s -o output.o
```

CI 环境没有交叉工具时可标记为条件跳过，但必须同时有不依赖外部工具的文本结构测试，检查：

- 无虚拟寄存器泄漏。
- `div/rem` 不包含立即数源操作数。
- `fadd.s/fadd.d` 不使用 `t*/s*/a*`。
- `flw/fsw/fld/fsd` 使用 `offset(base)` 格式。
- 需要舍入的 FP 指令显式带 `rne`，不需要 rm 的指令不多出操作数。
- 输出中没有非标准 `li.s/li.d`。

#### 7.5 语义测试

整数用例由现有 RV32 仿真器或独立参考函数验证：

- 正数、负数、0、`INT32_MIN/MAX`。
- `div/rem` 除零和溢出边界。
- `min/max/abs` 的随机对比。

f32/f64 用例覆盖正常值、次正常值、±0、±Inf、NaN 以及中点舍入，并校验 `RNE`、`fmin/fmax` 的 NaN/有符号零语义。用例优先在支持 RV32F/D 的 QEMU 或 Spike 上运行；测试启动时先做能力探测并记录模拟器、版本、ISA 和 ABI。若 CI 不具备，将语义测试明确标为 skipped，但仍须完成汇编和 IEEE 754 常量位模式验证。不把当前仅支持 RV32IM 的内置编码器/仿真器误报为 FP 语义验证已通过。

#### 7.6 CLI 与回归测试

- `args_to_config()` 保存 `--extended-isel`。
- 开关关闭时仍使用基础选择器。
- 开关开启时对 f32/f64 DSL 生成 F/D 扩展汇编。
- `--target-isa/--target-abi/--fp-rounding-mode` 能到达选择器，不合法组合在生成前失败。
- `--dag-isel --extended-isel` 和 `--backend llvm --extended-isel` 给出可操作错误。
- 现有 backend、parser、IR verifier、regalloc 测试全部通过。

#### 7.7 性能与稳定性指标

性能验收使用固定输入的静态指标，不使用易受 CI 噪声影响的编译 wall-clock 时间：

- 记录指令选择后和寄存器分配后的指令数、FP 指令数、spill load/store 数及总 spill 字节。
- 扩展 `cycle_estimator.py` 对 `fmin/fmax/compare/sqrt` 的分类与延迟表，并在固定管线配置下输出预估 cycles/CPI。
- 开关关闭时，现有 RV32IM 基准的汇编文本和静态指标必须与基线一致。
- 开关开启但程序不含扩展操作时，分配后指令数和 spill 数不得退化。
- f32/f64 求和、点积、比较和 `sqrt/min/max` 微基准将上述数值写入 JSON；初版将其作为可复现基线，不设置未经硬件标定的绝对 cycles 门槛。

## 阶段 2：f32/f64 IR 与类型化指令选择

> 状态：已实施
> 前置阶段：阶段 1 的整数闭环、扩展数值类型合同和 CLI 路由
> 阶段边界：本阶段完成浮点 IR、目标特性、精确常量和类型化 MachineInstr；FPR 分配、浮点 spill 与 ABI 返回属于阶段 3

### 1. 目标

阶段 2 要让 `f32/f64` 从 DSL、ONNX 和 IRBuilder 进入统一的强类型 IR，并被确定地选择为正确的 RISC-V F/D 机器操作。

完成后必须满足：

1. `f32/f64` 算术、访存、比较、`sqrt/min/max/abs` 不会落入整数选择路径。
2. 浮点常量保留 IEEE 754 binary32/binary64 位模式，不经过 `int()` 截断。
3. 每个机器操作数携带 GPR/FPR 类别，比较结果明确写入 GPR。
4. 需要舍入模式的操作显式使用 `RNE`；`min/max/abs` 和比较不附加舍入参数。
5. 目标 ISA、ABI 或类型不匹配时，在代码生成前给出明确错误。
6. 阶段 3 完成前，含 FPR vreg 的程序在寄存器分配入口明确停止，不能输出使用 `t*` 等 GPR 的伪浮点汇编。

### 2. 当前基线与缺口

阶段 1 已经具备：

- `DataType.FLOAT32/FLOAT64`；
- `MIN/MAX/ABS` 的 `i32/f32/f64` IR 合同；
- `FMIN/FMAX/FABS` 的 `.s/.d` 机器操作；
- `--extended-isel` 到扩展选择器的路由；
- 整数 `DIV/REM/MIN/MAX/ABS` 闭环。

阶段 2 需要解决以下问题：

| 缺口 | 当前风险 | 阶段 2 结果 |
|---|---|---|
| `SQRT` 尚未进入统一 IR 合同 | DSL 名称可能存在，但 IR 无法可靠表示 | 增加 `OpCode.SQRT`、builder、DSL、verifier 和选择规则 |
| `f32 ADD/SUB/MUL/DIV/NEG` 可能落到基础整数选择器 | 生成类型错误的机器操作 | 显式选择 `.s` 操作，`f64` 选择 `.d` 操作 |
| 浮点常量通过 `int(raw_val)` 或非标准 `LI_D` | 精度和位模式丢失 | 使用按位模式去重的常量池 |
| MachineOperand 没有寄存器类别 | regalloc 会把浮点 vreg 分到 GPR | 增加 `RegisterClass` 和位置类别约束 |
| 目标 ISA/ABI/舍入配置未进入选择器 | 在不支持 F/D 时仍可能选择浮点指令 | 增加 `TargetFeatures` 并在候选选择前校验 |
| 浮点比较与分支没有统一降低 | FPR 输入和 GPR 布尔结果容易混淆 | 按比较谓词生成 `feq/flt/fle` 和整数分支 |
| 阶段 3 尚未实现 | 可能输出表面像汇编、实际寄存器非法的文本 | 在 regalloc 边界 fail closed |

### 3. 本阶段范围

#### 3.1 IR 和前端

- 增加 `OpCode.SQRT`，签名为 `(F) -> F`，`F ∈ {f32, f64}`。
- `MIN/MAX/ABS` 保持现有 `i32/f32/f64` 合同，`REM` 保持仅 `i32`。
- `ADD/SUB/MUL/DIV/NEG` 对相同类型的 `f32/f64` 正确传播结果类型。
- `IRBuilder.load()` 增加显式结果 dtype；`STORE` 保持 `[address, value]` 的 IR 顺序。
- DSL 支持 `sqrt(x)` 和 `const(..., dtype:f32/f64)`。
- ONNX 只映射本阶段有明确语义和选择规则的操作，不以默认 `f32` 掩盖未知类型。
- 不增加隐式数值转换；混合 dtype 必须在 builder 或 verifier 报错。

#### 3.2 目标特性与候选模式

新增 `scratchv/backend/inst_patterns.py`：

```python
@dataclass(frozen=True)
class TargetFeatures:
    isa: str = "rv32im"
    abi: str = "ilp32"
    rounding_mode: str = "rne"
    libm_available: bool = False
    optimize_for: str = "balanced"

@dataclass(frozen=True)
class SelectionPattern:
    name: str
    opcode: OpCode
    dtypes: tuple[DataType, ...]
    required_extensions: frozenset[str]
    estimated_cost: int
    priority: int
```

候选选择顺序固定为 `(estimated_cost, priority, name)`。类型或 ISA 不合法的候选先过滤，不能参与成本比较。

目标组合至少支持：

| 数据类型 | ISA | ABI |
|---|---|---|
| 仅整数 | `rv32im` | `ilp32` |
| `f32` | `rv32imf` | `ilp32f` |
| `f64` | `rv32imfd` | `ilp32d` |

`D` 依赖 `F`。不合法组合在创建选择器前失败。

#### 3.3 类型化机器表示

- 增加 `RegisterClass.GPR/FPR`。
- `MachineOperand.reg/vreg()` 记录 `reg_class`；旧整数调用缺省为 GPR。
- `MachineOpSemantics` 记录每个 defs/uses 位置要求的寄存器类别。
- `MachineInstr` 增加可选 `rounding_mode`，只允许 RISC-V 定义的舍入模式。
- 同一 vreg 被要求为两种寄存器类别时立即报错。

必须覆盖的类别规则：

| 操作 | dst | src1 | src2 |
|---|---|---|---|
| `FADD/FSUB/FMUL/FDIV` | FPR | FPR | FPR |
| `FMIN/FMAX` | FPR | FPR | FPR |
| `FABS/FNEG/FSQRT` | FPR | FPR | — |
| `FLW/FLD` | FPR | GPR 地址 | — |
| `FSW/FSD` | FPR 值 | GPR 地址 | — |
| `FEQ/FLT/FLE` | GPR | FPR | FPR |

#### 3.4 浮点常量池

- 使用 `struct.pack()` 或等价的无损方法取得 binary32/binary64 位模式。
- 常量池键为 `(dtype, bit_pattern)`，不能用 Python 浮点值本身作为唯一键。
- `+0.0` 与 `-0.0` 分开；NaN 按位模式保留；Inf 不经过十进制往返。
- `f32` 条目使用 4 字节对齐和 `.word`，通过 `flw` 加载。
- `f64` 条目使用 8 字节对齐和 `.quad`，通过 `fld` 加载。
- 删除最终汇编中的 `LI_D` 路径；RISC-V 没有标准 `li.s/li.d`。

#### 3.5 指令选择矩阵

| IR | `f32` | `f64` | 舍入 |
|---|---|---|---|
| `ADD` | `fadd.s` | `fadd.d` | `rne` |
| `SUB` | `fsub.s` | `fsub.d` | `rne` |
| `MUL` | `fmul.s` | `fmul.d` | `rne` |
| `DIV` | `fdiv.s` | `fdiv.d` | `rne` |
| `NEG` | `fneg.s` | `fneg.d` | 无 |
| `ABS` | `fabs.s` | `fabs.d` | 无 |
| `MIN/MAX` | `fmin.s/fmax.s` | `fmin.d/fmax.d` | 无 |
| `SQRT` | `fsqrt.s` | `fsqrt.d` | `rne` |
| `LOAD` | `flw` | `fld` | 无 |
| `STORE` | `fsw` | `fsd` | 无 |

`SQRT` 本阶段只实现硬件 F/D 路径。libm 回退不是 Topic 28 验收的必要条件；阶段 3 完成硬浮点 ABI 后，未配置 F/D 的目标仍应明确拒绝而不静默回退。

浮点比较沿用 `BR_IF` 的双操作数形式：

- `==` → `feq.s/d`
- `!=` → `feq.s/d` 后反转条件
- `<`/`>` → `flt.s/d`，必要时交换操作数
- `<=`/`>=` → `fle.s/d`，必要时交换操作数

比较结果写入 GPR，再使用整数分支操作。

#### 3.6 编译管线安全边界

阶段 2 不实现 FPR 分配。为避免产生错误汇编：

1. 选择器单元测试直接检查未分配的类型化 MachineInstr。
2. CompilerDriver 在 regalloc 前扫描 FPR vreg。
3. 若检测到 FPR vreg，返回明确错误：浮点选择已完成，但需要阶段 3 的 FPR 分配支持。
4. 不允许把 FPR vreg 临时映射到 GPR，也不允许静默退回整数指令。

该限制在阶段 3 完成后由真实的分类寄存器分配替换。

### 3. 核心设计

#### 3.1 寄存器池

```text
GPR: t0-t6, s0-s11
FPR: ft0-ft11
保留: zero/sp/ra/gp/tp, a0-a7, fa0-fa7, fs0-fs11
```

- 三种分配路径分别维护 GPR/FPR 映射、空闲池、活跃集和 spill 决策。
- `ft0-ft11` 是 caller-saved，有 `CALL` 时，所有穿越调用且仍活跃的 FPR 值必须在调用前 spill、调用后按需 reload。
- 本课题不把 `fs0-fs11` 加入可分配池，从而不需为可选优化扩大 FPR callee-saved 帧协议。
- 物理寄存器合法性由统一函数检查；不允许以名称前缀散落判断。

#### 3.2 分配器合同

naive、greedy 和 linear 最终返回同一种结果，至少包含：

```python
@dataclass(frozen=True)
class SpillSlot:
    offset: int
    size: int
    alignment: int
    reg_class: RegisterClass

@dataclass
class AllocationResult:
    instructions: list[MachineInstr]
    register_map: dict[str, str]
    spill_slots: dict[str, SpillSlot]
    spill_bytes: int
```

具体类名可根据仓库风格调整，但不再以单一 `spill_slot_count * 4` 代表混合栈帧。槽位分配按 `align_up(cursor, alignment)` 计算，且同一 vreg 始终复用同一槽位。

#### 3.3 spill/reload 规则

| 值 | 宽度 | 对齐 | spill | reload |
|---|---:|---:|---|---|
| `i32` / GPR | 4 | 4 | `sw` | `lw` |
| `f32` / FPR | 4 | 4 | `fsw` | `flw` |
| `f64` / FPR | 8 | 8 | `fsd` | `fld` |

- spill 的值操作数使用其本来的寄存器类，地址基寄存器始终是 GPR `sp`。
- 重写器不从指令拼写猜宽度，宽度来自 vreg 类型元数据。
- 超过 I-type 12 位偏移范围的栈帧继续明确失败；扩展大栈帧寻址序列不属于本课题。

#### 3.4 混合栈帧

`abi_frame.py` 接收完整 frame layout，而不是槽位数。栈帧布局顺序固定为：

1. `ra` 和已使用的 GPR callee-saved 保存区。
2. 按对齐排列的 GPR/f32/f64 spill 区。
3. 尾部 padding，使函数入口和调用点的 `sp` 保持 16 字节对齐。

栈帧终结器根据结构化槽位重写偏移，不再依赖“每个槽 4 字节”的全局假设。每个 return 出口都恢复保存寄存器和 `sp`。

#### 3.5 返回值与 ABI

| IR 返回类型 | ABI 寄存器 | 复制方式 |
|---|---|---|
| `i32` | `a0` | `mv` |
| `f32` | `fa0` | `fmv.s` |
| `f64` | `fa0` | `fmv.d` |

- 返回 lowering 必须查看 IR 结果 dtype，不得固定发射 `mv a0, ...`。
- `fa0` 不进入普通 FPR 分配池，由返回指令显式使用。
- `f32` 在 FLEN=64 的 D 目标上依照 psABI/ISA 的 NaN-boxing 规则处理，不用 GPR 复制替代。
- 本课题必须支持单值返回；多参数函数、多返回值和可变参数不在原始需求中。

#### 3.6 汇编发射

- `flw/fsw/fld/fsd` 使用 `value, offset(base)` 格式，base 必须是 GPR。
- `fadd/fsub/fmul/fdiv/fsqrt` 输出选定的静态舍入模式；`fmin/fmax/fabs/fneg/feq/flt/fle/fmv` 不带 rm。
- 常量池在 `.rodata` 中按 4/8 字节对齐，标签是编译单元局部的，正文以 `la + flw/fld` 访问。
- 函数 `.size` 必须引用对应的函数名，多函数输出不能拿下一个标签当上一个函数名。
- 发射后扫描不得出现 `%vreg`、非标准 `li.s/li.d`、FPR 位置上的 `t*/s*/a*` 或 GPR 位置上的 `ft*/fa*`。

#### 3.7 工具链和内置后端边界

- 可交付的 F/D 边界是生成能被 GNU assembler 或 Clang `--target=riscv32` 接受的 `.s`。
- `riscv_encoder.py` 和内置 RV32 模拟器未实现 F/D 编码/执行时，对每个 F/D 操作给出包含所需扩展名的明确错误。
- 浮点语义测试优先使用 Spike 或 QEMU；使用前记录工具、版本、ISA 和 ABI，不可用“环境没有”代替结构和汇编合法性测试。
- libm `sqrtf/sqrt` 回退不是课题验收的必要条件；RV32IMF/D 使用 `fsqrt.s/d` 已满足需求。未实现的软浮点目标必须拒绝，不列为 Topic 28 遗留项。

### 6. 测试矩阵

#### 6.1 分配和 spill

| 用例 | naive | greedy | linear |
|---|---:|---:|---:|
| 纯 GPR 回归 | 必测 | 必测 | 必测 |
| 纯 f32，无 spill | 必测 | 必测 | 必测 |
| 纯 f64，无 spill | 必测 | 必测 | 必测 |
| 混合 GPR/FPR | 必测 | 必测 | 必测 |
| 超过 12 个活跃 f32 | 必测 | 必测 | 必测 |
| 超过 12 个活跃 f64 | 必测 | 必测 | 必测 |
| FPR 值穿越 CALL | 必测 | 必测 | 必测 |

每个用例同时断言：无 vreg，类别正确，槽位大小/对齐正确，没有两个同时活跃值覆盖同一槽位。

#### 6.2 汇编结构

- f32/f64 算术、`sqrt/min/max/abs`、load/store 和六种比较谓词。
- `fa0` 返回和 `a0` 整数返回。
- 带和不带 rm 的指令各自严格匹配参数数量。
- `.rodata` 常量的 ±0、次正常值、±Inf 和不同 NaN 位模式。
- 多函数、多 return、无 spill 和有 spill 栈帧。
- 输出扫描：无 vreg、无 `li.s/li.d`、无寄存器类别泄漏。

#### 6.3 端到端程序

| 程序 | 类型 | 覆盖点 |
|---|---|---|
| 有符号除法与余数 | i32 | `div/rem`、负数、返回 `a0` |
| 求和 | f32 | 常量池、`fadd.s`、RNE、`fa0` |
| 点积 | f64 | `fmul.d/fadd.d`、load/store、spill |
| 数值工具组合 | f32/f64 | `sqrt/min/max/abs`、比较和分支 |
| ONNX 小图 | f32/f64 | ONNX dtype 保留到最终汇编 |

每个程序至少运行一次主 CLI 路径；直接调用 selector 的单元测试不替代端到端验收。

#### 6.4 负例

- `f32` + `ilp32` 或不含 F 的 ISA。
- `f64` + `ilp32f` 或不含 D 的 ISA。
- D 存在但 F 缺失的非法 ISA。
- 混合 dtype、同一 vreg 的 GPR/FPR 冲突和 FPR 宽度缺失。
- 非法舍入模式和不需 rm 的指令携带 rm。
- 栈偏移越界、未分配 vreg 泄漏、内置编码器接收 F/D 指令。
