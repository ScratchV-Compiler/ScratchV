# 课题12：RISC-V 后端指令计数统计器设计文档

> 文档类型：详细设计
> 适用范围：`scratchv/backend/inst_counter.py`、`scratchv/compiler.py`、`scratchv/main.py` 及 benchmark/CI 接入
> 设计基线：仓库当前实现（2026-09-24）
> 相关文档：[Topic 12 课题说明](12-指令计数统计器.md) | [Topic 12 开发文档](12-指令计数统计器-开发文档.md)

---

## 1. 文档目标

本文档定义 RISC-V 汇编静态指令统计的测量口径、解析策略、分类模型、数据结构、比较语义、报告输出、编译器/CI 集成和验收标准。

设计重点是让“指令数”成为可解释、可比较、可编程使用的指标，而不是仅从文本中数出若干行。

## 2. 问题定义

编译器生成的汇编可用静态指令数快速回答以下问题：

- 某次优化是否减少了汇编指令；
- ALU、访存、分支和跳转的构成比例如何；
- ScratchV 与 LLVM 的同源输入在指令构成上有什么差异；
- 某个新指令或伪指令是否被正确识别；
- CI 中的静态代码规模是否发生明显回退。

它不能单独回答动态执行次数、实际周期、Cache miss、分支误判或能耗。静态指令数是代码形态指标，不是性能的充分条件。

## 3. 测量口径

### 3.1 默认口径

默认模式统计输入汇编文本中的每个指令 mnemonic：

- 空行、纯注释、纯标签和汇编器伪操作不计数；
- `label: add a0, a1, a2` 中的 `add` 计 1 条；
- 伪指令默认以文本中的 1 条 PSEUDO 计数，不猜测汇编器展开长度；
- 未知 mnemonic 计入 MISC，同时保留具体 mnemonic 计数；
- 总数是全部实际分类的指令之和，不包含元数据。

### 3.2 口径标识

每份结构化结果必须携带：

```text
schema_version: 数据结构版本
classification_version: 分类表版本
count_mode: textual | expanded
isa: rv32im | rv32imf | rv64gc | unknown
```

当前必须实现 `textual`。`expanded` 伪指令展开模式属于可选扩展，启用时必须明确标识，不能与 textual 结果静默比较。

### 3.3 静态与动态数据的边界

| 指标 | Topic 12 | 其他工具 |
|---|---|---|
| 汇编文本 mnemonic 数 | 支持 | — |
| 机器码静态指令数 | 非默认，可扩展 | objdump/二进制解码器 |
| 运行时已提交指令 | 不支持 | Spike/TinyFive/内置仿真 |
| 周期和停顿 | 不支持 | cycle estimator |
| Cache 行为 | 不支持 | Topic 23 |

## 4. 当前实现审计

### 4.1 已实现能力

`scratchv/backend/inst_counter.py` 已包含：

- ALU、MEM、BRANCH、JUMP、PSEUDO、MISC 六类映射；
- 汇编文本/文件计数 API；
- 按 mnemonic 的 `Counter` 详细计数；
- 纯文本表格；
- 单文件条形图+饼图和多文件分组条形图；
- 单文件 HTML 报告；
- 多文件计数和相对首文件的差值；
- 独立 CLI；
- `CompilerDriver` 的 `--count-instr` 总数摘要集成；
- `tests/test_inst_counter.py` 的解析、分类、统计、比较和 HTML 基础测试。

### 4.2 已知缺口

| 编号 | 当前行为 | 影响 | 目标行为 |
|---|---|---|---|
| C-01 | `label: instruction` 整行被跳过 | 低估静态指令数 | 先移除标签，再解析 opcode |
| C-02 | 只识别 `#` 注释 | 对其他汇编风格不稳定 | 明确支持的注释方言，默认 RISC-V GNU `#` |
| C-03 | `_INST_RE` 定义但未使用 | 解析逻辑分裂 | 删除死代码或归一到共享 asm parser |
| C-04 | 分类表缺少 FP 计算、atomic、CSR/system、compressed | MISC 比例难解释 | 扩展分类并报告 unknown 列表 |
| C-05 | `dict[str, int]` 中塞入 `_detailed: Counter` | 类型不真实、序列化麻烦 | 使用结构化 `InstructionStats` |
| C-06 | 零计数也至少显示一个 `#` | 文本图误导 | 零值空 bar |
| C-07 | 空输入生成图表可失败 | CLI 不稳定 | 生成明确“No instructions”图或返回可操作错误 |
| C-08 | 两个同 basename 文件会覆盖 | 比较数据丢失 | 使用唯一 label，冲突时包含相对路径/序号 |
| C-09 | `--compare` 提前 return | 无法同时产生 chart/HTML | 分离计算与渲染，一次运行多产物 |
| C-10 | 多文件 `--html` 只报告第一个 | 与用户预期不符 | 使用专用多文件 HTML 报告 |
| C-11 | `--verbose` 未使用 | CLI 契约虚假 | 默认摘要，`--verbose` 才显示 mnemonic 明细 |
| C-12 | 缺少 JSON/Markdown | 难接 CI 和版本对比 | 提供稳定序列化格式 |
| C-13 | matplotlib/pandas 未在可选依赖中声明 | 安装指南不完整 | 声明 report 可选依赖或去除必需性 |
| C-14 | driver 只把 total 写入 warnings | 结构化数据丢失，警告语义不合 | 写入 `CompileResult.stats` |

## 5. 设计目标与非目标

### 5.1 设计目标

1. 对 ScratchV 和常见 GNU RISC-V 汇编文本进行确定性静态计数。
2. 数据模型显式区分类统计、mnemonic 统计、总数、未知指令和元数据。
3. 未知指令不丢失，且可以在 CI 中被显式发现。
4. 文本、JSON、Markdown、HTML 和图表都从同一统计模型渲染。
5. 单文件和多文件比较共享一套口径和类别顺序。
6. 比较结果同时提供绝对差值和相对变化，对零基线有明确规则。
7. 主编译器将统计放入 `CompileResult.stats`，不冒充为 warning。
8. 默认功能零第三方可视化依赖，图片/DataFrame 能力可选。

### 5.2 非目标

- 不在本模块模拟程序执行或推导循环迭代次数；
- 不把静态指令数直接换算为周期/时间；
- 不实现完整 RISC-V assembler 或 linker；
- 不在无 ISA/ABI 上下文时自动猜测所有伪指令的机器码展开；
- 不用指令数作为唯一性能回归门禁。

## 6. 总体架构

```text
assembly text/files
       |
       v
line normalization
  - remove comments
  - split optional label
  - reject directives/empty lines
       |
       v
opcode extraction ----> parse diagnostics (optional)
       |
       v
classification registry
       |
       v
InstructionStats
  - category_counts
  - opcode_counts
  - unknown_opcodes
  - metadata
       |
       +--> text / Markdown
       +--> JSON
       +--> HTML
       +--> chart (optional matplotlib)
       +--> ComparisonResult
       +--> CompileResult.stats / benchmark / CI
```

### 6.1 模块分层

| 层 | 输入 | 输出 | 错误策略 |
|---|---|---|---|
| Parser | 单行汇编 | `opcode | None` | 跳过非指令，可选收集可疑行 |
| Classifier | mnemonic | category + ISA metadata | unknown -> MISC，不抛错 |
| Aggregator | opcode 序列 | `InstructionStats` | 始终返回全类别 |
| Comparator | 2..N 个 stats | `ComparisonResult` | 标签必须唯一 |
| Renderer | stats/comparison | text/JSON/MD/HTML/image | 输出失败不篡改统计数据 |
| Integration | stats | compiler/benchmark result | 结构化传递，不解析文本表格 |

## 7. 数据模型

### 7.1 `InstructionStats`

```python
from collections.abc import Mapping

@dataclass(frozen=True)
class InstructionStats:
    category_counts: Mapping[str, int]
    opcode_counts: Mapping[str, int]
    unknown_opcodes: Mapping[str, int]
    total: int
    source: str | None = None
    count_mode: str = "textual"
    isa: str = "unknown"
    schema_version: int = 1
    classification_version: str = "1"
```

不变式：

```text
total == sum(category_counts.values())
total == sum(opcode_counts.values())
unknown_opcodes 是 opcode_counts 中分类为 MISC 的子集
category_counts 始终包含所有标准类别，即使值为 0
所有计数 >= 0
```

`frozen=True` 只能防止字段被重新赋值，不能冻结内部 `dict`。构造函数必须对三组计数做防御性拷贝，在验证不变式后用 `MappingProxyType` 或等价的不可变映射存储。公共属性不得暴露可变引用，否则 renderer 和 CI 可在构造后观察到不一致的 `total`。

`source` 保存调用方传入的原始路径字符串，不自动转换为绝对路径、不做 `resolve()`；用于显示的唯一 `label` 由比较层单独管理。

为保持兼容，现有 `count_instructions()` 可在迁移期继续返回 legacy dict，但新的 `analyze_instructions()` 应返回 `InstructionStats`。完成调用方迁移后，再于主版本边界移除混合字典。

### 7.2 分类数据

类别建议从当前 6 类扩展为不重叠的主类别：

| 类别 | 定义 | 示例 |
|---|---|---|
| ALU | 整数算术、逻辑、移位、比较、上位立即数 | `add`, `mul`, `srai`, `lui` |
| FP | 浮点计算、比较、转换、移动 | `fadd.s`, `fsqrt.d`, `fcvt.w.s` |
| MEM | 整数/浮点载入与存储 | `lw`, `sd`, `flw`, `fsd` |
| BRANCH | 条件分支 | `beq`, `bltu`, `bnez` |
| JUMP | 跳转、调用和返回的实指令/控制伪指令 | `jal`, `jalr`, `j`, `ret` |
| ATOMIC | A 扩展原子操作 | `amoadd.w`, `lr.w`, `sc.w` |
| SYSTEM | fence、CSR、环境调用等 | `fence`, `csrrw`, `ecall` |
| PSEUDO | 非控制类汇编器伪指令 | `li`, `mv`, `nop` |
| MISC | 已解析但尚未分类 | 自定义扩展 |

兼容取舍：当前 `j/ret/call/tail` 可分布在 JUMP/PSEUDO。为了保持“控制流开销”可解释，目标设计将调用/返回/跳转伪指令按语义归入 JUMP，并用 `is_pseudo` 次级属性标记。这会改变历史分类数据，因此必须升级 `classification_version`，不得静默改表。

### 7.3 指令描述表

长期建议使用元数据对象替代纯 `opcode -> category` 字典：

```python
@dataclass(frozen=True)
class OpcodeInfo:
    category: str
    extension: str
    is_pseudo: bool = False
```

这使报告可同时按主类别和 ISA 扩展汇总，也为伪指令展开留出位置。

### 7.4 `ComparisonResult`

```python
@dataclass(frozen=True)
class CategoryDelta:
    baseline: int
    current: int
    absolute: int
    percent: float | None

@dataclass(frozen=True)
class ComparisonResult:
    baseline_label: str
    stats: Mapping[str, InstructionStats]
    category_deltas: Mapping[str, Mapping[str, CategoryDelta]]
    opcode_deltas: Mapping[str, Mapping[str, int]]
```

`stats` 包含所有输入（包括 baseline），键为唯一 label，且 `baseline_label` 必须是其中一个键。`category_deltas` 和 `opcode_deltas` 也包含所有 label；baseline 的绝对差值和百分比固定为 `0`，使 renderer 不需要猜测缺失行是否代表 baseline。三组映射使用相同的输入顺序。

`category_deltas[label]` 始终包含全部标准 category；`opcode_deltas[label]` 包含所有输入 `opcode_counts` 的并集，某文件中未出现的 opcode 按 0 计算。

与 `InstructionStats` 相同，`ComparisonResult` 构造时必须对三组外层和内层映射做防御性拷贝并递归暴露为只读映射；`frozen=True` 本身不能保证嵌套映射不变。

相对差值规则：

```text
absolute = current - baseline
percent = absolute / baseline * 100, when baseline > 0
percent = 0.0, when baseline == 0 and current == 0
percent = None, when baseline == 0 and current > 0
```

`None` 在文本中显示为 `N/A`，JSON 中为 `null`，避免用无穷大误导用户。

`percent` 内部按 Python `float` 计算；序列化前使用 `round(value, 4)` 保留最多 4 位小数，人类可读报告显示 1 位小数。CI 比较优先使用 `baseline/current/absolute` 整数字段，不以浮点文本作为唯一依据。

## 8. 汇编解析设计

### 8.1 处理步骤

```text
raw line
  -> parse with backend._asm_parser.parse_line()
     - split supported comment suffix
     - consume whitespace and one optional leading label
     - extract/lowercase opcode
  -> if opcode is None: skip or record suspicious non-empty line
  -> if ParsedAsmLine.is_directive: skip
  -> validate canonical opcode
```

`scratchv/backend/_asm_parser.py` 是 directive 和 label 的权威语法实现：

- `.L1:`、`1:` 和 `name$part:` 由 `label` 字段识别，不视为 directive；
- `.text`、`.word`、`.option` 以及其他点号开头的 opcode 由 `is_directive=True` 识别，textual 模式全部跳过；
- `label: instruction` 保留标签后的 opcode；
- v1 每行支持最多一个前置 label；多个 label 同行记为可疑行，不静默猜测。

若 Topic 12 需要扩展语法，必须先在共享 parser 和其测试中实现，不在计数器内维护第二份 directive 列表或正则。

示例：

| 输入 | 结果 |
|---|---|
| `  add a0, a1, a2 # sum` | `add` |
| `loop:` | `None` |
| `loop: addi t0, t0, -1` | `addi` |
| `.L1: bnez t0, .L1` | `bnez` |
| `.text` | `None` |
| `.word 0x13` | `None` |
| `# add a0, a1, a2` | `None` |

### 8.2 标签和指令

不能通过“第一个 token 以 `:` 结尾就返回 None”处理，因为 GNU assembler 允许标签和指令同行。解析器必须消费标签后继续解析剩余文本。

仓库已有 `scratchv/backend/_asm_parser.py`。开发时应先评估复用其 `parse_line()`，避免指令计数器、美化器、调度器分别维护不同汇编语法。如果现有共享 parser 无法覆盖该口径，先增加共享 parser 测试，再扩展它。

### 8.3 指令合法形式

mnemonic 需支持字母、数字、下划线和点，以覆盖 `fadd.s`、`amoadd.w.aq`、`c.addi`等形式。指令大小写归一为小写。

### 8.4 ISA 来源

`isa` 只来自 API 参数或 CLI `--isa`，默认为 `unknown`。v1 不从 `.option`、文件名或已出现指令反向推断 ISA；这些信息可作为未来诊断，不得静默改写元数据。分类器始终使用完整注册表，`isa` 仅用于报告和可比性检查；发现与声明 ISA 不符的指令时可产生诊断，但不丢失计数。

### 8.5 指令边界与数据伪操作

`.word` 等数据伪操作即使可能编码为机器指令，在 textual 模式下也不计数。若要统计内联机器字，需新的 binary/objdump 分析模式。

## 9. 分类设计

### 9.1 匹配顺序

1. 对 canonical opcode 做精确映射；
2. 对带 `.aq/.rl/.aqrl` 的 atomic 指令去除序属性后匹配；
3. 对可规则化的扩展指令使用受控模式，不使用过宽的 `startswith()`；
4. 不命中时进入 MISC/unknown。

### 9.2 未知指令策略

未知指令不应导致默认统计失败，因为 ScratchV 可扩展新指令。但报告必须显示 unknown 总数和具体 mnemonic。CLI 增加严格模式：

```text
--fail-on-unknown
```

当 unknown > 0 时返回非零退出码，供分类表维护和 CI 使用。严格模式不改变报告内容，仍应生成诊断所需的结果。

### 9.3 伪指令策略

默认 textual 模式将伪指令按源汇编一条计数。可选 expanded 模式必须知道 ISA/XLEN/符号重定位上下文；无法确定展开时标记 unresolved，不得假定所有 `li` 都是一条真指令。

## 10. 统计算法

### 10.1 单次扫描

对 N 行汇编和 U 个不同 mnemonic：

- 时间复杂度：`O(N)`；
- 额外空间：`O(U + C)`，C 为固定类别数；
- 逐行解析，不必为统计复制完整文本；
- 文件 API 用 UTF-8 打开，换行符由 Python 通用换行处理。

### 10.2 确定性

- category 显示顺序来自单一常量；
- opcode 明细按 `(-count, opcode)` 排序，同计数时字典序稳定；
- JSON 使用固定 schema，不依赖 `Counter` 的 repr；
- 输入顺序只影响 label 显示顺序，不影响单文件统计结果。

## 11. 比较设计

### 11.1 基线

默认将第一个文件视为 baseline，同时提供 `--baseline LABEL|PATH` 显式指定。所有其他文件的 delta 相对该 baseline 计算。

### 11.2 唯一标签

默认使用 basename；当 basename 冲突时，使用最短唯一路径后缀。CLI 也允许为每个位置输入按顺序重复指定 label：

```text
tool /path/to/a/output.s /path/to/b/output.s --label before --label after
```

结构化数据中同时保存 label 和 source path，不以 basename 作唯一键。

### 11.3 结论边界

报告可陈述“静态指令总数下降 8.2%”，不得直接陈述“性能提升 8.2%”。任何性能结论都需与动态指令、周期或真实运行时间数据结合。

## 12. 报告设计

### 12.1 纯文本

默认只显示类别、计数、比例和总数；`--verbose` 附加 mnemonic 明细和 unknown 列表。零计数的 bar 为空。

### 12.2 JSON

```json
{
  "schema_version": 1,
  "kind": "single",
  "classification_version": "1",
  "source": "output.s",
  "count_mode": "textual",
  "isa": "rv32im",
  "total": 10,
  "category_counts": {
    "ALU": 3,
    "FP": 0,
    "MEM": 2,
    "BRANCH": 1,
    "JUMP": 2,
    "ATOMIC": 0,
    "SYSTEM": 0,
    "PSEUDO": 2,
    "MISC": 0
  },
  "opcode_counts": {
    "add": 1,
    "addi": 1,
    "sub": 1,
    "lw": 1,
    "sw": 1,
    "beq": 1,
    "j": 1,
    "ret": 1,
    "li": 1,
    "mv": 1
  },
  "unknown_opcodes": {}
}
```

单文件 JSON 必须包含全部标准 category。多文件比较使用独立 `kind="comparison"` schema，并且仅在所有输入的 schema version、classification version、count mode 和 ISA 兼容时生成：

```json
{
  "schema_version": 1,
  "kind": "comparison",
  "classification_version": "1",
  "count_mode": "textual",
  "isa": "rv32im",
  "baseline": "before",
  "files": [
    {
      "label": "before",
      "stats": {
        "source": "before.s",
        "total": 2,
        "category_counts": {
          "ALU": 1, "FP": 0, "MEM": 0, "BRANCH": 0,
          "JUMP": 1, "ATOMIC": 0, "SYSTEM": 0,
          "PSEUDO": 0, "MISC": 0
        },
        "opcode_counts": {"add": 1, "ret": 1},
        "unknown_opcodes": {}
      },
      "delta": {
        "total": {"baseline": 2, "current": 2, "absolute": 0, "percent": 0.0},
        "category_counts": {
          "ALU": {"baseline": 1, "current": 1, "absolute": 0, "percent": 0.0},
          "FP": {"baseline": 0, "current": 0, "absolute": 0, "percent": 0.0},
          "MEM": {"baseline": 0, "current": 0, "absolute": 0, "percent": 0.0},
          "BRANCH": {"baseline": 0, "current": 0, "absolute": 0, "percent": 0.0},
          "JUMP": {"baseline": 1, "current": 1, "absolute": 0, "percent": 0.0},
```

### 12.3 Markdown

面向 PR/CI 摘要，包含简短总表、相对 baseline 差值和 unknown 警告。详细 mnemonic 可收起或只显示 Top N，避免过大的 CI 输出。

### 12.4 HTML

使用内嵌 CSS，不依赖 CDN；对 title、label、path、opcode 等用户可控字段做 HTML escaping。多文件报告必须展示每个文件和 delta，不能只取第一个文件。

### 12.5 图表

- 单文件：类别条形图；饼图只在 total > 0 时绘制；
- 多文件：分组条形图，文件过多时转为水平图或禁止继续堆叠；
- 空数据：显示 `No instructions found`，不调用空 pie；
- 图表为可选功能，缺 matplotlib 时返回可操作错误，不影响文本/JSON/HTML；
- 数据标签和图例使用稳定顺序。

## 13. CLI 设计

```text
python -m scratchv.backend.inst_counter FILE [FILE ...]
    [--compare]
    [--baseline LABEL|PATH]
    [--label LABEL]...
    [--verbose]
    [--json-output PATH]
    [--markdown PATH]
    [--html PATH]
    [--chart PATH]
    [--isa ISA]
    [--fail-on-unknown]
```

### 13.1 输出规则

- stdout：默认文本报告；
- stderr：输入/输出错误和“报告已写入”状态；
- 指定 JSON/Markdown/HTML/chart 时可同时生成；
- `--compare` 不得提前 return 跳过其他 renderer；
- 缺文件、无权限、输出写入失败返回非零；
- `--fail-on-unknown` 在报告生成后返回退出码 2。

### 13.2 参数组合契约

| 输入/参数 | 行为 |
|---|---|
| 1 个文件，无 `--compare` | 生成单文件报告，所有 renderer 可用 |
| 1 个文件 + `--compare` | 参数错误，退出码 1 |
| 2..N 个文件，无 `--compare` | stdout 按输入顺序输出各自摘要；如同时请求 JSON/Markdown/HTML/chart，拒绝并提示加 `--compare` |
| 2..N 个文件 + `--compare` | 构造唯一 `ComparisonResult`，stdout 和全部 renderer 共用同一 baseline |
| `--baseline` 无 `--compare` | 参数错误，退出码 1 |
| `--baseline` 无法唯一匹配输入 | 参数错误，列出可用 label，退出码 1 |

`--label LABEL` 为可重复参数，按出现顺序与位置输入一一对应；不提供时使用最短唯一路径后缀。`--label` 数量必须为 0 或与文件数相等，label 不得重复。

`--baseline` 先对 label 做精确匹配，未命中时再对调用方传入的原始路径字符串做精确匹配；不做 basename 模糊匹配。未指定时使用第一个输入。一次 CLI 运行只构造一个 `ComparisonResult`，因此 text/JSON/Markdown/HTML/chart 必须共用相同 baseline。

### 13.3 退出码

| 码 | 含义 |
|---|---|
| 0 | 统计和所有请求的报告成功 |
| 1 | 输入或输出 I/O/参数错误 |
| 2 | strict unknown 检查失败 |
| 3 | 可选报告依赖缺失或渲染失败 |

如项目已有统一 CLI 退出码约定，实现时应以全局约定为准，但必须保留“输入错误”与“严格分类失败”的可区分性。

## 14. 编译器集成

### 14.1 执行位置

统计应在所有启用的汇编后处理完成之后运行，因为这份汇编才是最终写入文件的产物。当需比较 pass 前后时，由专门 benchmark 在两个明确节点各自捕获 stats，不改变默认 `--count-instr` 口径。

### 14.2 `CompileResult.stats`

建议结构：

```python
result.stats["instruction_count"] = stats.to_dict()
```

CLI 的 `--count-instr` 可从该结构数据渲染简表。“Instruction count: N”不再放入 `warnings`，因为正常统计不是警告。

### 14.3 后端限制

`--count-instr` 只适用于 RISC-V 汇编输出。当 backend 为 LLVM IR 时，CLI 必须在编译前拒绝该参数组合并返回退出码 1；不可静默跳过，也不可把 LLVM IR 当 RISC-V 汇编统计。

## 15. Benchmark 与 CI 集成

### 15.1 保存内容

每个 case 至少保存：

- compiler/config/commit 标识；
- source label 和 ISA；
- total/category/opcode/unknown counts；
- classification version；
- baseline delta；
- 执行是否成功和错误原因。

### 15.2 回归阈值

指令数不应对所有 case 使用一个绝对阈值。建议：

- 单元/fixture：精确计数；
- 稳定小程序：在 case 配置中显式给出 `max_total_increase` 或 `max_total_increase_pct`；
- 大模型：在 case 配置中给出相对 baseline 阈值，并结合正确性和动态指标；
- unknown count：主干 CI 中默认要求 0，新 ISA 扩展合入时同步更新分类表和版本。

项目不提供一个伪精确的全局默认百分比：除 unknown 外，case 没有配置阈值时只生成报告而不使 CI 失败。阈值配置、baseline commit 和更新理由必须一起评审。

### 15.3 基线可比性

只有 schema version、classification version、count mode 和 ISA 兼容时才自动计算回归。v1 的 ISA 兼容规则是字符串完全相等：两者都为 `unknown` 可比，一个 `unknown` 与一个显式 ISA 不可比，不自动推导 `rv32im` 是否为另一 ISA 的子集。口径不同时报告 `not comparable`，不产生看似精确的百分比。

## 16. 错误处理

| 错误 | API | CLI |
|---|---|---|
| 输入文件不存在 | `FileNotFoundError` | stderr + 非零 |
| 输入无权限/解码失败 | 原因明确的异常 | stderr + 非零 |
| 空汇编 | 返回 total=0 stats | 成功，报告空数据 |
| 未知 opcode | 计入 MISC/unknown | 默认成功，strict 模式非零 |
| 图表依赖缺失 | `ImportError` 或领域错误 | 只有请求 chart 时失败 |
| 报告路径无法写入 | I/O 异常 | stderr + 非零，不声称已保存 |
| 同名 label | 自动唯一化或拒绝 | 不覆盖前一份统计 |

## 17. 安全性

- HTML 中所有用户可控文本必须 escape；
- 图表标题只作为文本，不执行 TeX/脚本；
- 不从汇编文本解析并执行 `.include`、`.incbin` 或宏；
- 文件路径仅用于读写显式目标，不通过 shell 拼接；
- 对非受信的超大汇编可增加文件大小/行数限制，默认不将全文嵌入报告；
- JSON 和 HTML 报告不包含汇编原文，除非用户明确要求且经过转义。

## 18. 性能要求

- 计数器对输入做单次线性扫描；
- 对百万行文件不建立每行 AST 列表，允许流式统计；
- 文本/JSON/HTML 渲染不重新解析汇编；
- 多文件统计可逐个处理，结果仅保留 `O(files * (U+C))` 聚合数据；
- 图表生成与核心计数分离，不影响无图模式启动时间。

## 19. 测试设计

### 19.1 解析器单测

- 空行、空白、CRLF；
- 纯注释、行尾注释；
- 纯标签、本地标签、数字标签、标签+指令；
- 一般伪操作、未知伪操作、数据伪操作；
- 带点 mnemonic、大写 mnemonic、atomic 序属性；
- 不完整/奇怪文本不得被当成 Python 代码或 shell 执行。

### 19.2 分类单测

每个支持的 ISA 扩展至少有正例；每个 category 至少有两个典型指令；未知 opcode 必须进入 MISC 并保留原 mnemonic。分类表变更必须附带版本决策。

### 19.3 不变式测试

对所有 fixture 验证：

```python
assert stats.total == sum(stats.category_counts.values())
assert stats.total == sum(stats.opcode_counts.values())
assert set(stats.unknown_opcodes) <= set(stats.opcode_counts)
```

### 19.4 报告测试

- 零数据、单类别、全类别；
- HTML 转义 title/path/opcode；
- JSON schema 字段和排序；
- Markdown 表格在 label 含 `|` 时正确转义；
- 多文件 HTML 含全部文件；
- chart 在空数据下不崩溃；
- 无 matplotlib 环境仅 chart 测试按预期失败/跳过。

### 19.5 CLI 测试

- 单文件默认输出；
- 多文件 compare + JSON + HTML + chart 同时生成；
- 多文件不带 compare 时只允许逐文件文本摘要；
- `--label` 数量/重复值与 `--baseline` 匹配失败的退出码；
- `--verbose` 是否真正控制明细；
- 缺文件、不可写路径、同 basename；
- `--fail-on-unknown` 退出码；
- 终端状态信息不混入 JSON 文件。

### 19.6 集成测试

- RISC-V backend + `--count-instr` 的 stats 不为空；
- LLVM backend + `--count-instr` 在编译前拒绝并返回退出码 1；
- 统计 total 等于对最终输出文件单独运行 Topic 12 的结果；
- 开启 peephole/const-merge/schedule/beautify 时统计口径仍是最终产物。

## 20. 兼容性与迁移

### 20.1 现有公共 API 兼容矩阵

| 现有接口 | 迁移期行为 | 新接口/模型 |
|---|---|---|
| `count_instructions(text)` | 保留签名和 legacy dict 返回值，内部通过集中 adapter 转换 | `analyze_instructions(text)` |
| `count_instructions_file(path)` | 保留签名、I/O 异常类型和 legacy dict | `analyze_file(path)` |
| `format_table(counts)` | 保留；对 legacy dict 转换后调用 `render_text(..., verbose=True)`，保持旧版默认显示明细 | `render_text(stats, verbose=False)` |
| `generate_chart(counts, path, title)` | 保留签名并适配 legacy dict | 接受 `InstructionStats` 的新 chart renderer |
| `generate_multi_chart(multi_counts, path, title)` | 保留签名并适配 legacy dict 映射 | 接受 `ComparisonResult` 的新 chart renderer |
| `generate_html_report(counts, path, title)` | 保留签名并适配 legacy dict | `render_html(stats_or_comparison)` + 写文件 helper |
| `compare_files(paths)` | 保留名称，返回新 `ComparisonResult`；迁移期提供旧属性 | `compare_stats()` / 新 `ComparisonResult` |
| `ComparisonResult.files/counts/diffs` | 保留为只读兼容属性：`files` 是 label 顺序列表，`counts` 是含 `_detailed` 的 legacy dict 映射，`diffs` 仅含非 baseline 的标准 category 绝对差 | `baseline_label/stats/category_deltas/opcode_deltas` |
| `ComparisonResult.to_dataframe()` | 保留当前 `File/ALU/MEM/BRANCH/JUMP/PSEUDO/MISC` 列顺序，pandas 仍为 lazy optional dependency；扩展列另增新接口 | 新模型上的兼容方法 |
| `print_comparison(result)` | 保留，向 stdout 写入新文本 renderer 结果 | `render_text(comparison)` |
| `scratchv.backend.count_instructions` | 继续从 `scratchv/backend/__init__.py` 导出 | 同时可新增 `analyze_instructions` |

兼容属性和 legacy 包装至少保留到下一个 major 版本；在移除前先发出 `DeprecationWarning`、更新调用方和发布说明。不允许在同一个 minor 版本中新增后立即移除适配层。兼容面的回归以当前 `tests/test_inst_counter.py` 的输入/输出为黄金样本，不只验证符号仍可 import。

### 20.2 数据版本迁移

1. 先增加 `InstructionStats` 和新 API，现有公共符号按上表继续运行；
2. 让 renderer、CLI、CompilerDriver 和 benchmark 逐步迁移到新模型；
3. 为 legacy dict 提供集中 adapter，不在每个调用点复制 `_detailed` 特判；
4. 分类口径改变时升级字符串 `classification_version`，新分析只使用当前分类表，不提供按旧版本重算；
5. 历史 JSON 保留其原分类版本，版本不同时标记 `not comparable`，不双写两套新统计；
6. JSON schema 不兼容变更时升级整数 `schema_version`；读取器遇到未支持的 major schema 必须明确拒绝；
7. 在下一个 major 版本边界才可移除 legacy dict/兼容属性，且需要迁移说明和回归证据。

## 21. 验收标准

- [ ] 正确统计标签与指令同行的输入；

- [ ] compare 模式可同时生成所有请求的报告；
- [ ] 多文件 JSON 符合 12.2 节 schema，baseline 含全 0 delta，所有 renderer 共用同一 baseline；

## 22. 风险与权衡

| 风险 | 后果 | 缓解 |
|---|---|---|
| 分类表持续演进 | 历史报告不可比 | 分类版本+兼容性检查 |
| 独立 parser 与其他后端工具漂移 | 同一行汇编解析不一致 | 优先复用 `_asm_parser.py` |
| 伪指令按 1 条计 | 与机器码指令数不同 | 报告 count mode，后续增加 expanded/objdump 模式 |
| 类别过粗 | 不能解释扩展/延迟差异 | 主类别+扩展元数据，不过早细分几十类 |
| 计数下降被解读为性能上升 | 产生错误结论 | 报告明确标记静态口径，结合动态指标 |
| matplotlib/pandas 引入重 | 安装和 CI 成本增加 | 保持为 report 可选依赖，核心零依赖 |

## 23. 后续演进

- 基于 objdump 的真实机器指令静态统计；
- 按函数、基本块和符号区域分组；
- 代码尺寸（字节）和 compressed 指令收益；
- 按 ISA 扩展（I/M/A/F/D/C/V）汇总；
- 与 Topic 18 调度结果、cycle estimator 和 Topic 23 Cache 结果联合报告；
- 按优化 pass 捕获指令变化时间线；
- 可配置的 CI 回归基线和审核后基线更新流程。

这些演进都必须保留口径版本，不得将不同测量方式合并成一条无标识的“指令数”。
