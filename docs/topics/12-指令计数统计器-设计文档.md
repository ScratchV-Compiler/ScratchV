## 1. 这个功能要做什么

Topic 12 要把 ScratchV 最终生成的 RISC-V 汇编转换为稳定的结构化统计，用于：

- 查看静态指令总数和类别构成；
- 比较两个或多个汇编产物，量化优化前后变化；
- 将结果输出为文本、JSON、Markdown、HTML 或图表；
- 将数据写入 `CompileResult.stats`，供 benchmark 和 CI 使用；
- 发现未识别的指令，防止分类表长期漏维护。

它测量的是“汇编文本中的静态 mnemonic 数”，不是运行时动态指令数、周期、Cache miss 或真实性能。因此可以说“静态指令减少 8%”，不能单凭本报告说“性能提升 8%”。

### 1.1 输入和输出

| 项 | 内容 |
|---|---|
| 输入 | API 传入的汇编文本、一个或多个 `.s` 文件、编译器后处理完成后的最终汇编 |
| 核心输出 | `InstructionStats` 或 `ComparisonResult` |
| 人类可读输出 | stdout 文本、Markdown、HTML、可选图表 |
| 机器可读输出 | 带版本的 JSON、`CompileResult.stats`、benchmark/CI 记录 |

### 1.2 实现边界

第一版只实现 `textual` 模式：

- 每个出现在文本中的指令 mnemonic 计 1 条；
- 空行、注释、纯标签和 assembler directive 不计数；
- `label: add a0, a1, a2` 中的 `add` 计 1 条；
- 伪指令按文本中 1 条计数，不猜测 assembler 展开长度；
- `.word` 等数据 directive 即使内容可解码为指令，也不计数；
- 未知 mnemonic 计入 MISC，同时保留其名称和次数。

`expanded` 伪指令展开和 objdump 机器码计数是后续能力，不能与 `textual` 结果混用。

## 2. 指令如何分类

所有指令只进入一个主类别。ISA 扩展和“是否伪指令”是正交元数据，不再通过重复分类表达。

| 类别 | 边界 | 典型指令 |
|---|---|---|
| ALU | 整数算术、乘除、逻辑、移位、比较、上位立即数 | `add`、`addi`、`sub`、`mul`、`divu`、`srai`、`sltu`、`lui`、`auipc` |
| FP | 浮点算术、融合运算、开方、比较、转换和寄存器搬运 | `fadd.s`、`fmadd.d`、`fsqrt.s`、`flt.d`、`fcvt.w.s`、`fmv.x.w` |
| MEM | 整数和浮点载入/存储 | `lb`、`lhu`、`lw`、`ld`、`sw`、`flw`、`fsd` |
| BRANCH | 条件分支及其伪指令 | `beq`、`bltu`、`bnez`、`blez` |
| JUMP | 跳转、调用、返回，包括控制流伪指令 | `jal`、`jalr`、`j`、`jr`、`ret`、`call`、`tail` |
| ATOMIC | A 扩展的 load-reserved/store-conditional 和 AMO | `lr.w`、`sc.w`、`amoadd.w`、`amoswap.d.aqrl` |
| SYSTEM | fence、CSR、环境调用和特权级指令 | `fence`、`fence.i`、`csrrw`、`ecall`、`ebreak`、`wfi`、`sfence.vma` |
| PSEUDO | 非控制流的 assembler 伪指令 | `li`、`la`、`mv`、`not`、`neg`、`seqz`、`snez`、`nop` |
| MISC | 能解析但分类表不认识的 mnemonic | 自定义扩展或分类表漏项 |

### 2.1 压缩指令和扩展信息

Compressed 指令按语义进入主类别：`c.addi` 属于 ALU，`c.lw` 属于 MEM，`c.beqz` 属于 BRANCH，`c.j` 属于 JUMP，`c.nop` 属于 PSEUDO。报告仍保留原 mnemonic 和 `extension="C"`，不将其改写成基础指令。

初始分类表覆盖项目实际生成的 RV32IM，再逐步补齐 A/F/D/C/system。尚未支持的 V 扩展或自定义指令进入 MISC，不用过宽的前缀规则猜测。

### 2.2 分类注册表

```python
@dataclass(frozen=True)
class OpcodeInfo:
    category: str
    extension: str
    is_pseudo: bool = False
```

注册表以完整 canonical mnemonic 为键。匹配顺序是：

1. 完整 mnemonic 精确匹配；
2. 仅对 atomic 指令移除 `.aq`、`.rl`、`.aqrl` 顺序后缀再匹配；
3. 使用明确受控的规则处理可规则化扩展；
4. 不命中时进入 MISC/unknown。

不能统一删除 mnemonic 中的点号后缀，因为 `fadd.s`、`fadd.d`、`c.addi` 和 `amoadd.w` 中的后缀都是语义的一部分。

## 3. 数据模型

### 3.1 单文件结果

```python
from collections.abc import Mapping

@dataclass(frozen=True)
class InstructionStats:
    category_counts: Mapping[str, int]
    opcode_counts: Mapping[str, int]
    unknown_opcodes: Mapping[str, int]
    total: int
    source: str | None = None
    count_mode: str = "textual"
    isa: str = "unknown"
    schema_version: int = 1
    classification_version: str = "1"
```

必须满足：

```text
total == sum(category_counts.values())
total == sum(opcode_counts.values())
unknown_opcodes 是 opcode_counts 中 MISC 指令的子集
category_counts 始终包含全部 9 个主类别
所有计数是非负整数
```

`frozen=True` 不会自动冻结内部 `dict`。构造时必须防御性拷贝三组计数，验证不变式后使用 `MappingProxyType` 或等价只读映射。

`source` 保存调用方传入的原始路径字符串，不自动 `resolve()`。`isa` 只来自 API 参数或 CLI `--isa`，默认为 `unknown`，不从文件名或已出现的指令反向猜测。

### 3.2 多文件比较

```python
@dataclass(frozen=True)
class CategoryDelta:
    baseline: int
    current: int
    absolute: int
    percent: float | None

@dataclass(frozen=True)
class ComparisonResult:
    baseline_label: str
    stats: Mapping[str, InstructionStats]
    category_deltas: Mapping[str, Mapping[str, CategoryDelta]]
    opcode_deltas: Mapping[str, Mapping[str, int]]
```

`stats`、`category_deltas` 和 `opcode_deltas` 都包含 baseline，且按输入顺序排列。baseline 的 delta 固定为全 0。外层和内层映射均需防御性拷贝并转为只读映射。

差值计算规则：

```text
absolute = current - baseline
percent = absolute / baseline * 100  (baseline > 0)
percent = 0.0                        (baseline == 0 and current == 0)
percent = None                       (baseline == 0 and current > 0)
```

`None` 在文本中显示为 `N/A`，JSON 中为 `null`。JSON 百分比使用 `round(value, 4)`，人类可读报告显示 1 位小数；CI 应优先比较整数字段。

## 4. 核心处理流程

### 4.1 单文件分析

```text
汇编文本/文件
  -> 逐行读取
  -> _asm_parser.parse_line()
  -> 过滤空行、注释、纯标签和 directive
  -> 取得小写 canonical opcode
  -> 查询分类注册表
  -> 更新 category/opcode/unknown 计数
  -> 验证不变式
  -> 生成 InstructionStats
  -> 按需渲染报告
```

`scratchv/backend/_asm_parser.py` 是 label、comment、directive 和 opcode 的唯一语法来源。计数器不再维护第二套正则或 directive 列表。如果新语法无法解析，先修改共享 parser 及其测试。

| 输入 | 解析结果 |
|---|---|
| `add a0, a1, a2 # sum` | `add` |
| `loop:` | 不计数 |
| `loop: addi t0, t0, -1` | `addi` |
| `.L1: bnez t0, .L1` | `bnez` |
| `.text` / `.word 0x13` | directive，不计数 |

第一版每行最多支持一个前置 label。非空行既没有 opcode 也不是已知非指令时，记录为可疑行，不静默猜测。

### 4.2 多文件比较

```text
验证 schema/classification/count_mode/ISA 可比
  -> 为每个输入生成唯一 label
  -> 选择 baseline
  -> 计算 total/category/opcode delta
  -> 构造一个 ComparisonResult
  -> 所有 renderer 共用该结果
```

默认 label 是 basename；同 basename 时使用最短唯一路径后缀。用户可按输入顺序重复传入 `--label`。baseline 默认是第一个输入；`--baseline` 先精确匹配 label，再精确匹配原始 source path，不做 basename 模糊匹配。

只有下列字段兼容时才计算百分比：

- `schema_version`；
- `classification_version`；
- `count_mode`；
- `isa`（v1 使用字符串完全相等，两者都为 `unknown` 可比）。

不兼容时返回 `not comparable`，不生成看似精确的 delta。

### 4.3 编译器集成

```text
RISC-V 代码生成
  -> peephole/const-merge/schedule/beautify 等所有汇编后处理
  -> if config.count_instr: analyze_instructions(final_asm)
  -> result.stats["instruction_count"] = stats.to_dict()
  -> 写出最终汇编
```

统计必须位于所有汇编改写 pass 之后，否则报告与实际文件不一致。未启用 `--count-instr` 时不执行额外解析。LLVM IR backend 不是 RISC-V 汇编，与 `--count-instr` 组合时应在编译前拒绝，不能静默跳过。

## 5. 报告与 CLI 契约

### 5.1 报告内容

| 格式 | 用途 | 要求 |
|---|---|---|
| Text | 终端快速查看 | 默认显示类别摘要，`--verbose` 增加 opcode 和 unknown |
| JSON | API/CI/历史对比 | 稳定 schema，数字保持数字类型 |
| Markdown | PR 和 CI 摘要 | 显示总数、类别 delta 和 unknown 警告 |
| HTML | 离线详细报告 | 内嵌 CSS，所有用户文本 HTML escape |
| Chart | 可选可视化 | matplotlib 为可选依赖；空数据显示明确提示 |

所有格式都消费同一个 `InstructionStats` 或 `ComparisonResult`，不在 renderer 内重新解析汇编。

### 5.2 JSON schema

单文件 schema：

```text
schema_version: int
kind: "single"
classification_version: str
source: str | null
count_mode: str
isa: str
total: int
category_counts: {ALU, FP, MEM, BRANCH, JUMP, ATOMIC, SYSTEM, PSEUDO, MISC: int}
opcode_counts: {opcode: int}
unknown_opcodes: {opcode: int}
```

多文件 schema：

```text
schema_version: int
kind: "comparison"
classification_version: str
count_mode: str
isa: str
baseline: label
files: [
  {
    label: str,
    stats: {
      source, total, category_counts, opcode_counts, unknown_opcodes
    },
    delta: {
      total: {baseline, current, absolute, percent},
      category_counts: {ALU, FP, MEM, BRANCH, JUMP, ATOMIC, SYSTEM, PSEUDO, MISC: {baseline, current, absolute, percent}},
      opcode_counts: {ALL_SEEN_OPCODES: absolute_delta}
    }
  }
]
```

`files` 是数组，以保留输入顺序。baseline 也有一条全 0 delta。顶层已保存公共版本、口径和 ISA，嵌套 `stats` 不重复这些字段。

### 5.3 CLI

```text
python -m scratchv.backend.inst_counter FILE [FILE ...]
    [--compare]
    [--baseline LABEL|PATH]
    [--label LABEL]...
    [--verbose]
    [--json-output PATH]
    [--markdown PATH]
    [--html PATH]
    [--chart PATH]
    [--isa ISA]
    [--fail-on-unknown]
```

| 输入/参数 | 行为 |
|---|---|
| 1 个文件，无 `--compare` | 生成单文件报告 |
| 1 个文件 + `--compare` | 参数错误 |
| 2..N 个文件，无 `--compare` | 只向 stdout 按顺序输出独立摘要；请求文件报告时提示增加 `--compare` |
| 2..N 个文件 + `--compare` | 构造一个比较结果，全部 renderer 共用同一 baseline |
| `--label` | 数量必须为 0 或等于文件数，值必须唯一 |
| `--baseline` | 只能与 `--compare` 使用，且必须唯一匹配输入 |
| `--fail-on-unknown` | 先生成请求的报告，再因 unknown 返回严格模式退出码 |

退出码：`0` 成功，`1` 参数或 I/O 错误，`2` strict unknown 失败，`3` 可选渲染依赖或渲染失败。

## 6. 最容易出错的地方

| 坑点 | 错误结果 | 设计要求 |
|---|---|---|
| 遇到 label 就跳过整行 | `label: instruction` 漏计 | 复用共享 parser，取 label 后的 opcode |
| 把 `.L1:` 当 directive | 本地标签上的指令漏计 | 依赖 `ParsedAsmLine.is_directive`，不用简单 `startswith(".")` |
| 删掉所有点号后缀 | FP/atomic/compressed 分类错误 | 保留完整 mnemonic，仅处理 atomic 顺序后缀 |
| 将伪指令当机器指令展开 | 数量似乎精确但实际错误 | textual 模式每个伪指令固定计 1 |
| 未知指令直接丢弃 | total 被低估 | 计入 MISC 并保留 unknown 明细 |
| 两个文件 basename 相同 | 后者覆盖前者 | 使用唯一 label，不用 basename 作唯一键 |
| baseline 为 0 时直接做除法 | 崩溃或无穷大 | 使用 `0.0`/`None` 明确表达 |
| `frozen=True` 中保存可变 dict | total 和分类可在构造后失配 | 防御性拷贝并转为只读映射 |
| compare 分支提前 `return` | HTML/JSON/chart 未生成 | 先统一计算，后独立执行所有 renderer |
| 统计位于汇编 pass 之前 | 报告与最终 `.s` 不一致 | 只统计所有后处理之后的文本 |
| 静态指令下降被当作性能上升 | 得出错误性能结论 | 与动态指令、周期和正确性结果联合分析 |
| HTML 直接插入 path/opcode/title | 生成可执行脚本 | 对所有用户可控字段进行 HTML escape |

## 7. 兼容和版本

新模型不能一次性删除现有 API。迁移期保留：

- `count_instructions()` 和 `count_instructions_file()` 的 legacy dict 返回值；
- `format_table()`、`generate_chart()`、`generate_multi_chart()`、`generate_html_report()`；
- `compare_files()`、`print_comparison()`；
- `ComparisonResult.files/counts/diffs/to_dataframe()`；
- `scratchv.backend.count_instructions` 导出。

旧 API 在入口处通过一个集中 adapter 转换，新 renderer 只消费新模型。legacy `diffs` 仍排除 baseline；`to_dataframe()` 仍保持 `File/ALU/MEM/BRANCH/JUMP/PSEUDO/MISC` 列集和顺序。移除兼容层只能在下一个 major 版本进行，且需先发出 `DeprecationWarning`。

版本规则：

- JSON 结构不兼容变更：升级整数 `schema_version`；
- 分类表或分类口径改变：升级字符串 `classification_version`；
- 历史数据版本不同：保留原数据并标记 `not comparable`，不静默重算。

## 8. 错误、性能和安全

### 8.1 错误语义

| 场景 | 行为 |
|---|---|
| 文件不存在/无权限/非 UTF-8 | API 保留标准 I/O/解码异常；CLI 输出明确错误 |
| 空文件 | 成功返回 total=0 和全部零类别 |
| 未知 opcode | 默认成功并记入 MISC；strict 模式在报告生成后失败 |
| 缺少 matplotlib/pandas | 仅请求相应可选能力时失败 |
| 报告不可写 | 返回失败，不输出伪成功消息 |

### 8.2 性能

- 计数时间复杂度为 `O(N)`，N 为汇编行数；
- 聚合数据空间为 `O(U + C)`，U 为不同 mnemonic 数，C 为固定类别数；
- 文件 API 逐行扫描，百万行输入不保存百万个持久 AST 节点；
- renderer 不重新解析汇编，可选图表不影响无图模式启动。

### 8.3 安全

- 不执行 `.include`、`.incbin` 或宏；
- 不通过 shell 拼接输入路径；
- HTML 转义 title、label、path 和 opcode；
- JSON/HTML 默认不嵌入汇编原文；
- 对不受信超大输入可在调用层设置文件大小或行数限制。

## 9. 验收标准

- [ ] 标签、directive、带点 mnemonic 和 atomic 顺序后缀解析正确；
- [ ] 9 个主类别都有精确分类测试，unknown 不丢失；
- [ ] `InstructionStats` 和 `ComparisonResult` 满足计数不变式和深度不可变要求；
- [ ] 单文件和多文件 JSON 符合第 5.2 节 schema；
- [ ] text/JSON/Markdown/HTML/chart 消费同一统计对象；
- [ ] 多文件同 basename 不丢数据，全部 renderer 共用同一 baseline；
- [ ] `--verbose`、`--compare`、`--label`、`--baseline`、`--fail-on-unknown` 符合 CLI 契约；
- [ ] 空输入可生成有效报告，HTML 用户字段全部转义；
- [ ] CompilerDriver 只对最终 RISC-V 汇编统计，结果写入 `stats` 而非 `warnings`；
- [ ] 现有公共 API 和 `tests/test_inst_counter.py` 的旧行为在迁移期继续可用；
- [ ] Topic 单测、CLI 测试、编译集成测试和项目 L2 验证通过。
