# Topic 18：实现与验证方法

## 编译流程

CompilerDriver：ONNX/DSL → IR → 指令选择 → greedy 或 linear 寄存器分配 → 汇编 → 局部调度 → 输出。分配器是编译配置，决定调度器接收到的物理寄存器和栈访存；调度默认关闭。

standalone：ONNX → RV32IM 机器码 → 地址修补 → 局部调度 → 二进制与汇编。该路径使用固定寄存器布局；调度置换已有机器字，常量合并由独立开关控制。

| 文件 | 职责 |
|---|---|
| `scratchv/backend/llvm_mca.py` | 调用 LLVM MCA、校验版本及完整性、读取时间线和原始 JSON |
| `scratchv/backend/schedule_semantics.py` | 指令形式、物理寄存器读写、访存与控制流语义 |
| `scratchv/backend/inst_scheduler.py` | 区域划分、依赖图、候选顺序和 LLVM 收益判定 |
| `scratchv/backend/schedule_verify.py` | 独立验证读值来源、最终写入及副作用顺序 |
| `benchmarks/bench_cnn_schedule.py` | 仓库 CNN 的调度 A/B、验收及报告 |
| `benchmarks/schedule_analysis.py` | CFG 固定点活跃性分析 |
| `benchmarks/cnn_schedule_execution.py` | 汇编重编码与完整 CNN 的 QEMU 执行验证 |

## CPU 模型与工具契约

唯一计时来源是 **LLVM MCA、`sifive-e76`**。仓库评测结果使用 LLVM 18.1.3，模型定义为该版本的 [RISCVSchedSiFive7.td](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/llvm/lib/Target/RISCV/RISCVSchedSiFive7.td)。项目不维护周期表、旁路公式或 CPU 模拟器；LLVM 处理指令延迟、资源占用和流水线等待。

每次分析一个区域，命令固定为：

```bash
llvm-mca-18 -mtriple=riscv32 -mcpu=sifive-e76 -mattr=+m,+f,+d,-c \
  -iterations=1 -noalias=false -timeline \
  -timeline-max-cycles=0 -timeline-max-iterations=1 -json < region.s
```

程序通过 `LLVM_MCA` 指定可执行文件，默认 `llvm-mca`；Python API 的 `llvm_mca` 参数优先于环境变量。启用调度且存在可分析区域时需要该工具。日常运行不限制精确版本；兼容性由 CPU 目标、命令参数及 JSON/Timeline 校验确定。报告记录实际版本、模型源码链接和调用参数。工具缺失、无法识别版本输出、超时、部分解析和不完整时间线均报错，不启用替代模型。

LLVM 对返回指令发出的“忽略 PC 更新”提示符合静态区域的分析口径，可接受；其他诊断仍视为错误。程序的实际控制流由 QEMU 执行回归检查。

LLVM 输入规范化访存语法，将区域末尾的分支目标替换为局部符号，输出汇编的标签和操作数不变。支持的伪指令必须对应一条机器指令；检查 Timeline、指令数与微操作数，拒绝意外展开。JSON 保存规范化输入、工具参数及完整 LLVM 输出。相同可执行文件和输入的结果在进程内缓存，工具文件变化会使缓存失效。

## 调度与正确性

1. 标签、控制转移、注释、指令形式边界等划分连续区域；禁止跨区域移动，终止指令固定。
2. 建立 RAW、WAR、WAW、访存、浮点状态和控制依赖。所有访存保持原序，整数除法保留与其他指令的相对位置。依赖边表示顺序约束，不表示周期。
3. 从依赖已满足的节点中选择候选：优先安排最近 RAW 生产者位置较早的指令，其次按后继依赖深度、原始位置排序。该规则只生成合法排列，不预测发射时间。
4. 用 llvm-mca 分别分析原序与候选；仅当候选完成周期严格减少时采用，否则恢复原序。未采用的候选周期和发射记录也写入 JSON。
5. 独立 verifier 检查指令身份、每次读取的定义来源、最终写入、访存和控制边界。语义验证失败时恢复整个区域，严格模式报错；LLVM 工具故障直接报错。

standalone 从已修补机器码的 PC 相对偏移恢复符号目标，并建立区域边界；只置换区域内的 32 位机器字。跳转及目标位置、代码长度、权重和 AUIPC 位置不变。任意用户汇编中的数字跳转没有这一布局保证，因此保留整份原序。

## 指标

| 指标 | 口径 |
|---|---|
| 最大指令并行数 | Timeline 中单周期发射条数峰值，跨区域取最大值 |
| 关键路径长度 | N/A；当前接口未采集此顺序执行目标的关键路径分析，不自行补算 |
| 流水线气泡 | 发射区间内零发射的周期数 `B=S−U`；跨区域求和 |
| 完成周期 T | `max(最大 CycleExecuted, 最大 CycleIssued+1)−最小 CycleIssued` |
| 辅助指标 | 发射跨度 S、排空 T−S、平均 IPC=N/T、气泡率 ΣB/ΣS |

S 为首末发射周期覆盖的长度，U 为至少发射一条指令的周期数。例如发射时间 `[0,3]`、最后执行完成时间为 6，则 T=6、S=4、B=2、排空=2。原始 LLVM `TotalCycles` 也保留在 JSON，主表排除其末尾管理周期。

每个静态区域只分析一次，入口操作数就绪，不按循环或分支频率加权。气泡指零发射周期，峰值指当前排列在模型中的观测值；两者均不代表理论最优。局部周期合计不是整网运行时间，QEMU 执行验证也不提供硬件性能结论。

胜/平/负比较同一路径、同一区域的原序和最终顺序，以完成周期减少、相同、增加分类；未换序的建模区域也计入。退化候选被拒绝，因此最终负区域应为零。

## CNN 测试与验收

输入固定为跟踪在仓库中的 `models/graph/cnn.onnx`，缺文件、编译失败或输入不一致直接失败。

- 主路径：standalone，固定 `const_merge=True`，仅切换调度。
- 补充路径：CompilerDriver，固定 `backend=riscv`、`optimize_level=none`，分别选择 greedy/linear，关闭其他汇编优化。这些路径使用简化 ONNX lowering，不代表完整 CNN 的动态计算量。
- 静态检查：指令及寄存器集合、读值来源、最终写入、栈访存、sp 操作、边界和 CFG 活跃峰值。调度发生在分配之后，不新增分配或 spill；活跃峰值仍可能增加。
- 主路径必须覆盖除 AUIPC 外的全部指令，LLVM 周期合计改善，所有最终区域不退化；汇编重编码、代码布局及权重字节必须一致。
- 使用 QEMU 比较三个固定 Q16.16 输入的全部整数寄存器、工作区和输出。基线崩溃、调度版本崩溃或状态差异均失败。`execute=False` 只运行静态检查，报告明确标为未执行。

A/B 两侧使用相同的代码生成器，仅切换调度。standalone 代码生成回归位于 `tests/test_standalone_execution.py`，调度 A/B 回归位于 `tests/test_inst_scheduler_standalone.py`。执行等价不替代 Q16.16 与 ONNX 浮点参考的精度验证。

## 复现与 CI

依赖项目 Python 环境、LLVM MCA、支持 RV32 的 clang/ld.lld 和 qemu-riscv32。CI 保留 `ubuntu-latest`，使用发行版提供的 `llvm` 软件包，不锁定 LLVM 版本。各次 A/B 使用同一工具和参数；跨版本结果需结合版本信息比较。

严格复现仓库报告的数值时，安装 LLVM MCA 18.1.3，并确认以下可执行文件输出的版本确为 18.1.3：

```bash
export LLVM_MCA=llvm-mca-18
PYTHONHASHSEED=0 python -m benchmarks.bench_cnn_schedule
PYTHONHASHSEED=0 SCRATCHV_REQUIRE_RISCV_EXECUTION=1 python -m pytest \
  tests/test_inst_scheduler*.py tests/test_standalone_const_merge.py \
  tests/test_standalone_execution.py tests/test_cnn_pipeline.py \
  tests/test_regalloc_linear.py tests/test_pr37_regression.py -q
```

报告写入 `benchmark_reports/inst_scheduler_cnn.md` 和同名 JSON；汇编与二进制位于 `benchmark_reports/cnn_schedule/`。审阅快照见本目录的验证报告和 `cnn-scheduling-results.json`。

沿用现有 CI jobs：`test` 准备 LLVM、Clang、LLD 和 QEMU，统一执行调度及 standalone 回归，结果进入 `test_results.xml`；`benchmark` 运行 CNN A/B、合成压力测试及固定小用例，生成报告并上传到 `benchmark-reports` artifact 和 Job Summary。执行工具缺失时回归失败，禁止跳过。没有新增 pipeline 或 job。
