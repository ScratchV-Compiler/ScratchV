## 1. 前置准备：SSH Key 与 gh CLI

### 1.1 配置 SSH Key（一次性）

用 SSH 推送代码免去每次输入密码。没有配过的话：

```bash
# 1. 生成 SSH Key（一路回车即可）
ssh-keygen -t ed25519 -C "your_email@example.com"

# 2. 复制公钥
cat ~/.ssh/id_ed25519.pub
```

然后去 [GitHub → Settings → SSH and GPG keys](https://github.com/settings/keys) 点 "New SSH Key"，粘贴公钥。

> 💡 **验证是否配好**: 跑 `ssh -T git@github.com`，看到 `Hi xxx! You've successfully authenticated` 就对了。

### 1.2 安装 gh CLI

`gh` 是 GitHub 官方命令行工具，可以不用开网页就创建 PR：

```bash
# Ubuntu/Debian
sudo apt install gh

# 或者下载独立二进制（无需 sudo）
mkdir -p ~/.local/bin
# 去 https://github.com/cli/cli/releases 找最新版本
curl -sL "https://github.com/cli/cli/releases/download/v2.95.0/gh_2.95.0_linux_amd64.tar.gz" -o /tmp/gh.tar.gz
tar -xzf /tmp/gh.tar.gz -C /tmp
cp /tmp/gh_2.95.0_linux_amd64/bin/gh ~/.local/bin/gh
export PATH="$HOME/.local/bin:$PATH"
```

### 1.3 认证 gh CLI（一次性）

```bash
gh auth login
```

按提示选择：
- `GitHub.com`（不是 GitHub Enterprise）
- `SSH`（与上面配的 SSH Key 匹配）
- `Login with a web browser`（会自动打开浏览器）

> 💡 **验证是否认证成功**: `gh auth status` 应该显示 `Logged in to github.com`

## 2. 第1步：从 main 拉最新代码

> ⚠️ **在做任何修改之前，先拉最新代码**，避免后续合并冲突。

```bash
# 切换到 main 分支
git checkout main

# 拉取最新代码
git pull origin main
```

实际输出示例：
```
Switched to branch 'main'
Already up to date.
```

> 💡 如果本地有未提交的修改，先 `git stash` 暂存，拉完后再 `git stash pop` 恢复。

---

## 3. 第2步：创建功能分支

> ⚠️ **永远不要在 main 分支上直接修改！** 每次新功能/修复都从 main 开新分支。

```bash
# 创建并切换到新分支
git checkout -b docs/pr-guide
```

实际输出：
```
Switched to a new branch 'docs/pr-guide'
```

### 3.1 查看当前所在分支

```bash
git branch
```

实际输出：
```
  clean-main
* docs/pr-guide    # ← * 号表示当前分支
  jzj_dev
  main
```

### 3.2 分支命名建议

| 类型 | 命名示例 | 说明 |
|------|---------|------|
| 新功能 | `feat/xxx` | `feat/conv-opt`, `feat/add-pooling` |
| 修 bug | `fix/xxx` | `fix/regalloc-crash`, `fix/memory-leak` |
| 文档 | `docs/xxx` | `docs/pr-guide`, `docs/api-reference` |
| 重构 | `refactor/xxx` | `refactor/ir-types`, `refactor/backend` |
| CI 相关 | `ci/xxx` | `ci/add-benchmark`, `ci/fix-runner` |

现在在功能分支上，可以放心改代码了。

```bash

vim scratchv/backend/regalloc_linear.py
```

## 7. 第6步：创建 Pull Request

### 7.1 方式一：用 gh 命令行（推荐）

推送成功后，GitHub 已经提示了 PR 链接，直接用 `gh` 创建：

```bash
# 基本用法：从当前分支向 main 创建 PR
gh pr create --base main --head docs/pr-guide \
  --title "添加 PR 提交指南文档" \
  --body "## 修改内容
- 从 SSH 配置到 PR 创建完整流程
- 所有命令经实际验证
- 包含 CI 自动检查和常见问题

## 验证
- 每条命令在本地实际运行并记录输出

🤖 Generated with [Claude Code](https://claude.com/claude-code)"
```

实际输出：
```
https://github.com/ScratchV-Compiler/ScratchV/pull/8
```

### 7.2 方式二：去 GitHub 网页创建

推送后 GitHub 会给你一个链接（如 `https://github.com/ScratchV-Compiler/ScratchV/pull/new/docs/pr-guide`），浏览器打开即可。

在网页上：
1. 确认 **base** 是 `main`，**head** 是你刚推送的分支
2. 写标题和描述
3. 点 "Create pull request"

### 7.3 查看 PR 状态

```bash
# 查看当前分支关联的 PR
gh pr view

# 在浏览器打开 PR
gh pr view --web
```

### 7.4 PR 描述模板

PR 描述要写清楚三件事：**改了什么、为什么、怎么验证的**。

```markdown
## 修改内容
- 具体改了什么，逐条列出

## 动机/背景
- 为什么要做这个修改？解决了什么问题？

## 验证方法
- 跑了什么测试？结果是什么？

## Dashboard 截图（如有性能变化）

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

## 8. 第7步：PR 提交后的操作

### 8.1 在 PR 中追加 commits

如果 review 后需要修改，直接在同一个分支上继续改：

```bash
# 修改代码...
vim scratchv/backend/regalloc_linear.py

# 提交并推送
git add .
git commit -m "修复 review 反馈的格式问题

- 统一缩进为4空格
- 修复变量命名

Co-Authored-By: Claude <noreply@anthropic.com>"
git push
```

新 commit 会自动追加到 PR 中，不需要重新创建 PR。

### 8.2 同步上游 main

如果你的 PR 开了几天，main 分支可能已经被其他人更新了：

```bash
# 拉取最新 main
git fetch origin main

# 把你的分支 rebase 到最新的 main 上
git rebase origin/main

# 强制推送（因为 rebase 改变了 commit hash）
git push --force-with-lease
```

> ⚠️ **用 `--force-with-lease` 而不是 `--force`**！前者会检查远程分支是否被别人改过，更安全。

### 8.3 合并后清理

PR 合并后，可以删除本地分支：

```bash
# 切回 main
git checkout main
git pull origin main

# 删除本地分支
git branch -d docs/pr-guide

# 删除远程分支（GitHub 上 PR 合并后通常自动删了，但可以手动确认）
git push origin --delete docs/pr-guide
```

## 9. CI 自动检查

推送代码后，GitHub Actions 会自动运行 CI。在 PR 页面底部可以看到检查状态：

- 🟡 **黄色圆点** — 正在运行
- 🟢 **绿色勾** — 全部通过
- 🔴 **红色叉** — 有失败

ScratchV 的 CI 包含两步（在 `.github/workflows/ci.yml` 中定义）：

| 步骤 | 命令 | 说明 |
|------|------|------|
| test | `pytest tests/ -v` | 单元测试 |
| benchmark | `make bench-ci` | 基准测试 + 生成 dashboard |

### 本地提前检查（推荐）

在推送之前先在本地跑一遍，大概率能通过 CI：

```bash
# 跑单元测试
make test

# 跑基准测试
make bench-ci
```

## 10. 常见问题

### Q1: git push 时提示 "Permission denied (publickey)"

**原因**: SSH Key 没配或没加到 GitHub。

**解决**:
```bash
# 检查是否连上
ssh -T git@github.com

# 如果连不上，重新生成并添加 SSH Key
ssh-keygen -t ed25519 -C "your_email@example.com"
cat ~/.ssh/id_ed25519.pub   # 复制到 GitHub Settings → SSH Keys
```

### Q2: git push 时提示 "failed to push some refs"

**原因**: 远程分支有你本地没有的 commits（比如你 rebase 过或者别人推了同分支）。

**解决**:
```bash
# 先拉远程，再推送
git pull --rebase origin docs/pr-guide
git push
```

### Q3: git commit 后发现有文件忘加了

**解决**:
```bash
# 追加到上一次 commit（不改 commit message）
git add 忘记的文件
git commit --amend --no-edit

# 如果已经 push 过，需要 force push
git push --force-with-lease
```

### Q4: PR 合并后有冲突怎么办？

**原因**: main 分支有其他 PR 合并了，和你改的文件有重叠。

**解决**:
```bash
git fetch origin main
git rebase origin/main
# 如果有冲突，手动解决后:
git add 解决的文件
git rebase --continue
git push --force-with-lease
```

### Q5: 怎么把一个 PR 标记为 "Draft"（草稿）？

用 `gh` 创建时加 `--draft`：
```bash
gh pr create --draft --title "WIP: 新功能（还在开发中）" --body "..."
```

或在 GitHub 网页上 PR 页面点击 "Convert to draft"。

### Q6: 国内 GitHub 连接不稳定怎么办？

参考项目 CI 迁移经验，配置 Git 使用 HTTP/1.1：
```bash
git config --global http.version HTTP/1.1
```

## 完整流程速查

```bash
# 1. 拉最新
git checkout main && git pull origin main

# 2. 开分支
git checkout -b feat/my-feature

# 3. 改代码 + 提交
git add .
git commit -m "标题

主体
Co-Authored-By: Claude <noreply@anthropic.com>"

# 4. 推送
git push -u origin feat/my-feature

# 5. 创建 PR
gh pr create --base main --head feat/my-feature \
  --title "功能描述" \
  --body "修改内容和验证方法

🤖 Generated with [Claude Code](https://claude.com/claude-code)"

# 6. Review 后追加修改
git add . && git commit -m "修复 review 反馈" && git push

# 7. 合并后清理
git checkout main && git pull origin main
git branch -d feat/my-feature
```
