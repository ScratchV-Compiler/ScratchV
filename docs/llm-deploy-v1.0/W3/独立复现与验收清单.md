以下是可以直接执行的候选口径。确认人和日期留空，不能将作者选择当作团队共识。

| 项目 | 本地采用的定义 | 团队确认记录 |

| 验证覆盖 | 下列七组输入全部执行、普通/诊断同后端 logits 完全一致、四项因果/key-padding 不变量通过 | 待确认：人 / 日期 / 讨论记录 |
| Nightly | 以完整七组硬门槛为数值条件，记录实际 workflow run、SHA、结果及原始产物；具体运行频率和资源由维护者确认 | 待确认：人 / 日期 / 讨论记录 |

medium 的通道尺寸是候选配置，开发计划只指定了六层。它验证 Qwen3 结构和计算语义，不是完整尺寸预训练六层模型。完整模型使用真实预训练权重；两种证据分别验收。

`reference-v4` 规定若干 FP32 运算的计算顺序和近似算法，不修改模型输出、不把 ORT 调用作为 IR 算子实现，也不保证任意 CPU、BLAS 或 ORT 版本逐位一致。解释器 API 默认仍是 `native`；`reference-v4` 通过不等于 `native` 通过，也不能沿用历史 v1/v2/v3 的验收结果。复现达到固定误差门槛即可，不要求重复作者机器上的零误差。

`SCRATCHV_FP32_REFERENCE_CPU` 可设为 `auto`、`avx2-fma3` 或 `avx512`，未设置时默认 `auto`。`auto` 根据 NumPy 报告的可用 AVX2/FMA3/AVX512F 能力选择参考策略；能力不足、无法推断或 `NPY_DISABLE_CPU_FEATURES` 遮蔽相关能力时明确失败。显式取值只固定 IR 的参考算术顺序，不控制 ORT 选择哪种 CPU 内核，也不保证本机 IR/ORT 一致。报告保存实际解析后的 `cpu_strategy`，每位复现者应同时保存启动时的环境变量原值。完整使用契约见 [完整模型入口](../../../probes/w3_qwen3_full/README.md)。

v4 的完整 profile 还记录 MatMul 的 K 分块、行分块、尾行/单列补齐、操作数布局和向量策略。AVX2 采用固定两行和 C 连续分块，AVX512 保留原路径；复现与 audit 必须核对这些字段，不能只核对 `name`、`cpu_strategy` 或最终形状。当前 v4 已提交于 `1c49e8acbcd9174491b2d0c2a5a0072178ae5f9a`，[第四轮](https://github.com/yuki-328/ScratchV/actions/runs/37299235103)的 preparation、完整 full 和汇总均已通过；第三轮 FAIL 保留为历史记录，完整 raw 数组离线 audit 也已通过。

完整模型的 ORT 基准固定为 CPUExecutionProvider、关闭图优化、intra/inter threads 均为 1、关闭 CPU memory arena。medium 分别覆盖 IR `none/basic/all` 和普通/诊断两种图，使用原有 NumPy 执行路径，不能将完整模型的单一优化等级覆盖描述成所有优化都已验证。

## 3. 独立执行步骤

在已核对的快照或 checkout 根目录运行。每次重试使用新的输出目录；保留失败目录，不能将以前的成功产物覆盖到新结果中。

```bash
set -euo pipefail
W3_SOURCE="${W3_SOURCE:-$PWD/output/assets/source}"
W3_MODEL=/absolute/path/to/qwen3-0.6b-onnx
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
export PYTHONIOENCODING=utf-8 SCRATCHV_FP32_REFERENCE_CPU=auto

if [[ -e .git ]]; then
  git rev-parse HEAD
  git status --short
else
  "$SCRATCHV_PYTHON" -B -X utf8 scripts/package_w3_repro.py verify --root "$PWD"
fi
"$SCRATCHV_PYTHON" -B -X utf8 scripts/run_w3_preparation.py \
  --source-dir "$W3_SOURCE" --model-dir "$W3_MODEL" \
  --output-dir output/w3-repro-preparation-01 \
  --cc "$SCRATCHV_CC" --qemu "$SCRATCHV_QEMU"
"$SCRATCHV_PYTHON" -B -X utf8 probes/w3_qwen3_full/run.py \
  --model-dir "$W3_MODEL" --output-dir output/w3-repro-full-01 \
  --fp32-mode reference --worker-timeout 1800 --max-worker-memory-gib 10
```

上面的 Bash 命令使用 `set -euo pipefail`，任何入口返回非零都会终止后续步骤，失败目录须保留。远端执行参照 [Linux CI 与 Nightly](Linux-CI与Nightly.md)。两套工作流支持手动运行，Nightly 编排准备项与完整七组。作者[第四轮 Linux 手动编排](https://github.com/yuki-328/ScratchV/actions/runs/37299235103)已在同提交通过两套 gate 和汇总，完整 raw audit 已通过；应按每次实际 SHA、profile 和各套结果分别登记，不能拼接不同提交的通过项。配置存在、手动调用成功和定时 schedule 成功是三种不同状态；作者运行不能替代复现者在自己环境执行。

`--max-worker-memory-gib 10` 是 worker 进程树的采样终止阈值，不是总机器内存预算或操作系统硬配额。超时和内存不足属于运行失败；可以在记录机器资源后调整资源预算，但不能用改模型、缩短覆盖、放宽数值误差来取得全量 PASS。解释器张量存储统计、进程全生命周期 RSS 和父进程采样值口径不同，原始字段应分别保留。

### 3.1 必须覆盖的七组输入

完整图契约：INT64 `input_ids [1,256]`、FP32 加性 mask `[1,1,256,256]`，FP32 logits `[1,256,151936]`。这些是可复现的 embedding ID 数值测试，不是语言生成质量测试。

| case | 有效长度 | 必须检查的内容 |
|---|---:|---|
| `full_seed_0` | 256 | 种子 0 的满长输入，全部 logits |
| `full_seed_42` | 256 | 种子 42 的满长输入，全部 logits |
| `one_token` | 1 | 1 个有效 token 和 255 个 padding query 的输出 |
| `short_17` | 17 | 17 个有效 token 和 239 个 padding query 的输出 |
| `short_255` | 255 | 255 个有效 token 和最后一个 padding query 的输出 |
| `changed_future` | 256 | 修改 `full_seed_0` 第 64 个索引起的 token，前 64 个位置应保持因果隔离 |
| `changed_padding` | 17 | 保持 `short_17` 的 mask，改变 padding token ID，前 17 个有效位置应保持隔离 |

每组 ORT 和 IR 各执行普通图、诊断图，先检查各自两份完整 logits 逐元素完全一致，再分别跨后端比较。四项不变量是 ORT/IR 各自的未来 token 隔离和 padding 隔离，均严格 `<1e-4`、`rtol=0`。它们比较受保护的有效前缀；正式跨后端精度仍比较全部 256 个位置，不能只比较前缀。

完整诊断有 30 个检查点：embedding、28 层 residual 输出、final norm。检查点误差用于定位；正式硬门槛作用于完整 logits。medium 的 81 个检查点及 18 项隔离检查由 preparation 单独验收。

### 3.2 退出判定与失败处理

| 入口 | 可以接受的结果 | 不足以验收的结果 |
|---|---|---|
| preparation | 五项均 PASS、返回 0、报告和原始产物齐全 | 仅 preflight 或部分子入口通过 |
| full runner | 七组完整覆盖、四项不变量通过、`status=PASS`、返回 0 | `--case` 子集返回 PARTIAL/2；FAIL/1；中断 130 |
| layer-diff | 完整 schema 覆盖并通过 | 选定部分层的 PARTIAL 不替代完整覆盖 |
| localize | 用于记录同输入的层内误差、原语误差和定位结果 | `COMPLETE`/0 仅表示诊断完成，不是 W3 数值 PASS |

失败先保存日志、输入、两后端报告、完整 logits、检查点和 schema。检查 `cases[].comparison.logits` 与 `first_divergence`，再按 [LOCALIZE.md](../../../probes/w3_qwen3_full/LOCALIZE.md) 定位。不得删除不通过的 padding 位置、换用不同参考、将局部成功写成全量成功。
