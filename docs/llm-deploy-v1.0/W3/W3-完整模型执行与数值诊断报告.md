## 执行与数值范围

固定真实 Qwen3-0.6B ONNX 为 28 层、FP32、L256、无 KV cache。每组输入分别启动 ORT 和 IR worker，两个后端各运行普通图及诊断图。ORT 使用 CPUExecutionProvider、关闭图优化与 CPU memory arena、intra/inter threads 均为 1。IR 使用优化等级 `none`、`numpy-fp32-reference-v4/avx2-fma3`。

## Linux 环境、时长与内存

实际 runner 为 Ubuntu 24.04.5、Python 3.12.14、4 vCPU AMD EPYC 7763、约 16.77 GB RAM。NumPy 2.2.6、ONNX 1.18.0、ORT 1.22.1、Torch 2.7.1+cpu；NumPy 诊断为 AVX2/FMA3、OpenBLAS 0.3.29 / Haswell、`OPENBLAS_CORETYPE=null`。这些字段不能推断 ORT 内部 dispatch。

- 完整 runner 墙钟时长 `1477.314971525 s`，约 24.6 分钟，包含加载、普通/诊断执行、比较和证据写盘。
- 每组 ORT worker 总时长约 `15.20–15.53 s`；每组 IR worker 总时长约 `193.45–195.88 s`。每个 worker 都有两次前向，不是单次推理 benchmark。
- worker 自报全生命周期 RSS 峰值：ORT `4,443,017,216–4,443,987,968` bytes，IR `3,102,253,056–3,102,715,904` bytes。
- 父监控的进程树 RSS 采样峰值：ORT `4,443,328,512–4,444,389,376` bytes，IR `2,943,205,376–3,057,094,656` bytes。采样可能错过瞬时峰值，不与 worker 自报值混用。

完整入口采用只读权重映射、initializer 借用和中间 binding 最后使用后回收。Linux 通过独立进程组管理本次拥有的进程树，超时/采样内存超限/中断时清理。采样终止阈值不是操作系统硬配额，也不是整台机器总内存预算。默认解释器调用行为保持兼容；本报告不将容量准备当作 W6 性能优化收益。
