## 2. 改动如何组成完整工作

### 编译器与解释器支撑

- ONNX 前端增加可选的外置权重只读映射，检查名称、路径、偏移、长度、dtype 和 shape。
- IR 解释器增加只读 initializer 借用、最后使用后释放 binding、同步观察回调及可选内存统计，支撑完整模型执行和选择性检查点保存。
- 增加版本化 `numpy-fp32-reference-v2` 模式及对应单测。该模式使用 NumPy 计算，不在 IR 算子内调用 ORT；解释器 API 默认仍为 `native`。
- 默认 initializer 复制、保留中间 binding 等调用行为保持；借用及回收模式限定纯算子、单基本块、SSA、单一末尾 RETURN，不支持时明确报错。
- 第三方 Eigen MPL-2.0 与 MLAS MIT 材料的声明和许可证随源码/安装包保存。项目主体 MIT 与文件级许可分别说明。

### 探测与验收入口

| 入口 | 作用 |
|---|---|
| `scripts/run_w3_preparation.py` | 顺序执行 medium、真实权重子图、小 Attention QEMU、完整资产预检、layer-diff 五项检查 |
| `probes/w3_qwen3_full/run.py` | 启动 ORT/IR 独立 worker，实际执行完整模型；核对七组输入、完整输出和四项不变量 |
| `probes/w3_qwen3_full/localize.py` | 基于同一输入继续定位层内与原语差异，诊断完成不等于数值验收通过 |
| `scripts/verify_w3_evidence.py` | 重新读取已保存原始数组，重算误差及不变量，核对报告、哈希、schema 和数值策略 |
| `scripts/package_w3_repro.py` | 为未提交代码生成可校验源码快照，包含复现所需示例、测试和文档；不包含 Git 历史或模型 |
| `scripts/collect_w3_ci_evidence.py` | 收集受大小限制的准备阶段诊断证据，记录实际文件哈希及省略原因 |

完整执行区分 `PASS/0`、`FAIL/1`、`PARTIAL/2`，中断为 130。单例正确不会变成全覆盖 PASS。进程树超时/内存保护、失败报告、原始数组保留和读取边界均有回归覆盖。

### CI 和交付

两套验收工作流固定使用 `ubuntu-24.04` 与 Python 3.12，记录系统资源、实际依赖和工具版本；保持手动入口并支持同提交复用。准备工作流获取完整 Git 历史，使固定旧版本 benchmark 真正执行。

Nightly 默认不执行定时数值任务，需要 `W3_NIGHTLY_ENABLED=true`；手动触发可明确运行完整编排。只有准备项与完整七组均成功，汇总才能通过。报告与原始数组分开管理保留期，不能只凭报告文件存在判断产物完整。具体见 [Linux CI 与 Nightly](Linux-CI与Nightly.md)。

源码包内历史 benchmark 会明确说明缺少 Git 历史；它不会向上借用其他仓库。超时处理测试独立于真实历史，Git 集成则在实际 checkout 中执行。

## 4. 评审顺序与兼容边界

建议先确认完整 logits 的范围和误差门槛，再评审前端/解释器可选接口、FP32 模式、完整 runner 的验收拒绝逻辑、其他探测与证据工具，最后核对 CI、文档及第三方许可。

- 当前零误差仅属于固定 Windows/CPU/依赖环境下的 `reference-v2`；不是默认 `native`、其他 CPU/BLAS 或 Linux 的通过保证。
- medium 为六层随机小配置候选，需要团队认可通道尺寸；真实子图仅使用第一层预训练权重和受控激活。
- 映射的权重文件在调用期间必须保持不变；映射接口本身不替代固定资产哈希验证。
- 解释器统计不包含全部临时缓冲、分配器及调用方持有的数组；进程 RSS 和采样内存另行报告。
- 完整 IR 门槛以固定 ONNX 的 ORT 执行为参考；既有导出阶段 PyTorch/ORT 差异保留独立口径，不因 IR/ORT 通过自动消失。
- W3 的小 Attention QEMU 与完整 host IR 分别验收。完整大模型的 RISC-V 代码/权重分离、装载及 QEMU 前向属于 W4；生成循环属于 W5。
