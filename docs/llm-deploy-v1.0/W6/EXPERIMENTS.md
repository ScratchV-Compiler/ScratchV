# 生成耗时与优化建议

<a id="pipeline-cost"></a>

France 用例生成并校验 8 个 token，共用 **346.226 秒（约 5 分 46 秒）**。其中首次处理提示词占 **72.87%**，是目前最值得优先优化的部分。

本次配置：Qwen3-0.6B，4 核、FP32、KV cache 与 W6 优化开启，工作区 padding 关闭。

| 阶段 | 耗时（秒） | 占总时间 | 优化价值 |
| --- | ---: | ---: | --- |
| 首次处理提示词（Prefill） | 252.307 | 72.87% | 最高：减少无效位置的计算 |
| 接续生成 7 个 token（Decode） | 33.249 | 9.60% | 其次：输出越长，越值得优化 |
| ORT 参考计算 | 46.960 | 13.56% | 属于校验开销，减少它不算模型加速 |
| QEMU 会话启动 | 13.497 | 3.90% | 较低：当前已复用进程和权重 |
| 数值比较、文字处理等 | 0.214 | 0.06% | 很低：对总时间影响很小 |

以上为实际等待时间，包含最终文字生成和校验；不含前置编译、最终报告保存和终端显示。优化版 C 编译与链接另用 65.409 秒，本次生成复用构建，没有重复编译。

## 为什么优先优化矩阵乘法

Dense 是模型中与固定权重相乘的计算，用于注意力投影和 MLP。单独分段测量时，它在首次前向中用时 **214.688 秒，占 82.94%**；加上 Attention 和词表输出层的矩阵乘法，相关区间合计占 **88.78%**。因此，减少这部分计算最有机会明显缩短首次前向。

这些是另一次分段测量中首次前向内部的占比，包含相应检查和同步，不与上表的时间相加。

## 后续先做什么

1. **先减少 Prefill 的无效计算。** 当前只有 5 个有效输入 token，却计算了 256 个位置。短 Prefill 小模型实测加速 10.097×；下一步验证完整模型的收益，不能直接套用这个倍数。
2. **再优化 Dense。** 缩短 Prefill 后重新测量，确认矩阵乘法还占多少，再针对内层计算和权重读取优化。
3. **较长文本重点排查 Decode 的重复检查。** 单次诊断中，入口检查用时 2.130 秒，占该次 Decode 的 41.81%；先拆分检查内容，再决定哪些能在会话启动时只做一次。该次 Decode 的完整 Attention 仅占 1.36%，继续优化它的整体收益较小。

优先级依据本次耗时和可减少的工作判断。后两项仍需测量；上述 Decode 内部比例来自一次独立诊断，不代表所有输出长度。
