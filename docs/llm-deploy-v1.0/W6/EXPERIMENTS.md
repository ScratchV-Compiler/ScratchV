# W6 · 四核 QEMU 性能与数值对照

## 本分支增加了什么

W6 在 W5 已能生成文本的基础上，优化一次模型前向。Qwen3-0.6B 可以按词表分块计算最后一层（LM Head），还可以让 QEMU 直接从临时文件映射权重所在的内存。两项都需显式启用。原末层、原装载方式、默认单核以及手动和自动选核均保留。W6 小图实验另提供 Attention 三算子融合入口，使用同一输入衡量耗时和工作区容量。

## 实际复现结果

本机 Ubuntu 24.04 / WSL2，基线提交 `a99d035`，含本地 W6 改动。以下对照固定 4 核、FP32、QEMU 8.2.2，工作区 padding 关闭。常规标量实验使用 RV64GC。标量与 RVV 短循环对照统一开启 RVV 1.0，向量寄存器宽度为 256 位。

### 成对读取 Q 的两个相邻元素

**减少加载指令没有带来稳定的前向加速。** 同样将 K 循环展开两步，一次读取两个 Q 元素在首批少用 17.30 毫秒，交换顺序后多用 8.19 毫秒。两批按配对胜次分别为 7/10 和 6/10，但第二批较慢的轮次抵消了其他轮次的收益。保留为实验选项。

| 实现 | 第一批前向（毫秒） | 相对原始 1×4 | 第二批前向（毫秒） | 相对原始 1×4 |
| --- | ---: | ---: | ---: | ---: |
| 原始 1×4 | 344.43 | 1.000× | 342.61 | 1.000× |
| 5×4 有界直接写回 | 277.41 | 1.242× | 261.05 | 1.312× |
| 同一 5×4，展开两步，逐个加载 Q | 279.12 | 1.234× | 260.22 | 1.317× |
| 同一 5×4，展开两步，成对加载 Q | 261.82 | 1.316× | 268.40 | 1.276× |

两批使用种子 4108 的同一张四核 FP32 小图，保持八块分工、K 面板和有界写回方式。每组预热一次、正式运行十次，轮换运行位置，保留所有慢轮。表中为 QEMU 启动至 UART 完成的实际经过时间中位数。成对加载距离各自同批的 1.5× 目标分别还差 32.20 和 39.99 毫秒。

**为什么要有展开对照。** 两种新实现都先完成第 k 步，再完成第 k+1 步；只有 Q 的读取方式不同。5×4 主块每两步均执行 40 条 FP32 融合乘加。对齐时，成对版的加载从 18 条变为 13 条，同时增加 10 条寄存器传送和 5 条位移。计入最后一行，整图热循环加载从 60,817,408 减至 44,040,192 条（减少 27.59%），总指令从 205,258,752 增至 238,813,184 条（增加 16.35%）。两种主循环都没有栈访存，实际读取的 FP32 数量相同。

**数值与对齐。** 两批 110 次正常前向都逐位核对全部 1,048,576 个分数，与原图 ORT 参考的最大绝对误差为 0。实际 RV64 ELF 在 Q 地址为 `0x88000004` 时也执行成功，完整输出逐位一致。该地址满足原 ABI 的 4 字节对齐要求，内核自动使用普通加载。另有 8 次特殊输入与原 4×4 的位模式一致，6 次尾行溢出均返回状态 2 并回收 QEMU。

<details>
<summary>哪些输入可以直接写回，以及怎样保护错误输出</summary>

- **省去最终复制。** 已有 ABI 在计算前检查缓冲区容量、地址对齐和重叠。若所有 Q、K 的绝对值都不超过 2³²，每个乘积至多为 2⁶⁴。第 j 次累加的上下界 ±j·2⁶⁴（j ≤ 128）均可用 FP32 精确表示，舍入保持该界限，因此中途和最终结果都有限。此时直接向调用方输出写入，保留原有的逐分数检查和零符号处理，省去 4 MiB 最终复制。ABI 仍要求提供 4 MiB 工作区。
- **一并省去逐分数写回检查。** 当全部输入绝对值都在 [2⁻³⁰, 2³²] 且裸机使用最近偶数舍入时，每个输入均为 2⁻⁵³ 的整数倍。每次乘加的未舍入值以及舍入后的结果均为 2⁻¹⁰⁶ 的整数倍。非零结果无法下溢为负零，精确抵消产生正零。因此可以直接保存原先 128 次有序 FP32 融合乘加得到的值。任何不满足条件的有限输入都回到原检查与复制路径，NaN 或无穷仍上报错误。[浮点舍入的单调性与精确性](https://flocq.gitlabpages.inria.fr/theos.html)
- **实际核对。** 本机用 ±2³²、相邻的超界值、正负零、次正规数和精确抵消核对两条写回路径。使用刚好得到 −2⁻¹⁰⁶ 和 +0 的输入检查了输出位模式。另用尾行溢出和最后一个 K 为 NaN 检查失败时调用方的输出保持原值，同一工作区随后可以复用。

</details>

### 同一段 Attention 乘加的标量和 RVV 对照

**本机 QEMU 上，RVV 一次算满 8 个 FP32 元素，仍慢于同宽标量。** 4×8 的两批试验中，RVV 每分分别多用 43.88% 和 29.85%。进入整张小图的条件是两批 RVV 耗时中位数都更低，且各自超过半数的配对更快。本轮保留标量，独立 Attention 相对原始 1×4 的 **1.5×** 目标仍未达到。

| 块大小及批次 | 标量（纳秒/分数） | RVV（纳秒/分数） | 标量耗时 ÷ RVV 耗时 | RVV 更快的配对 |
| --- | ---: | ---: | ---: | ---: |
| 4×8，第一批 | 252.96 | 363.96 | 0.695× | 0 / 8 |
| 4×8，第二批 | 236.28 | 306.80 | 0.770× | 3 / 8 |
| 4×4，此前第一批 | 226.80 | 314.46 | 0.721× | 1 / 8 |
| 4×4，此前第二批 | 204.76 | 273.85 | 0.748× | 2 / 8 |

**每分用时怎么算。** 先在当前 QEMU 进程内预热，再由主核用 10 MHz 的 `rdtime` 从分发任务计到四核全部完成。4×8 每核处理 64 个块，四核共 256 块，每块 32 个分数，重复 16 遍。表中每分用时等于这段实际经过时间除以 131,072，此前 4×4 的分母为 65,536。两批 4×8 标量的计时中位数为 33.16 / 30.97 毫秒，RVV 为 47.70 / 40.21 毫秒。每批交替运行 8 对，第二批交换起始顺序，加速比只在同批同宽内计算。模拟器启动、输入准备、预热和转储都在计时之外。

**是否真的用了 8 个元素。** 同一份 ELF 通过输入参数选择标量或 RVV。36 次运行中，四个核在预热时和计时循环后读回的向量长度都为 8。两组每步先读取同一组连续的 8 个 K 值，再按行读取同样的 4 个 Q 值。每个分数依次做 128 次 FP32 融合乘加，最后加正零，按行写回。反汇编中每步标量执行 32 条 `fmadd.s`，RVV 执行 4 条八元素 `vfmacc.vf`。

4×8 标量同时维护 32 个累加值，其中 10 个用通用寄存器保存 FP32 的原始位，每步增加 20 次寄存器间传送。两组内层循环都没有栈访存。表中包含这项实际成本，指令数量无法直接换算为耗时。结果适用于本机 QEMU 8.2.2 与该块形状，真实 RVV 芯片的吞吐需单独测量。

**数值结果。** 4×8 的 32 次正式运行和 4 次批次预热共核对 4,718,592 个 FP32 输出，覆盖原图 8,192 个不同位置。全部与 ONNX Runtime 逐位一致，最大绝对误差为 0。另从此前保存的完整 Attention 分数矩阵抽取相同位置，再次逐位复核每次 QEMU 转储的输出，结果相同。

### Attention 组合图的耗时与工作区

直接用原布局的 K 计算分数，并在每两行算完后立即执行 Softmax，两批整图前向分别加速 **1.081×、1.068×**。所需工作区从 **10 MiB 降至 4 MiB（减少 60%）**。独立矩阵乘法仍按上表的 1.5× 目标单独验收。

| 实现 | 第一批前向（毫秒） | 复测前向（毫秒） | 工作区 |
| --- | ---: | ---: | ---: |
| 逐算子执行 | 444.86 | 444.61 | 10 MiB |
| 按行融合三算子 | 411.68 | 416.31 | 4 MiB |

输入为两个运行时 FP32 张量 Q、K，形状均为 `[16,256,128]`。计算 `Softmax(Q @ Transpose(K), axis=-1)`，其中转置排列为 `[0,2,1]`，输出 `[16,256,256]`。逐算子版在同一个 QEMU 进程内依次运行三个算子。两组均固定 4 核、padding 关闭，使用相同的 2×4 乘加、K 轴累加顺序、`fp32-reference` Softmax 和最终输出复制。

- **省掉 K 的整张转置。** 直接从 K 的四个原始行读取乘加所需的值，省去转置时读 K、写 Kᵀ 各 2 MiB，以及对转置结果的 2 MiB 有限性扫描。原始输入仍在入口检查。
- **省掉独立的分数数组。** 两行分数先写入概率工作区对应的位置，写回时检查有限性，省去一次 4 MiB 的分数扫描。Softmax 仍逐行读取分数、计算最大值和指数，再在原位归一化。全部核成功后，两种实现都把 4 MiB 最终概率复制给调用方。

按生成代码消除的整段遍历计，每次少 **8 MiB 读取、2 MiB 写入**。实际内存总线流量受缓存影响。逐算子工作区中 Kᵀ、分数和概率的起始偏移分别为 0、2、6 MiB。融合只需概率工作区，每核每次临时放两行分数（2 KiB），四核最多同时使用其中 8 KiB，这部分已计入 4 MiB。工作区容量由构建布局核对，输入、调用方输出和两组各自预留的 4 MiB 四核栈另计。

- 实验入口为 `--attention-inner-loop rvv`。默认使用标量实现。RVV 候选目前限这张固定形状小图，在实际 RISC-V 芯片上的速度需实测。

## 整体怎么实现

- **Dense** 的右矩阵是常量。构建时把相邻列整理在一起，运行时可连续读取。**Attention** 的 Q、K 都是输入，必须在每次前向时处理。本次分数小图还比较了成功后的返回复制。默认实现保留。
- **LM Head** 与输入 Embedding 共用同一份权重。可选实现每次按小块读取词表，在各个输入位置复用，省去 593.5 MiB 的完整转置工作区。输出仍含每个位置的全部词表分数。
- **QEMU 权重装载**。原方式用 QEMU 的 `loader` 写入模拟内存。Linux 上可选 `file-backed-ram`，先把权重放到稀疏文件里的指定位置，再由 QEMU 私有映射整段内存。模拟程序能正常写内存，原权重保持只读。该选项只改变 QEMU 的运行环境。大内存模型上，QEMU 复位时写入的设备树可能跨进权重区。启动前先让同配置的 QEMU 保持暂停并查询实际地址，再从只读权重中恢复重叠字节。
- **数值校验**。主控用相同输入在 ONNX Runtime（ORT）CPU 上计算参考，检查输出形状、有限性、对 ORT 的最大绝对误差 `< 0.001`，并核对每行最高分 token。

生成器在张量最后一次使用后回收工作区，供后面的张量复用。本次分块版完整图的 5,712 个中间结果用了 73 个不同的工作区起始地址。原末层和分块末层的构建工作区分别为 758.25 和 164.75 MiB，差额来自省去共享权重的整表转置。[工作区分配实现](../../../scratchv/backend/tensor_c_codegen.py)

## 如何复现

先完成 [Linux 环境准备](../LINUX_REPRODUCTION.md)，在仓库根目录运行。仅运行后面的完整模型或独立末层时，`MODEL_DIR` 指向包含 `model.onnx` 和真实权重分片的目录。每次选择新的输出目录。

复现 Q 成对加载对照时，命令会同时测原始 1×4、专项 4×4、有界直接写回和两种展开方式，在 `result.json` 中保存逐轮耗时与完整输出的位差。

```bash
python -B -m probes.w6_performance.run --attention-scalar 5x4-bounded-output 5x4-q-unroll2 5x4-q-pair --output-dir output/w6-q-pair-repeat
```

复现逐核计时时只需固定小图的输入，环境需有四个可用逻辑 CPU、`nm` 和 `libfdt`。第一条命令分别运行低扰动、列块和行块三级计时。第二条单独测四核真实 WFI 时间，各自的 `result.json` 保留原始计数和每轮的耗时。测实际加速比请使用下方无插桩命令。

```bash
python -B -m probes.w6_performance.attention_kernel_profile --output-dir output/w6-kernel-profile-repeat
python -B -m probes.w6_performance.attention_worker_wait --output-dir output/w6-kernel-wait-repeat
```

复现输入范围和写回的对照时，下列命令会自动加入原始 1×4 和专项 4×4，使用同一份 ORT 参考。加上 `3x8 2x8 5x4-static` 可测标量分块与固定分工。

```bash
python -B -m probes.w6_performance.run --attention-scalar 5x4-bitwise 5x4-bounded-output 5x4-normal-output --output-dir output/w6-score-writeback-repeat
```

标量 / RVV 短循环只需四个可用 CPU、支持 RVV 1.0 的 QEMU、`nm` 和 `libfdt`，输入由程序生成。`--columns 8` 测 4×8，默认值 4 测 4×4。命令会在同一 ELF 上运行两批，`result.json` 给出每分耗时和对 ORT 的位差，各轮目录保留完整输出、逐核计时、向量长度和实际 QEMU 参数。

```bash
python -B -m probes.w6_performance.attention_matched --columns 8 --output-dir output/w6-matched-4x8-repeat
```

复现本轮独立 Attention 的两项复测时，下面的命令各自包含原始 1×4、专项 4×4 和已有 5×4，并核对全部输出。初筛的另外三个选项为 `6x4-cached`、`5x4-first-pack`、`5x4-preboxed-k`。结果写入各自的 `result.json`。

```bash
python -B -m probes.w6_performance.run --attention-scalar 5x4-cached 5x4-bitwise --output-dir output/w6-writeback-repeat
python -B -m probes.w6_performance.run --attention-scalar 5x4-cached 5x4-paired-bitwise --output-dir output/w6-paired-writeback-repeat
```

复现 5×4 加缓存写回的独立对照时，以下命令同时运行原始 1×4 和专项 4×4。将候选参数换为 `5x4 4x4-cached` 可复现两项单独改动，换为 `5x4-cached 5x4-cached-claim-panel` 可复现两种 K 面板的对照。

```bash
python -B -m probes.w6_performance.run --attention-scalar 5x4-cached --output-dir output/w6-scalar-repeat
```

复现输入有限性检查对照需要四个可用 CPU、`nm` 和 `libfdt`。以下命令仅使用程序生成的 Attention 小图输入，`result.json` 保存扫描分项、整图前向和异常输入结果，`runs.jsonl` 保存逐次正常运行。

```bash
python -B -m probes.w6_performance.attention_input_profile --output-dir output/w6-attention-input-repeat
```

复现 4 / 8 / 16 块分工对照时，使用已有分段计时入口。命令先执行无插桩测量，再执行诊断批次，结果写入 `result.json`、`runs.jsonl` 和各轮的 `per-core.bin`（仅诊断）及 `output.bin`。

```bash
python -B -m probes.w6_performance.attention_profile --claim-granularity --output-dir output/w6-claims-repeat
```

本地专项只跑 Dense 和独立 Attention 小图，再检查同批数据。每种实现预热 1 次、正式 3 次；本地未提交修改也参与构建，报告中的提交号表示工作树基线。Attention 未达 1.5× 时第二条命令返回 1，不要把退出码忽略。

```bash
python -B -m probes.w6_performance.run --compare-candidates --output-dir output/w6-small-repeat/matmul
python -B scripts/check_w6_ci.py --run-dir output/w6-small-repeat --commit "$(git rev-parse HEAD)" --mode small
```

复现三算子组合图时，在新的输出目录运行以下命令。入口构建同一张图的两种实现，生成同一份输入和 ORT 参考。`result.json` 记录速度和工作区，`runs.jsonl`、各轮 `output.bin` 与 `ort.npy` 可用于复查。

```bash
python -B -m probes.w6_performance.attention_chain --output-dir output/w6-attention-chain-repeat
```

独立 Attention 矩阵乘法对照使用程序生成的输入，无需模型权重。以下入口依次比较原始 1×4、此前最快标量、融合输出检查，以及融合检查加并行复制。结果写入 `result.json` 和各轮的 `output.bin`。

