### 3.1 本次新增时长记录的读取与边界

运行 `probes/w2_qwen3_small/riscv.py --model-dir <本轮小模型目录> --output-dir output/qwen3-riscv` 后，读取该输出目录的 `report.md/html/json`。`report.timing` 记录 `pipeline_seconds`、`cross_compile_seconds_total`、`qemu_process_wall_seconds_total`，`groups` 区分 normal/diagnostic 与 none/all；每次执行记录 `qemu_process_wall_seconds`，保留 `seconds` 兼容字段。交叉编译汇总仅含已记录的成功构建，不含 ScratchV 解析/优化/生成 C 或失败构建耗时，须同时核对构建完成数。

数值成功/失败、运行失败、超时、已尝试但未启动、尚未尝试等状态应与时长一起查看。QEMU 进程墙钟包含启动、guest 计算、输出打包/UART 和退出；超时还包含子进程清理，不含 host 输入准备/输出解码，不是纯 forward 计时；流水线时间不含最终报告渲染。失败保留已测耗时，无测量为 null；未启动不能记成零秒成功，汇总不能把未完成的尝试写成 28 次通过。CI Summary 展示相同 Markdown 数据，原始 JSON/HTML 随 artifact 保留。当前不据此给出加速比或性能通过结论。

## 4. 留待决定或后续实施

### 4.1 优先决定：优化能否消除未使用算子的数值错误

证据：`output/tensor-review-dce-error-contract.json`。输入1，图中先执行未使用的除零，再返回`输入+1`：

- `none`：IR解释器抛出NumericError。
- `basic/all`：DCE删除除零，返回2。

当前DCE文档把无用纯计算视为可删除，而解释器/新后端提供运行时数值错误。这两种语义尚未明确协调。本轮没有全面禁用DCE，也没有把现象标为已修复。

需要E2/E3/E5选择并记录：

1. 错误属于可观察行为：给可能失败操作定义effect/安全判定，并同步DCE、LICM、常量折叠的规则和回归。
2. 只保证被使用结果的语义：明确允许删除无用计算的错误，调整文档及不同优化级别的错误验收范围。

推荐先决定契约，再实施一致修复；不能只对一个除零case打补丁。本次Qwen探测未触发这一差异。

### 4.2 通用Pow语义覆盖

tensor-c对整数底数的负/浮点指数，以及FP32底数配绝对值大于2**24的整数指数，支持范围仍比解释器更严格，会显式拒绝部分输入。
本次固定Qwen图使用指数2，不构成W1模型阻塞。若下一阶段要求通用算子全覆盖，应先明确dtype/指数契约，再扩实现和边界case。

### 4.3 完整模型仍需独立工程工作

- 代码与权重分离：当前C常量展开和256 MiB常量上限不能承载约2.22 GiB完整权重。
- 内存与输出：512 MiB guest、链接布局、静态arena、约148.4 MiB logits及UART传输须统一设计；不是只改一个容量参数。
- 完整规模数值：中等配置、真实维度/预训练子图、完整28层及词表的IR/QEMU验证尚未完成。IR解释器复制权重和保留中间值的内存成本也要测量。
- 历史完整导出 padding 位置的 PyTorch/ORT 差异仍待定位；对已有产物执行 verify 不会重新评判该差异。
- Tokenizer、最后有效位置logits、greedy/EOS/上下文容量、token循环需要运行时集成。
- MatMul分块、减少张量物化、融合和传输优化应有性能基线与数值回归；当前没有新增性能加速结论。

这些工作不能由两层随机小模型的成功替代。KV Cache、动态长度、量化和RVV仍属后续版本。
