## 1. 当前执行配方与证据格式

新部署探测使用 `qemu-system-riscv64 -machine virt` 裸机、RV64GC/LP64D、TCG，启动/链接脚本由 `scratchv/runtime/riscv_tensor.py` 生成。Zig 0.14.1 的 `zig cc` 编译显式张量循环 C，数学函数来自随附 musl，禁用 fast-math/FMA。输入用 QEMU raw loader，输出用带状态、长度、校验和及结束标记的 UART 二进制帧；损坏帧、trap、超时和非零状态均失败。

原稿的 RV32 Linux user-mode 配方（`clang --target=riscv32-linux-gnu`、`qemu-riscv32`、ecall write/exit）仍可解释旧 standalone 测试，但**不是本次 Qwen 路线**。不要把两套启动/ABI混用。使用 Linux-musl 编译目标来链接数学库不表示 guest 中存在 Linux。

每次探测保留实际命令、退出码、报告、源码/模型/输入/ELF指纹、工具版本与错误详情。独立复現者使用新的空输出目录；不能复用第一人的已生成数组代替自己的参考计算。生成产物默认在忽略的 `output/`，报告不随 Git 自动发布。

## 2. FP32 MatMul：原假设与新路线结果

### 2.1 原探测保留的结论

| 原假设 | 当前解释 |
|---|---|
| H1：旧 `_select_matmul` 只 emit 标量整数 MUL | 旧路径缺口未被新 tensor-c 修复或推翻 |
| H2：旧选择器缺张量 FP32 lowering | 助记符存在不等于张量实现；新路径由C编译器生成浮点机器码 |
| H3：原路径的RV32/RV64及ABI混用 | 新路线明确RV64GC/LP64D；不据此声明所有旧路径都统一 |

原计划要求如实记录失败，不为绿色临时绕过。本次提供了可审查的新后端实现及对照回归，应明确记作**路线变更**，不能把旧selector写成已通过原探测。标准张量编译入口应拒绝交给不具备相应语义的旧后端。

### 2.2 现行步骤与门槛

`probes/w1_matmul_4x4/run.py` 构造固定输入 ONNX，运行 ORT，经 `CompilerDriver(backend="tensor-c", optimize_level="all", verify_ir=True)` 生成 C、构建 RV64 ELF、启动 QEMU并比较。7用例含4×4小数、projection、attention、双侧批次广播、vector_dot、matrix_vector、vector_matrix。shape/dtype/有限值须一致，`max_abs < 1e-5`，`rtol=0`。

## 3. 两层 Transformer 与真实 Qwen3 小配置

### 3.1 原合成图的作用

`probes/w1_tiny_transformer/run.py` 使用 PR89 的两层合成模型执行 ONNX/ORT/IR 数值检查。这是原 `probe:small-transformer`，不要求经过 RISC-V。该图没有 Q/K RMSNorm，使用 partial RoPE，因此不能单独验证官方 Qwen3 的完整结构语义。

原草案 H4“必须新增融合 IR 节点才能表达注意力”不成立：当前基础算子图已能执行。H5基础算子表达Attention经实测支持；旧selector的handler缺失不等于IR解释器不能表达。IR解释器已经存在，循环/分支由专门测试覆盖；不再将它列为缺失依赖。

### 3.2 官方实现的小配置

使用固定 `transformers==4.51.3` 的 `Qwen3ForCausalLM`，固定seed随机权重。layers=2、hidden=32、intermediate=96、heads=4、kv_heads=2、head_dim=16、vocab=128、L=256、FP32、eager、无KV Cache。Q投影宽度64刻意不等于hidden32。

模型保留 Q/K RMSNorm、**全 head_dim RoPE**、GQA、SwiGLU、residual、tied embeddings。通过官方forward上的观察器取得29个检查点，另与没有观察器的官方forward核对logits，防止观测改变计算。诊断图以 `trace_pack` 单返回拼接全部检查点，同时保留ORT命名输出；普通图单独输出logits。

7输入覆盖全长两seed、有效长度1/17/255、修改未来token、修改padding token。完整256个位置均验shape/dtype/有限值与严格 `max_abs < 1e-5`（`rtol=0`），同时分别记录有效/padding位置误差。独立NumPy检查GQA头映射、probabilities/context与mask泄漏。

### 3.3 编译优化与QEMU扩展

`run.py` 验 PyTorch/ORT/IR；`riscv.py` 从其同一模型目录读取普通/诊断图，走实际CompilerDriver，检查none/basic/all优化后的IR；none/all各生成ELF并分别执行7输入。

## 4. 完整 Qwen3 ONNX 导出

### 4.1 核心门槛与输入

固定官方 `Qwen/Qwen3-0.6B` revision，FP32、L=256、无KV Cache，opset18。输入是 `input_ids: INT64 [1,256]` 和 `attention_mask: FP32 [1,1,256,256]`，mask为加性causal+padding，position_ids固定0..255。必须成功导出、保存真实权重分片，且ORT能产生有限的 `[1,256,151936]` logits。

这是完整模型的ONNX/ORT门槛，不要求本项同时完成完整IR/QEMU推理。只检查protobuf或只运行两层小图不能完成此门槛。

### 4.4 仓库门禁

`probes/w1_qwen3_export/run.py` 是统一门禁入口，具体命令见独立复现指南。PR运行该入口的轻量回归测试；手动/定时工作流的独立 `full-qwen3-onnx` job 用download模式验证固定发布产物并真实执行ORT两case。PR的轻量测试不替代完整ORT执行；PR中重型job未执行应如实显示。入口各模式均检查哈希、结构并运行ORT，缺权重/分片、哈希不符或执行失败时非零退出，不能以“尚未交付”成功退出。

固定revision、模型/分片哈希、输入seed/有效长度、输出shape/dtype/有限值、provider/线程数和实际执行状态写入报告。源码版本另由复现记录中的checkout commit与CI run关联，不能假称当前完整模型报告已记录源码哈希或完整输出数组。历史 `verification.json` 只作来源说明，不能作为新运行的成功标志。
