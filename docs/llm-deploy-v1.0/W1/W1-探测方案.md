## 1. 通用配方

### 1.1 编译 + 链接 + 执行（照抄，来自 `tests/test_standalone_execution.py:84`）

```bash
clang --target=riscv32-linux-gnu -march=rv32im -mabi=ilp32 \
      -nostdlib -static -fuse-ld=lld -Wl,--no-relax \
      execute.s -o execute.elf

qemu-riscv32 ./execute.elf
```

### 1.2 数据往返的诀窍

不要试图读文件——现有测试的做法是让 RISC-V 端用 `ecall` 把内存 **dump 到 stdout**，Python 侧解析：

```asm
# 写：a7=64 (write), a0=1 (stdout), a1=缓冲区, a2=字节数
li a0, 1
la a1, dump_start
li a2, <total_bytes>
li a7, 64
ecall

# 退出：a7=93 (exit), a0=退出码
li a0, 0
li a7, 93
ecall
```

Python 侧用 `subprocess.run([...], capture_output=True)` 拿 `stdout`，`struct.unpack` 解析。

**验证建议**：在缓冲区前后各留 `guard_bytes`（如 256 字节）空洞，断言 guard 区全零——能抓到越界写。现有测试就是这么做的。

## 2. 探测 1：`probe:qemu-matmul`

### 2.1 目的

打通 **IR → RISC-V 汇编 → 链接 → QEMU 执行 → 数值比对** 的完整链路。这是 W1 所有后端工作的地基。

### 2.2 预期（静态勘察结论，待证实/推翻）

| 假设 | 依据 | 预期结果 |
|---|---|---|
| **H1**：`MATMUL` 被降级成一次标量整数乘，不是矩阵乘 | `instruction_select.py` 的 `_select_matmul` 只 emit 一个 `MUL` | 4×4 结果**错误** |
| **H2**：后端不产生 FP32 指令 | 全后端 0 处 emit `FMUL_S/FADD_S` | 输出为整数，或编译报错 |
| **H3**：IR→asm 路径的 ISA 是 RV32 | `MachineOp` 只有 `LW/SW`，无 `LD/SD` | 用 rv32 工具链可编译 |

> ⚠️ **如果 H1 成立，本探测第一轮就会失败**——这是**预期内的失败**，正是要发现的。请如实记录，不要为了"探测通过"而临时打补丁绕过。

### 2.3 步骤

1. 构造 4×4 输入矩阵 A、B（固定值，便于手算核对）
2. 写一个最小 ONNX（或直接用 `IRBuilder` 手工构造 IR `MATMUL`）
3. `scratchv` 编译 → `.s`
4. 按 §1.1 链接、QEMU 执行
5. 与 numpy `A @ B` 比对

### 2.4 判定标准（计划 §4.3）

**误差 < 1e-5**。若 R1/H1 成立导致失败，判定为 `失败（发现 R1 确认）`，并**立即上报**——它会改变 W2 的工作量估算。

## 3. 探测 2：`probe:small-transformer`

### 3.1 目的

确认 **IR 能否表达一个完整的 Transformer 层**（RMSNorm / RoPE / SwiGLU / GQA + 因果掩码）。

### 3.2 预期

| 假设 | 依据 | 预期结果 |
|---|---|---|
| **H4**：IR 缺 RMSNorm/RoPE/SwiGLU/GQA 节点 | `OpCode` 28 个取值里没有 | 探测**必须新增 IR 节点**才能跑通 → 记为本探测的**产出**而非失败 |
| **H5**：`ATTENTION` 可用基础算子拼出 | IR 有 `MATMUL`/`SOFTMAX`/`TRANSPOSE` | 需先确认 `TRANSPOSE` 可用（见 H6） |
| **H6**：`TRANSPOSE`、`CONCAT` 不可用 | 二者在 `instruction_select.py` 无 handler | 若走**解释器**路径可能可用；走**后端**路径必然报错 |

> **关键区分**：本探测的判定是"**IR 解释器** vs ORT"（计划 §4.3 原文），**不要求**走 RISC-V 后端。所以 H6 未必阻塞本探测——这正是把探测 2 与探测 1 分开的价值。

### 3.3 步骤

1. 用 PyTorch 搭 2 层 TinyTransformer（hidden 小、头数小），导出 ONNX，`dynamic_axes=None`
2. 跑 ORT，保存各层激活与最终 logits 作为参考
3. 走 ScratchV `ONNXParser → IR`，用 **IR 解释器**执行
4. 逐算子/逐层比对

### 3.4 判定标准（计划 §4.3）

**误差 < 1e-5**。

## 4. 探测 3：`probe:qwen3-onnx`

### 4.1 目的

确认 Qwen3-0.6B 能导出为 ONNX，且 ORT 能跑出正确形状的 logits。**这是 W3 硬门槛的基准来源。**

### 4.2 步骤

1. 拉取 Qwen3-0.6B 权重（**固定 revision**，记录 commit hash 与校验和 → 风险 R19）
2. `torch.onnx.export(..., dynamic_axes=None, opset=<版本>)`
3. 输入固定 `input_ids=[1,256]`、`attention_mask=[1,1,256,256]`
4. ORT 执行，记录：
   - 输出形状是否为 `[1,256,151936]`
   - 峰值内存 / 耗时
   - 生成文本是否连贯（贪心解码，跑几句看）

### 4.3 判定标准（计划 §4.3）

ONNX 导出成功；输入 `[1,256]`；输出 `[1,256,151936]`；**ORT 可执行**。
