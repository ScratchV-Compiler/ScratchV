https://github.com/ScratchV-Compiler/ScratchV/blob/2d07ccc42936dcfde19d552bca02a324cd33821c/docs/llm-deploy-v1.0/W1/算子补齐与单测报告.txt
原始平台、计数、计时和数值不改名为 Linux 数据；新结果必须由下面的 Linux 命令重新生成。

一、实现范围

ONNX 前端 → 共享 IR → NumPy 解释器覆盖两组算子：
1. PR #89 探测图：Gather、Sqrt、ReduceMean、Transpose、Concat、Slice、Unsqueeze、Expand。
2. 真实 Qwen3 导出额外需要：Abs、Cast、Constant、Cos、Identity、Pow、Reciprocal、Sin。
第一组复用已有 IR 与内核，补前端/边界；第二组新增 ABS、CAST、COS、SIN、POW、RECIPROCAL，Constant 使用绑定，Identity 复用输入值。

语义修复包括零维标量与向量区别、INT64 精度、静态 shape/axis 参数链、外部权重和 Constant、FP32 常量舍入、临时值命名冲突、静态求值规模限制、Cast 截断/溢出、Pow 广播与整数精度，以及 Slice 的反向边界和 INT64 哨兵。前端不将中间值伪装为 initializer。

二、验收用例

tests/test_onnx_shape_ops.py：八类形状/索引算子，ORT 对照、边界和非法参数。
tests/test_onnx_qwen_numeric_ops.py：数值算子、常量、静态参数链及 RMSNorm 组合。
tests/test_ir_qwen_numeric_ops.py：IR 类型、广播、整数精度与错误定位。
tests/test_onnx_constant_regressions.py：FP32 舍入、整数宽度、名字碰撞、求值规模。
tests/test_onnx_operator_benchmark.py：基准自身的身份、正确性及失败传播。
实际 passed/skipped/failed 以本次 Linux 输出为准，不沿用历史计数。

三、Linux 环境与资产准备

以下为 Bash，已存在环境时可复用，但必须核对依赖版本。benchmark 使用单独环境，以保持历史前后对照依赖；它不替代完整模型门禁的固定导出环境。

set -euo pipefail
sudo apt-get update
sudo apt-get install --no-install-recommends python3.12-venv git-lfs
python3.12 -m venv .venv-operators
source .venv-operators/bin/activate
python -m pip install "numpy==2.5.3" "onnx==1.23.0" "onnxruntime==1.29.0" "pytest==9.1.1"
python -m pip install --no-deps -e .
python -m pip check
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
export NUMEXPR_NUM_THREADS=1

git rev-parse HEAD
git status --short
git fetch origin 20b105e80ba3dbe13cb01a3d4ca18c32b6c31ed6
git lfs install --local
git lfs pull --include="probes/w1_tiny_transformer/out/tiny_transformer_2l.onnx"

基线为固定提交 20b105e80ba3dbe13cb01a3d4ca18c32b6c31ed6，不能用不同分支 HEAD 代替。浅克隆必须补齐历史。原模型 SHA256 应为 17a8f191ee65a9d97143131016058e8a3c10a7d5c06e8152bf16dd8941cd19e1，不可把 LFS pointer 当 ONNX。

四、生成修改前后 benchmark

python -X utf8 -B -m benchmarks.bench_onnx_operators \
  --baseline-ref 20b105e80ba3dbe13cb01a3d4ca18c32b6c31ed6 \
  --output-dir benchmark_reports/onnx_operators-linux-01 \
  --warmup 1 --repeats 5

每轮选择新的输出目录。CLI 生成自己的 fixtures、参考和 JSON/Markdown/HTML 报告，不读取 docs 目录中的历史索引作为测量。源码、模型、输入、环境身份与错误详情由新报告保存。

24 个固定用例包含 16 独立算子、2 已支持的对照、2 错误回归和 4 组合链路，含原 PR #89 两层 Transformer。ABBA 顺序比较修改前/后，每版本两轮；前后都通过的用例才计算耗时比。不支持、失败或缺测不能解释为零耗时或无限加速。

IR.run 计时包含验证、执行规划、绑定复制、NumPy 计算与返回复制；ONNX 解析单独计时，ORT 参考不计入。此基准验证支持与正确性变化，不证明 QEMU 性能改善。重新生成的 Linux 样本不可与不同平台的历史耗时直接算加速比。

六、范围与后续门禁

这是静态图和 FP32 所需前端/IR 能力，同时覆盖现有 FLOAT64、INT32、INT64；不宣称全部 ONNX dtype/opset 或动态 shape/axis。Reshape allowzero=1 等不支持语义明确拒绝；非法定义域、非有限值及部分整数溢出明确报错。当前固定 Qwen 图使用 FP32 底数与整数指数 2；通用 Pow 范围需要分别验证。

完整 28 层解析、真实两层 Qwen3 数值与 RV64/QEMU 分别从 W1/README.md、W2/README.md 和 probes/w2_qwen3_small/README.md 进入；基础算子 benchmark 通过不能代替这些门禁。

同目录 benchmark.md 为 Linux 复跑入口，benchmark.html 为可打开的指引，benchmark.json 为明确标识的历史索引，不包含新测量。原始完整测量保留在固定提交历史中。
