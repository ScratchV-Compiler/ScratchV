一、完成范围

完成 ONNX 前端 → 共享 IR → NumPy 解释器路径所需的两组算子：
1. PR #89 探测图八类：Gather、Sqrt、ReduceMean、Transpose、Concat、Slice、Unsqueeze、Expand。
2. 真实 Qwen3 导出图额外八类：Abs、Cast、Constant、Cos、Identity、Pow、Reciprocal、Sin。
第一组复用已有 IR 算子与内核，补齐前端和边界测试；第二组新增六个 IR opcode，Constant 绑定为全局常量，Identity 复用输入值。

二、本轮代码改动

scratchv/frontend/onnx_parser.py
- 补齐第二组前端映射；支持 Constant 的 tensor、value_int/value_ints、value_float/value_floats。
- 保持零维标量、单元素向量与 INT64 值的区别，支持外部权重及 Constant 外部数据。
- 求值 Constant → Cast/Abs/Reshape 等静态 shape/axis 链，适配真实 Qwen3 导出形式。
- 不将中间结果冒充 initializer；限制静态参数求值规模，避免超大 Expand 与尺寸乘积溢出。
- Add/Mul 统一发出 IR，修复 Python 标量折叠造成的 FP32 舍入与整数宽度错误。
- 预留全图 v_N 名字，修复 ONNX 原始名字和临时结果名碰撞。
- 明确拒绝当前 IR 不支持的数据类型。

scratchv/ir/types.py、scratchv/ir/builder.py
- 新增 ABS、CAST、COS、SIN、POW、RECIPROCAL 及 builder 方法。
- Cast 的结果 dtype 表示目标类型；Pow 允许底数与指数类型不同，结果保持底数类型。

scratchv/analysis/ir_verifier.py
- 增加新算子签名、浮点算子类型约束和 Pow 输出类型校验。

scratchv/verification/ir_numpy_ops.py
- 增加新算子的实际 NumPy 求值和数值错误诊断。
- Cast 整数缩窄保留低位；浮点转整数按截断后范围检查，避免 INT64 边界错误。
- Pow 支持广播、混合类型以及有界的精确整数计算。
- Slice 使用 ONNX 的正反向钳制规则，修复过小负 start 的反向切片，并处理空维和 INT64 哨兵。

五、支持边界与下一步

本次范围是部署方案所需的静态图及 FP32 路径，同时覆盖 IR 已有的 FLOAT64、INT32、INT64 类型。
没有实现 ONNX 的全部 dtype/opset 扩展；动态 shape/axis 参数及 Reshape allowzero=1 仍明确拒绝。
解释器沿用严格数值策略：非法定义域、非有限结果以及新增 Abs/整数 Pow 的溢出会报错。
整数 Pow 对大整数采用精确计算，ORT CPU 在超 2**53 的整数幂上可能存在浮点精度差异；实际 Qwen 使用 FP32 底数和 INT64 指数 2。

下一步应运行真实 Qwen3 结构的小模型，包含 Q/K RMSNorm、完整 RoPE、GQA、SwiGLU，逐层对照 PyTorch/ORT/IR。
之后再验证优化流水线、完整 0.6B 推理的数值/内存，以及 RISC-V 后端和 QEMU。
本轮没有补 RISC-V 降低和执行支持，不能据此前端/IR 结果判断 QEMU 已可运行。

本次单测/benchmark 版本为 NumPy 2.5.3、ONNX 1.23.0、onnxruntime 1.29.0；解释器路径不是复跑前提。
