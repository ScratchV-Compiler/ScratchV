## 1. 项目概述

### 1.1 背景

ScratchV 是一个面向计算机体系结构与编译原理学习的 AI 编译器，核心管线为 ONNX 解析 → IR 构建 → 优化 Pass → RISC-V 代码生成。项目最初主要验证 CNN 类静态计算图；当前已沿用共享 IR 和 CompilerDriver，补入 NumPy IR 解释器、张量 C 后端和 RV64 裸机运行器，跑通真实 Qwen3 结构的两层缩小模型。完整 Qwen3-0.6B 已在作者[第四轮 Linux 手动编排](https://github.com/yuki-328/ScratchV/actions/runs/37299235103)的提交 `1c49e8acbcd9174491b2d0c2a5a0072178ae5f9a` 下通过全部七组 IR/ORT 数值，preparation 和同提交汇总也通过；完整 raw 数组下载验真及 audit 通过，团队独立复现及正式验收尚待完成。早期 v2 记录保留在固定历史提交，Linux v3 证据按原身份保留，详情见 [W3 工作总结](W3/W3-工作总结与验收进度.md)。大权重装载、目标容量和完整 QEMU 前向按 W4 推进。

### 1.2 目标

在 RISC-V 平台（QEMU）上运行 ScratchV 编译的 Qwen3-0.6B，对简单 prompt 生成连贯文本。

### 1.3 v1 范围界定

| 维度 | v1 决策 | 理由 |
|---|---|---|
| 数据类型 | FP32 | 避免量化节点解析、定点运算、量化误差对齐 |
| 序列长度 | 固定 L=256 | 避免动态形状支持，所有张量形状编译时确定 |
| KV Cache | 不支持 | 避免动态内存、循环结构、缓存管理 |
| 推理模式 | 单次前向 + host 端 token 循环 | 模型是静态数据流图，张量内核有循环；生成循环在 host 端 |
| 采样 | Greedy 优先，top-k/top-p 可选 | 先验证正确性，再丰富策略 |
| 目标平台 | 当前实现为 QEMU virt 裸机、RV64GC/LP64D | 功能验证；团队确认后冻结，QEMU 时间不等于硬件性能 |

### 1.4 排除项（后续版本）

- KV Cache（v2）
- INT8/FP16 量化（v2/v3）
- RVV 向量扩展（v3）
- 真实 RISC-V 硬件性能调优（v3）
- 动态序列长度（v2）
- 多 batch 推理（暂不需要）

### 2.3 Qwen3-0.6B 关键配置

| 参数 | 值 |
|---|---|
| 层数 | 28 |
| hidden_size | 1024 |
| intermediate_size | 3072 |
| Q 注意力头数 | 16 |
| KV 注意力头数 | 8（GQA） |
| head_dim | 128 |
| vocab_size | 151936 |
| 位置编码 | 全 head_dim RoPE，theta=1e6；固定 position_ids=0..255 |
| 激活函数 | SwiGLU |
| 归一化 | RMSNorm |
| 权重绑定 | 是（Embedding 与 LM Head 共享） |

配置来源固定为导出 manifest 的 `Qwen/Qwen3-0.6B` revision `c1899de289a04d12100db370d81485cdf75e47ca`，不能从 `hidden_size / heads` 推导 head_dim：Q 投影宽度为 16×128=2048。Q/K 各有 RMSNorm；PR #89 合成图的 partial RoPE 不代表官方模型。真实结构探测采用官方类的缩小配置和随机权重，不是预训练两层权重切片。

### 2.4 固定长度推理模式

```
输入：
  input_ids:      [1, 256]        int64
  attention_mask: [1, 1, 256, 256] float32

输出：
  logits:         [1, 256, 151936] float32

Host 端循环：
  1. 编码 prompt → input_ids
  2. 右侧 padding 到 256，构造加性 attention_mask（因果 + key-padding）
  3. 调用 RISC-V 前向函数
  4. 取最后一个有效 token 位置的 logits，不取右侧 padding 的第255位置
  5. 采样下一个 token
  6. 追加到 input_ids，重复 2–5
  7. 直到 EOS、max_new_tokens 或有效序列长度达到256；超过容量的处理另行明确
```

**关键约束**：每次前向都处理完整的 256 长度序列，不足部分用 pad token 填充；加性 mask 允许位置为 0、屏蔽位置为 `finfo(float32).min`。输入 ID 保持 INT64，mask 保持 FP32。注意力计算随序列长度呈平方增长，每生成一个 token 都重算前向。v1 不静默裁剪过长 prompt 或滑动窗口；上下文截断和多轮历史策略需显式约定、补测试。

## 8. 总结

本设计方案的核心逻辑是：

1. **范围最小化**：FP32 + 固定长度 + 无 KV Cache + 无 INT8，让 ScratchV 回归其最擅长的静态计算图编译。
2. **风险前置**：W1 整周预研，用 5 天换取对整个项目可行性的判断。
3. **三层数值验证**：小模型 → 中等模型 → 完整模型，每层独立门槛，避免最后才发现问题。
4. **CI 门禁驱动**：PR 快速门禁、Nightly 完整门禁、Weekly/Release 门禁，四个硬门槛自动判定。
5. **周粒度管理**：降低管理开销，每周集成日，W8 纯缓冲吸收延期。
6. **清晰演进路径**：v1 验证正确性，v2 加 KV Cache，v3 加量化与向量化。

**W3 的 `numeric:ir-full-qwen3`（误差 < 1e-4）已获得作者第四轮 Linux v4 七组完整执行证据，同提交 preparation 及整套手动汇总也已通过**，中等配置、真实维度子图和资源观测也已建立。历史失败记录保留；第四轮原始数组下载验真和 audit 也已通过，剩余为 W1 人工前置记录、W3 团队口径确认、E1/E2/E5 独立复现及定时 Nightly 验收，之后按阶段条件推进 W4 完整 RISC-V/QEMU 前向。当前实施状态与证据范围见 [W3 工作总结](W3/W3-工作总结与验收进度.md)。
