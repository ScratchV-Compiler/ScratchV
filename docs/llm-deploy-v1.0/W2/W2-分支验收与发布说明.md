# W2 独立分支验收与发布说明

W1 两层报告与参考测试修复见 [PR #93](https://github.com/ScratchV-Compiler/ScratchV/pull/93)。本分支直接基于 PR #91 合并提交 `3bb88e81498d6d9293aed70e25a4e5a2104465d0`，不包含独立 W1 PR 中的六个两层报告/参考测试文件。两部分可分别审阅和合并。共享后端的标量绑定、运行时日志和取消清理加固随 W2 交付。

## 范围

- 固定完整 28 层 ONNX 的结构、前端解析、IR verifier、逐节点和权重绑定审计。
- RMSNorm/RoPE/SwiGLU/GQA 前端模式，七类基础后端的 16 小图/32 次 QEMU。
- 官方 Tokenizer、输入/mask、最后有效位置 greedy/停止条件，以及完整词表两层小配置的单步模型集成。
- 七项统一验收入口，完整前端 PR 必跑任务，以及拒绝失败、取消、跳过、缺失的 CI 汇总。
- 标量 IR 常量外部绑定一致性；日志写入失败保留主错误；取消时清理独立编译器/QEMU 会话。

本分支 Windows 固定 CPU 环境重新执行：**629 passed / 1 skipped**（仅 Linux 嵌套会话清理用例跳过）；**七项统一验收 7/7 PASS**，实际 32 次基础后端 + 28 次两层 QEMU 全通过。完整图为 28 层、7,847 节点、2,148 绑定、5,910 条 IR，verifier 与逐项审计通过。运行时为 20 组语料/480 对照/5 场景；完整词表单步集成为 2 文本、8 次调用。136 项源码指纹与发布前代码一致。

总入口耗时 251.494 秒，两层 QEMU 进程累计 154.125 秒，基础后端 QEMU 累计 6.194 秒；并行验收时的本机单次观察，不用作性能对比。精度最大误差：基础后端 `2.384185791015625e-7`，单步集成 `2.8312206268310547e-7`，两层 IR `1.9073486328125e-6`，两层目标诊断 `1.6689300537109375e-6`，均小于 `1e-5`。

另外，以本分支新生成的模型显式执行 none/basic/all 三项产物优化集成，**3/3 通过、0 跳过**，证据为 `output/w2-publish-artifact.xml`。

证据在 `output/w2-publish-tests.xml`、`output/w2-publish-acceptance/report.json/md/html` 及各子目录。工作流 YAML、29 段 Bash、文档链接及 diff 格式检查通过。本分支没有重跑全仓 tests；原整合工作树 3020 项通过属于下述历史记录，不能用其代替本分支验证。固定 ORT 环境下三个原有算子参考用例的兼容修复归属 PR #93。项目的本地 L2 harness 文件缺失，未声称运行。此前 [W1 修复与 W2 本地验收报告](W1修复与W2本地验收报告.md) 记录的是两部分合在一起的历史工作树，不应冒充本分支的精确源码证据。

## 复现与限制

运行 [统一入口](README.md) 的七项门禁；每次使用新的输出目录。源文件哈希、模型/ELF 身份、原始命令、误差和仿真墙钟时间均保存在生成的 JSON/Markdown/HTML 中。

完整图解析不等于完整 0.6B 的 IR/QEMU 数值前向。当前 Attention 使用已定义语义的基础算子组合，无新增融合 opcode。第二人复现、接口冻结、完整模型权重独立装载和生成循环仍需后续完成。

Linux 嵌套会话清理用例在 Windows 上明确跳过；CI 配置已经提供入口，但只有对应提交的实际远端执行才能证明 Linux 通过。完整 ONNX ORT 前向继续由独立手动/夜间任务验证。
